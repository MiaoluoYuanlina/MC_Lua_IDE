# MC Lua IDE 使用手册

IDE 跟随 Minecraft 的语言设置。中文相关语言使用中文界面和拼音首字母搜索；日语使用日语界面、日语手册，并提供独立的“ローマ字”搜索开关；英语及其他语言使用英文界面，不显示这两个开关。日语支持罗马字全拼/前缀、平片假名互搜、半角假名、促音与长音等常用表记；例如 `komando` 匹配 `コマンド`、`hensuu` 匹配 `変数`。汉字仅使用已收录的常见游戏/UI 读音，不会使用中文拼音猜读其他 Mod 的未知汉字。中文拼音与日语罗马字偏好分开保存。切换语言不会修改代码、文件名、资源 ID 或已保存的配置键。部分尚未逐条翻译的 API 详细说明会保留中文原文，避免遗漏原有约束；第三方模组的文档按该模组提供的翻译选择和回退。

> 管理员在 Minecraft 客户端内编辑脚本，由安装本 Mod 的服务端保存并安全执行。

> 手册里的每张 Lua 示例卡片右上角都有“复制”按钮。点击后可直接在编辑器中按 `Ctrl+V` 使用。

> 手册正文不能直接选择；可以用手册顶部的“复制全文”按钮复制整篇手册，示例代码用卡片上的“复制”按钮。

建议按“首次运行 → Lua 基础 → IDE 编辑功能 → MC API → 事件与进阶项目”的顺序阅读。只想查某个方法时，打开“UI与窗口 → 视图 → API 文档”，按名称或中文作用搜索；API 文档会同时显示当前服务器上其他 Mod 注册的扩展函数。

## 安装与运行原理

服务端必须安装本 Mod；要使用 IDE 的管理员客户端也必须安装同版本。普通玩家客户端默认不需要安装。脚本文件保存在服务器，Lua 代码在服务器的独立虚拟线程执行；涉及世界、玩家和物品的 `MC.*` 操作会切换到服务端游戏线程完成，不会以打开 IDE 的玩家身份偷偷执行。只有单人世界所有者或 OP 等级 4 能读取、编辑、运行脚本。

第一次使用时，确认服务器和管理员客户端的 Minecraft/Fabric/本 Mod 版本匹配。进入世界后按 `U` 或输入 `/lua` 打开 IDE。若服务器未安装本 Mod、协议不一致或当前账号权限不足，聊天栏会显示原因。服务器管理员可在 Mod Menu 配置 Lua 限制和是否要求所有玩家安装客户端 Mod；完整权限说明见后文“多人服务器安装与权限”。

## 快速开始

### AI工具：报错分析和代码标注

在 **工具 → AI工具** 打开可拖动、缩放、吸附的配置窗口。支持 **DeepSeek、GPT/OpenAI、Claude、Gemini**，每种服务分别保存 HTTPS API 基础地址、模型 ID、API Key。模型 ID 填写你自己的 API 账户可用的模型；GPT 使用 [Responses 工具调用](https://developers.openai.com/api/docs/guides/function-calling)，不是 ChatGPT 网页订阅登录。其他服务分别使用 [DeepSeek Tool Calls](https://api-docs.deepseek.com/guides/tool_calls/)、[Claude Messages 工具调用](https://platform.claude.com/docs/en/agents-and-tools/tool-use/handle-tool-calls)、[Gemini Function Calling](https://ai.google.dev/gemini-api/docs/function-calling)。基础地址不包含 `/responses`、`/messages`、`/chat/completions` 或模型生成接口后缀。修改后点击 **保存配置**，切换服务不会丢失各自的配置。

**AI 自动分析运行报错初次默认关闭。** 填写密钥或打开窗口不会开启分析；勾选开关并保存后，只有 IDE 提交运行的脚本报错或停止回调中的代码异常会触发自动分析。**写代码时的静态错误、黄色可恢复警告和 JSON 格式提示不会自动发送；保存/开启 AI 配置也不会分析已有的编辑器诊断。**

关闭再打开 IDE 时，会恢复当前服务器连接中最近一次运行的日志（最多 200 行），包括仍在运行、正常结束、停止与报错的任务，不会重新运行脚本。若 AI 自动分析已开启，则会补分析该次运行尚未分析的错误，包括关闭 IDE 后在后台发生的错误；正常完成与黄色可恢复警告不触发 AI。分析使用该次运行提交的原始代码，不把后来修改的编辑器内容当作运行代码。

运行报错汇总等待 2 秒，自动请求间隔至少 30 秒。每次运行的相同文件内容／错误只自动请求一次，反复关闭打开 IDE 不会重复请求，已完成的 AI 回复也保留在日志里；重新运行脚本产生的错误属于新一次运行。自动请求失败后不会因重开 IDE 无限重试，可手动重试；分析尚未完成就关闭 IDE 会取消请求，下次打开可重新尝试。也可点击 **分析当前报错** 手动分析编辑器诊断或运行报错（即使自动开关关闭，手动请求仍会发送代码）。最近一次运行日志和去重记录只保存在当前连接内存中，断开服务器会清空，不跨服务器、玩家或游戏重启恢复，也不会监视整个服务器所有脚本。

**黄色隐私/费用提示：** 报错、附近代码（包括未保存的内容），以及 AI 请求读取的相关工作区文本会发送到所选服务，可能产生 API 费用。自定义 API 基础地址的运营者也会收到密钥；务必确认地址可信。读取范围是服务端 Lua/datapack 工作区和客户端 IDE 管理的 resourcepacks，不包含配置目录或任意系统文件。会尽量遮蔽常见 `apiKey/password/token` 字段，但无法保证隐藏源码中的所有敏感内容，私密项目开启前请确认。

API Key 输入显示星号，已保存密钥不会再次填到输入框；留空保留，**清除当前服务密钥** 后保存可删除。完整配置只写入当前 Windows 用户注册表 `HKCU\Software\MC_Lua_IDE\AI` 的加密二进制值，经 Windows DPAPI 当前用户加密，不写入脚本、Mod 配置文件、Git、请求正文或运行日志。**红色安全提示：** 注册表加密不能防御以相同 Windows 用户身份运行的恶意程序，不能把它当作独立密码保险箱。其他系统不回退到明文文件，自动分析保持关闭。

分析采用只读工具调用循环：`list_files` 分页列出工作区，`read_file` 按行读取，`search_file` 搜索，`read_api` 查看当前内置和第三方 API，`annotate_code` 批量添加多文件代码标注。没有写文件、执行脚本、终端或任意网址访问工具。每次最多 6 轮、24 次调用、10 个相关文件和 64,000 字符的工具读取量；每次读取最多 200 行，单个附加文件最多 200 万字符，片段/长行会截断。分析在后台执行，不占用游戏主线程等待网络。

结果显示在 **运行日志**；连续 Lua 输出不会立即抹掉 AI 回复。AI 可标注多处代码：红底为错误、黄底为警告、蓝底为说明。鼠标悬浮查看说明；**悬浮标注时按 Esc 清除全部 AI 标注**，不会关闭 IDE。左键拖选时不显示标注提示。标注会核对原文件版本，修改代码后旧标注移除；未打开文件的标注会在打开匹配版本时显示。**取消分析 / 清除标注** 会取消待处理请求和标注；关闭 IDE 也会取消未完成分析，但已发送给服务的数据无法撤回。AI 的解释属于建议，不会自动修复代码。

### MCP 服务器：让 AI 通过授权工具协助编辑与运行

本模组提供两套独立的 MCP 服务，**初次默认全部关闭**，配置、端口、权限及最后一次开启／关闭状态会保存：

- **客户端**：在 IDE 的 **工具 → MCP 服务器** 打开配置窗口，默认端口 `8765`。游戏客户端需要在线，并拥有单人世界所有者或 OP 等级 4 权限；工具调用仍由服务端逐次检查权限。退出服务器会关闭监听但保留开启设置；重新进入同一世界／服务器、同一玩家且权限有效时恢复。切换到其他玩家或服务器不会自动沿用旧授权，需手动确认开启。
- **服务端**：在 **工具 → 服务器配置 → MCP 服务器（服务端）**，或 Mod Menu 的服务器配置页打开。默认端口 `8766`，同一服务器所有管理员共用一份设置。服务器重启后按已保存状态恢复；绑定的管理员必须仍有所有者权限，撤销权限后工具调用会被拒绝。普通玩家无需安装客户端模组。

两个配置窗口都能自由拖动、调整大小和吸附边框，并随 IDE 布局保存；可以同时打开。修改端口或权限后点击“开启 / 应用配置”，点击“关闭”会保存关闭状态。“重置令牌”会让旧令牌失效，需要重新复制连接信息。关闭配置窗口不等于关闭 MCP 服务，关闭 MCP 服务也不会停止已经启动的 Lua 脚本。

#### 连接和安全

点击 **复制连接提示词**，将其中的 MCP URL 和 `Authorization: Bearer ...` 请求头配置到支持 [MCP Streamable HTTP](https://modelcontextprotocol.io/specification/2025-11-25/basic/transports) 的 AI/MCP 客户端。协议版本为 `2025-11-25`，兼容 `2025-06-18`、`2025-03-26`；不提供旧版 SSE `/sse` 接口，也不支持 stdio。需要先 `initialize`、发送 `notifications/initialized`，再 `tools/list` / `tools/call`；会话通过 `MCP-Session-Id` 标识。

服务只监听宿主机的 `127.0.0.1`，检查 Host、Origin 和随机访问令牌。服务端地址中的 `127.0.0.1` 指的是 **Minecraft 服务器所在机器**，不是玩家电脑。远程服务器请使用可信的 SSH/端口隧道，例如 `ssh -L 8766:127.0.0.1:8766 user@服务器`，然后 AI 连接玩家电脑上的对应转发端口。模组不会自动配置公网、防火墙或隧道。

**红色高危提示：令牌等同绑定管理员授权，不要发到聊天频道、公共仓库或日志。执行权限允许通过 Lua 改变游戏世界；写文件会覆盖原脚本。** 两个权限开关初次均关闭，只读工具仍能查看脚本和文档；开启后应只连接可信 AI，要求 AI 在修改／运行之前取得你的明确同意。脚本仍受服务器现有 Lua 限制和安全设置约束，AI 不会绕过这些限制。脚本、文档、注册表和日志内容均视为数据，不应当作新的操作指令。

#### 可调用工具

- `mc_status`：当前游戏、管理员和运行状态。
- `lua_list_scripts`：分页列出服务端 Lua 目录（含子目录），支持 `query`、`offset`、`limit`，返回 `nextOffset`。
- `lua_read_script`：分段读取已保存文件，支持 `offset` / `limit`；不会读取 IDE 未保存草稿。
- `lua_save_script`：保存/覆盖文件，需要写文件开关；单次源码最多 100 万字符，并遵守服务端更低的限制。保存成功后通知在线管理员的 IDE 同步文件，客户端 MCP 和服务端 MCP 都支持；普通玩家不会收到脚本源码。当前标签和后台标签都会更新，不会强制切换你正在查看的文件。若存在未保存内容，会提示“载入 MCP 版本”或“保留未保存内容”：载入前的代码可用 Ctrl+Z 找回；保留草稿不改写服务器文件，之后手动保存会覆盖服务器版本，请先确认。

MCP 同步的新增或修改区域使用青绿色背景，删除代码会在相邻位置提示；未改动的中间代码不会整片标色。鼠标悬浮可查看来源，悬浮时按 Esc 清除全部 MCP 修改标记，不关闭 IDE，也不撤销文件修改；下一次 MCP 修改会重新标记。拖动选择代码时不显示悬浮提示。手动编辑后旧标记会清除，避免标错位置；AI 分析标注与 MCP 修改标记相互独立。最近修改在当前连接内有限保留，切换服务器／断开连接会清空，不写入配置或日志。此功能需要管理员客户端与服务端使用相同协议版本。
- `lua_run_script`：运行服务端已保存的脚本，不改写文件、不默认开启调试，需要执行开关。
- `lua_stop_script`：只停止本套 MCP 启动的脚本，不停止 IDE、其他管理员或另一套 MCP 启动的脚本。
- `lua_execution_logs`：查询本套 MCP 最近一次启动的脚本状态与最近 120 行 Lua 输出，每行最多 1000 字符。
- `mc_api_documentation`：按 `query` 查询内置手册/当前第三方 API，支持文本分页；客户端入口提供 IDE 的详细 API 文档，服务端入口提供内置手册及第三方文档数据。
- `mc_registry_ids`：动态获取游戏与模组注册的 ID，支持 `registry`、`query`、`offset`、`limit`，返回 `nextOffset`；偏移对应原注册表分页，查询结果为空时也可能还有下一页。

窗口的调用日志自动刷新，可用滚轮、↑↓ 或 PageUp/PageDown 浏览，并支持复制和清空。最近 500 条日志记录调用时间、方法/工具、结果和耗时，**不记录访问令牌、请求参数、源码或返回内容**；它不同于 `lua_execution_logs` 的脚本输出。调用日志只在本次游戏/服务器进程内保留，重启会清空；配置与启停状态仍会保存。

端口占用或权限无效时窗口会显示启动失败原因；即使保留了“开启”配置，也不代表监听已成功。工具调用超时后应先检查状态，不能盲目重复写入或运行。

修改监听配置会让现有 MCP 会话失效，请重新连接；已经提交到游戏服务器的操作仍可能完成，关闭监听不是撤销操作。

### 首次编辑和运行

1. 进入安装了 MC Lua IDE 的服务器后，使用服务器所有者账号或 OP 等级 4 的账号按 `U`。IDE 直接打开；首次进入显示空白编辑区和使用手册。
2. 点击“文件 → Lua 目录”，输入脚本名称或 `目录/名称`，点击文件图标新建脚本，也可读取现有脚本。
3. 已打开的脚本显示在代码框上方的标签栏；点击标签或文件窗口中的脚本可切换，`Ctrl+Tab` / `Ctrl+Shift+Tab` 可前后切换。各标签保留未保存文本、撤销历史和光标位置；关闭未保存的标签时会询问是否保存。编辑器顶部状态会实时检查语法。
4. 按 `Ctrl+S` 保存，按 `Ctrl+Enter` 运行。
5. 点击顶部常驻的绿色“▶ 运行”按钮开始调试；运行后按钮会变为红色“■ 停止”，可随时中断脚本。

Lua、datapack、resourcepacks 三个目录窗口右键点击文件、文件夹或列表空白处，都可以选择“在资源管理器中打开”。文件会在 Windows 资源管理器中被定位选中，文件夹会直接打开；空白处打开该目录的根位置。Lua 和数据包属于服务器：只在单人游戏／本机内置服务器中能够直接定位，连接远程服务器时会提示在服务器主机操作，不会误打开客户端同名文件。资源包始终打开管理员客户端自己的 resourcepacks 位置。右键菜单和二级菜单可以跨出窗口边框，覆盖其他窗口时仍由菜单响应；在空白处点击会收起菜单。

### 工具菜单：整理、重载与服务器资源包

顶部“工具”菜单提供以下操作，原有“导出当前 API”仍保留：

- **整理代码**：整理当前文件。Lua 的函数、回调、if/end、循环和表统一使用四个空格缩进，不改变字符串内容或将单行代码强制拆行；JSON / pack.mcmeta 格式化为四空格缩进；mcfunction 去除命令行前后的空白。不会自动保存，`Ctrl+Z` 可一次撤销；Lua 行号和断点不会因整理缩进改变。格式错误的 JSON 不会覆盖原文。
- **重载资源包**：重载当前客户端已经启用的资源包，更新插入窗口的资源 ID 缓存。请先保存资源文件；未启用的包不会自动启用。此按钮不会重载其他玩家的客户端。
- **重载数据包**：管理员向服务端请求原版级别的数据包重载，完成或失败后显示结果，同时刷新注册 ID。与 `/reload` 相同，会发现新数据包并保留明确禁用的数据包；不会自动保存编辑器。维度、维度类型、世界生成等启动时注册的数据仍可能需要重新进入存档，按钮不保证这些注册表热更新，也不声称消除原版重载开销。
- **上传并设置服务器资源包**：打开可移动、缩放、吸附并保存布局的上传窗口。点击“选择资源包 ZIP”，选择客户端的 ZIP 文件，填写玩家能访问的下载地址，然后点击“上传并应用”。ZIP 根目录需要 `pack.mcmeta` 和 `assets`，不能多套一层目录；最大 128 MiB。文件分块上传到当前存档的 `mc_lua_ide_server_pack`，由服务端检查路径、文件大小、ZIP 展开大小和文件校验值；普通玩家不能上传、读取设置或操作脚本。

上传窗口默认使用模组自带的 **HTTP ZIP 下载服务**，默认端口 8080；填写例如 `http://服务器公网地址:8080`，不要加 ZIP 文件名，模组自动生成内容校验值对应的下载路径。点击应用才会开启配置的下载端口；只提供资源包 ZIP，不提供脚本、控制台或任意文件访问。管理员负责配置防火墙、端口转发或 HTTPS 反向代理，本模组不会修改防火墙。地址必须能被每位玩家访问；远程玩家不能使用你电脑的 `localhost` 或 `127.0.0.1`。单机测试可以使用 `http://127.0.0.1:8080`。

关闭“使用模组的 ZIP 下载服务”可使用外部托管，地址填写 ZIP 的完整公开直链；需要自行将**同一份 ZIP**发布到该托管地址。上传到游戏服务端不等于上传到第三方网站，客户端下载的内容必须与本模组发送的 SHA-1 相符。

发布采用 Minecraft 原版服务器资源包协议：服务端发送 URL 和 SHA-1，客户端按原版提示下载并加载，**普通玩家无需安装 MC Lua IDE**。在线玩家会收到更新请求，后来加入的玩家也会收到；是否接受及下载结果由原版客户端处理，上传成功不代表每位玩家已经成功加载。默认不强制接受，勾选“要求玩家接受”后，拒绝或加载失败可能断开连接，请先验证下载地址。配置与已发布 ZIP 随存档保存，重启服务端后恢复。点击“停用资源包”停止本模组的分发、移除玩家上本模组发布的包并关闭下载服务，不删除已上传 ZIP，也不改写其他服务器资源包或 `server.properties`。

旧 ZIP 保留用于缓存与正在进行的下载，资源包目录总存储上限为 1 GiB，超过时提示管理员手动清理不再使用的旧 ZIP。上传过程中可取消，未完成的临时文件不会发布；新 ZIP 的校验或应用失败时，原先已发布的资源包保持不变。上传、配置和数据包重载均需要服务器所有者／OP 等级 4 权限。

### 大文件与执行限制

Lua、数据包 JSON／函数文件、资源包 JSON／mcmeta 的编辑、保存和读取上限统一为 **5,000,000 个字符**（原来为 100,000）；不单独限制行数。服务端文件通过大包分片传输，超过长度会明确报错，不会截取文件后半部分。中文和表情也计入字符容量；字符按 UTF-16 计数，一个表情可能占两个字符。大文件的撤销历史会按总容量淘汰较早快照，避免连续输入占用过多内存；小文件仍保留最多 100 次撤销。

文件容量与服务器的**执行限制**分开：即使管理员把执行脚本长度设得较小，仍可编辑和保存大文件。新配置默认允许执行 5,000,000 字符；已有配置不会被擅自提高。如果大文件保存成功、运行却提示“当前限制”，请管理员在 **Mod Menu → MC Lua IDE 设置 → Lua 限制 → 执行资源**中调整“执行脚本最大字符数”。其他运行时间、指令、事件、输出和权限限制不变。更新时管理员客户端与服务器都需要使用相同的新版本，旧协议客户端会提示版本不兼容。

### 关闭与恢复工作区

关闭 IDE 时自动保存工具窗口的显示状态、吸附位置、浮动位置和尺寸、吸附区大小、选中的吸附标签和标签顺序、布局锁定以及界面缩放。下次按 `U` 打开会恢复之前的布局，重启游戏后也有效。打开的 Lua、数据包和资源包文件标签、当前标签、文本光标和滚动位置也会恢复；正常打开时内容重新从服务器或客户端资源包读取。文件标签按服务器／单人存档和玩家分别保存，切换世界不会打开另一世界的文件。二进制预览重新加载，PNG 图片的已保存图层仍由图片工具项目文件恢复。

编辑器每秒检查修改并在后台保存本地恢复草稿，支持 Lua、JSON、`.mcfunction` 文本和资源包 PNG 的图层、可见性及分辨率。草稿保存在管理员客户端的 `config/mc_lua_ide/recovery/`，按服务器／存档和玩家隔离；这不是自动保存到原文件，也不会上传到服务器。客户端配置中因此可能包含管理员正在编辑的脚本正文，请保护此目录，不要把草稿当作可公开发布的资源包。

如果游戏崩溃、进程被终止或断线时还有未保存内容，下次打开 IDE 会询问是否恢复。选择“选择恢复文件”会打开 **工具 → 文件恢复** 窗口，可查看文件路径、类型和备份时间，双击或点击“恢复选中”，也可“恢复全部”。此窗口支持移动、调整大小、吸附和布局保存。恢复只打开未保存的标签，检查后按 `Ctrl+S` 才写入原文件；同名标签已有未保存修改时不会覆盖它。点击“稍后”或 `Esc` 保留全部草稿，可随时从工具菜单打开。删除草稿需要点击两次确认，只删除选中的恢复副本，不会删除原文件。

保存成功或明确选择“不保存”关闭标签／IDE后，会清理本次编辑对应的恢复草稿；未选择恢复的旧草稿仍保留。定期备份不能保证恢复硬崩溃前的最后一秒、正在写入的内容或磁盘故障导致的丢失，重要修改仍请及时保存。

多个工具窗口吸附到同一侧时，上方出现标签切换栏。单击切换窗口；按住标签左右拖动可调整同一区域中的顺序，蓝色位置提示和标签滑动动画会显示调整结果，松开后自动记住顺序。左、右、下三个区域独立排序，也支持其他 Mod 添加的窗口。暂时关闭窗口不会遗忘它的排序位置。“固定当前布局”开启时仍能切换标签，但不能拖动改变顺序；解除锁定后恢复排序。

如果任意标签（包括 PNG 画布）有未保存修改，关闭 IDE 或关闭该标签时会显示“保存后关闭／不保存／取消”。选择保存会逐个保存修改过的文件并等待服务端确认；任何文件保存失败都会保留编辑器和未保存的修改，显示原因，可重试。“不保存”会丢弃修改，但关闭 IDE 时仍记住文件标签；下次打开读取的是最后已保存的内容。“取消”或确认框里的 `Esc` 返回编辑；`Tab`／左右方向键切换按钮，回车确认。直接结束游戏进程或意外断线无法保证出现保存询问，请及时按 `Ctrl+S` 保存。

先不用调用游戏 API，创建 `hello` 脚本并粘贴以下代码。保存、运行后，日志窗口应立即显示两行文字：

```lua
print("你好，Minecraft！")
print("2 + 3 =", 2 + 3)
```

运行结果不会自动写回脚本文件；修改代码后要再次保存。运行时的 `print` 会实时进入日志窗口，脚本结束后日志仍保留，可点击关闭按钮收起。按“■ 停止”可中断正在等待或运行的脚本。一次只运行一个服务端脚本；持续注册事件的脚本会保持运行，直到停止或事件全部注销。

### 代码选区与滚动

鼠标拖动可以选择代码，双击选择光标下的词语或字符。选中一串非空白文字后，编辑区中完全相同的文字会自动以浅蓝背景高亮（区分大小写，按原文匹配，不是正则表达式）；取消选中会清除这些高亮，不影响 `Ctrl+F` 的搜索结果。

在代码编辑区点击鼠标右键可打开编辑菜单：复制、剪切、粘贴、删除、撤销和搜索。右键点在选区内会保留选中文字，点在选区外会将光标移到点击位置；没有选区时复制、剪切和删除灰显。粘贴沿用 Lua 智能缩进，剪切、删除和粘贴都可撤销；搜索会自动填入选中文字。菜单支持上下方向键和回车，点击外部或按 `Esc` 关闭，不会关闭 IDE。Lua、JSON 和 mcfunction 文本编辑都支持此菜单，图片、音频和 NBT 预览不显示文本编辑菜单。

在“UI与窗口 → 个性化”关闭代码自动换行后，长行保持一行显示，可用 `Shift+滚轮` 横向移动。编辑区底部的横向滚动条、右侧的纵向滚动条均可拖动，也可点击轨道跳转；拖动到编辑区外仍可继续滚动，松开鼠标即停止。拖动滚动条不会更改已有光标和选区。

### 命令方块与服务端控制台

服务端原生命令支持 `/lua list`、`/lua run <名称>`、`/lua testrun <名称>` 和 `/lua stop`，可以从命令方块、命令方块矿车、服务器控制台以及拥有权限的原版管理员客户端使用，无须依赖客户端聊天命令。

先在 IDE 保存脚本，例如 `tools/welcome.lua`，再在命令方块中填写 `lua run tools/welcome`。也支持 `.lua` 后缀和引号包裹的子目录路径。普通运行不启用断点或变量采样；`lua testrun tools/welcome` 启用调试。`lua stop` 停止当前服务端脚本。命令方块运行的脚本没有隐式玩家身份，涉及玩家的 API 仍需传递 UUID；`execute as @p run lua run tools/welcome` 也不会把脚本 API 改成客户端／玩家视角。

命令方块的“上一次输出”会收到 Lua 的即时及延时输出、完成／停止／错误提示，关闭“跟踪输出”则不写入它。命令成功计数 `1` 表示脚本已成功启动，不代表异步 Lua 已执行完成；路径非法、文件不存在或已有脚本正在运行时返回 `0`。持续监听脚本建议用脉冲命令方块启动，不要每 Tick 重复启动同一脚本。服务器仍保持同时只运行一个脚本的限制。

普通玩家及普通 OP 等级 2／3 的聊天命令不能运行、枚举或停止服务器脚本；聊天／控制台需要所有者权限（单人存档所有者或 OP 等级 4）。命令方块只在真实的原版命令方块／矿车执行流程中获得运行权限，不根据执行实体或坐标猜测权限，普通玩家不能通过冒充执行实体绕过限制。命令方块仅能运行管理员已经保存的文件，不能提交 Lua 源码或编辑文件。**请仅让可信管理员配置可启动 Lua 的命令方块：触发它会运行拥有服务端游戏控制能力的已保存脚本。** 管理员离线不影响由命令方块启动的脚本，服务器关闭或执行停止命令会结束它。

### 游戏内变量监视

F12 面板中的“位置调整…”会进入游戏内调试浮窗布局页，同时预览变量、断点信息、Lua 日志和自由摄像机提示。未开启的浮窗也会显示标有“仅预览”的示例，不会因此启用调试、请求额外变量、进入摄像机或改变原显示开关。拖动窗口内部移动位置，拖动四边或角落调整大小；鼠标停在可缩放边框时，只高亮对应的边。内容按新尺寸裁剪，变量与日志的可见行数随高度调整。

在位置调整页中右键任意浮窗，可打开它的背景设置。拖动“背景透明度”滑条实时调整：`0%` 完全不透明，`100%` 完全透明；仅影响该窗口的背景，不改变文字、边框或其他窗口。滑条获得焦点后可用左右方向键微调，Shift+左右每次调整 10%。菜单支持单独恢复该窗口的默认透明度，点击外部或 Esc 关闭菜单（不移动底下的窗口），再次 Esc 返回调试菜单。透明度与布局一起保存在客户端，下次打开继续使用；旧布局文件没有此设置时保留原先的背景透明度。

按 Tab / Shift+Tab 切换选中的浮窗，方向键微调位置，Ctrl+方向键调整大小，Shift 可加速。点击“完成”、Esc 或 F12 返回调试菜单并保存布局；“恢复默认”可重置全部浮窗。布局保存在当前客户端 `config/mc_lua_ide/debug-hud-layout.properties`，下次启动继续使用；分辨率／GUI 缩放变化时按比例适配，并确保窗口不超出画面。布局调整只在这个页面处理鼠标输入，返回游戏后仍可正常移动和操作。

在 IDE 中可打开“UI与窗口 → 视图 → 变量显示”，查看同一份服务端变量树。这个窗口支持拖动、调整大小、吸附到左／右／下方，以及鼠标滚轮滚动；点击窗口后也可用上下方向键逐行滚动。窗口的显示和吸附位置会随工作区布局保存。打开此窗口会独立请求调试快照，无须同时开启 F12 游戏内浮层。

变量窗口可拖动选择文字、双击选择整行，按 Ctrl+C 复制选中内容，Ctrl+A 选择全部变量文字；标题栏“复制”按钮直接复制完整变量树，包含未显示的行、缩进和被窗口裁剪的完整值。为避免刷新过程中选区变成另一条数据，选择期间暂时显示所选快照，按 Esc 清除选区并恢复实时显示，不会关闭窗口；再按 Esc 按原有规则关闭。点击代码编辑区后，Ctrl+A/C 仍作用于代码，不会被变量窗口抢走。F12 游戏内变量浮层仍不接收鼠标输入，不影响游戏操作。

变量值按 Lua 类型配色：字符串、数字、布尔值、表、函数和 `nil` 使用不同颜色。多个事件监听会分别保留最近一次采样，显示在“监听 #编号 · 事件名”的分组下，不会因另一个监听触发而被覆盖；同一作用域内重名的局部变量会显示 `[#2]` 等序号。监听尚未触发时没有该回调的局部变量样本；停止脚本后样本会清除。

返回游戏后按 `F12` 打开调试面板，开启“显示 Lua 变量值”，再点击“返回游戏”。使用 IDE 的运行按钮或 `/lua testrun <名称>` 启动可监视脚本；`/lua run <名称>` 是普通运行，不启用变量采样。左上角的只读面板会显示当前服务端 Lua 脚本的局部变量、闭包变量和脚本创建的全局变量。局部与闭包变量按调用栈分组为树形图；表值继续展开子字段，例如事件回调里的 `local models = YSMDummy.models()` 会在回调下一行执行时采样并保留最后一次观察到的值。内容定期更新；如果超过面板高度，在游戏画面中按 `↑`、`↓` 逐行滚动，不会自动翻页。打开编辑器等界面时方向键仍由当前界面处理。再次按 `F12` 可以关闭变量显示。只有服务器所有者或 OP 等级 4 能获取这些值，普通玩家不会收到调试数据。没有运行中的脚本时会显示提示；脚本停止后变量值不再保留。大型表只展示有限层级与字段，变量过多时会显示省略数量，避免调试本身拖慢服务器。

### 断点与单步调试

在 Lua 文件左侧行号栏单击，或将代码光标放到目标行按 `F9`，可添加／移除红色断点；`Ctrl+Shift+F9` 清空当前文件的全部断点。断点按服务器／存档和玩家分别保存，重开 IDE、重启客户端后仍会恢复；子目录中的 `require` 模块也可设置断点。断点应放在实际执行的语句上：注释、空行、仅定义函数而未调用的函数体不会触发。

使用 IDE 的运行按钮、`Ctrl+Enter` 或 `/lua testrun <名称>` 启动调试。普通 `/lua run` 不启用断点和变量采样。默认命中断点时仅暂停 Lua 工作线程，服务器游戏刻、玩家操作和客户端渲染继续运行；暂停期间不计入 Lua 最长运行时间。黄色箭头与行背景标明**下一条待执行的语句**，IDE 自动切到该 Lua 文件，变量显示窗口可查看此刻的局部变量和调用栈。修改代码不会热替换正在执行的脚本：若文本与运行版本不同，将不标记错误的暂停行，新版本断点要停止、重新运行后生效。

按 `F12` 可在游戏或 IDE 中打开调试面板，独立开启“断点信息显示”；游戏右上角显示当前暂停位置、调用栈和快捷键提示。该开关只控制浮层显示，不会移除断点。点击开关右侧的“…”小按钮打开“断点控制与快捷键”：左列按钮执行切换断点、清空本文件、暂停／继续、单步和停止，右列用于修改快捷键。只有服务器所有者或 OP 等级 4 可以获取调试信息或控制脚本。

在 IDE 中打开“UI与窗口 → 视图 → 断点调试”，无需离开编辑器即可点击暂停／继续、单步进入、单步越过、单步跳出和停止，也可切换代码光标所在行的断点、清空当前文件的断点。窗口实时显示执行状态、脚本与执行 ID、暂停位置和原因、调用栈，以及包括子目录模块在内的已设置断点列表；点击暂停位置、栈帧或断点可切换文件并跳到对应行。修改后的代码与运行版本不一致时会显示警告，不会覆盖未保存的内容。单步按钮仅在调试脚本暂停时可用；普通 `/lua run` 不启用调试。

断点调试窗口支持拖动、边框缩放、左／右／下方吸附及同区域标签切换，位置和开关状态随布局保存；详细信息较长时可用鼠标滚轮或上下／PageUp／PageDown 键滚动，窄窗口中的长文字自动折行。关闭窗口不会恢复或停止脚本。该窗口与 F12 的游戏内断点浮层开关独立，使用相同的快捷键配置和服务端管理员权限校验。小屏幕上的“视图”菜单提供上一页／下一页，避免菜单项超出屏幕。

详情中的“待执行代码”来自**服务端正在执行的脚本版本**，显示暂停行的实际代码（包含原有缩进）；不是按行号读取编辑器中新改的文本。模块断点显示模块自身的代码；等待事件、没有活动语句时显示提示。长行在窗口中折行，极长行的预览最多 4096 字符。游戏内断点浮层与 F12 子菜单也会显示代码预览。

F12 → 断点信息开关右侧“…”子菜单，以及 IDE 断点调试窗口，都有“断点暂停游戏”开关，两处同步到**同一个服务端设置**，默认关闭，只有服务器所有者／OP 等级 4 可修改。配置保存到服务器的 `config/mc_lua_ide/debugger.properties`。开启后，命中断点、手动暂停或单步停下时，通过原版刻冻结暂停世界模拟（世界时间、普通生物与方块刻等）；**多人服务器中会影响所有玩家的世界模拟**，不是只暂停管理员个人画面。玩家操作、聊天、网络和调试按钮仍可用，不会阻塞服务端主线程。

继续、单步执行、停止、关闭该开关、脚本异常结束、脚本所有者离线或服务器关闭，会释放由调试器施加的冻结。单步再次停下会再次冻结。关闭 IDE／调试窗口本身不会自动继续脚本。调试器不会解除进入断点前已经存在的 `/tick freeze`；暂停期间主动执行原版 `/tick freeze` 或 `/tick unfreeze` 会接管冻结状态，调试器不会把它反向改回。关闭该开关不会继续 Lua，只会解除调试器的世界冻结。

同一页面还提供“暂停时允许玩家移动”，IDE 断点窗口中显示为“玩家移动”。默认开启：世界冻结时仍能走动、跳跃和转动视角。关闭后，调试器冻结世界期间所有玩家的身体位置及乘坐载具都不能通过移动操作改变，但仍可转动视角、聊天和使用调试按钮。该设置保存到服务器 `debugger.properties`，管理员之间同步；只影响调试器拥有的冻结，不改变原版 `/tick freeze` 的行为。未开启“断点暂停游戏”时，此选项不限制正常移动。

“自由摄像机”是**当前管理员客户端**的选项，默认关闭，保存到 `config/mc_lua_ide/debug-view.properties`，不改变其他玩家视角。开启后，Lua 调试脚本暂停时自动分离视角，玩家身体保持原地：移动键（默认 WASD）飞行，跳跃键（空格）上升，潜行键（Shift）下降，疾跑键（Ctrl）加速，鼠标转动视角。此时“允许玩家移动”不会让该管理员身体跟着摄像机移动，攻击、使用、丢弃／交换物品及鼠标滚轮切换物品会被屏蔽。继续、停止、关闭摄像机选项或断开连接后恢复原来的视角与第一／第三人称设置；单步停到新位置会重新进入摄像机。打开 IDE／F12 等界面时摄像机停止飞行，关闭页面后继续观察；只显示客户端已经加载的区块，不额外加载服务器区块。摄像机不修改游戏模式、飞行权限，也不传送玩家，即使未冻结整个世界也可观察；服务端只在管理员有权限且脚本暂停时允许该模式。其他模组或原版旁观者已有独立视角时不会强行接管。

点击右列某个快捷键，再按新的按键即可设置，支持 `Ctrl`、`Shift`、`Alt` 的组合；`Esc` 取消本次修改，退格／`Delete` 或最右侧“×”取消绑定。重复快捷键会提示冲突并保留原设置，与 Minecraft 的已有按键重叠时会显示黄色提醒。`Esc`、`F11`、`F12` 分别保留用于关闭、全屏和调试面板，不能重新绑定。设置自动保存到客户端 `config/mc_lua_ide/debug-keys.properties`，即时影响 IDE、调试页面和游戏内操作，HUD 提示同步更新；游戏内没有调试脚本时不会拦截正常键盘操作，长按不会反复触发调试命令。

顶部提供两套一键预设，应用后覆盖全部七项调试快捷键：

| 操作 | F 键预设 | 小键盘预设 |
| --- | --- | --- |
| 切换当前行断点 | F9 | 小键盘 0 |
| 清空当前 Lua 文件断点 | Ctrl+Shift+F9 | Ctrl+Shift+小键盘 0 |
| 暂停／继续 | F6 | 小键盘 5 |
| 单步进入 | F7 | 小键盘 7 |
| 单步越过 | F10 | 小键盘 8 |
| 单步跳出 | F8 | 小键盘 9 |
| 停止脚本 | Shift+F6 | 小键盘 . |

以下快捷键说明使用默认的 F 键预设；自定义或切换预设后，以设置页面和浮层显示的按键为准。小键盘与主键盘数字键分别识别，不会把普通数字输入当作调试操作。

- `F6`：请求暂停／继续执行；暂停请求在下一条 Lua 语句生效，不会强行打断正在完成的游戏 API 操作。
- `F7`：单步进入，会进入被调用的 Lua 函数。
- `F10`：单步越过，执行当前语句及其函数调用，然后停在当前调用层的下一条语句；调用中存在的其他断点仍可命中。
- `F8`：单步跳出，执行到当前函数返回后的调用层；在主脚本中跳出会运行至结束或其他断点。
- `Shift+F6`：停止脚本，解除断点等待并注销事件；顶部“停止”按钮和 `/lua stop` 同样有效。

单步功能需先暂停。纯事件监听处于等待状态时也能暂停；此时按单步会等待下一次事件回调，在回调的第一条语句停下。多个事件到来不会在后台并发执行回调，事件队列仍受服务器容量限制。关闭 IDE 不会自动继续暂停的脚本，可以通过游戏快捷键或 F12 面板继续／停止；管理员离线或服务器关闭则停止其脚本。调试快捷键统一在 F12 面板的“断点控制与快捷键”页面修改，IDE 与游戏内使用相同配置。

示例：把断点放在 `local answer = double(4)` 这一行，运行后按 F7 进入函数、F10 执行乘法、F8 返回调用处，最后按 F6 继续。

```lua
local function double(value)
    local result = value * 2
    return result
end
local answer = double(4)
print("结果：", answer)
```

## Lua 基础：从会读到会写

Lua 脚本按从上到下的顺序执行。语句末尾通常不需要分号；用 `--` 写单行注释。IDE 会自动缩进、给关键字上色，但语法检查通过只说明代码结构正确，不保证玩家在线或资源 ID 存在。

### 实时检查：错误与警告

代码和行号中的红色表示确定的静态错误，黄色表示需要注意的风险。顶部状态显示两者数量，悬浮状态提示可查看中文解释；黄色警告不会禁止运行。编辑后会重新检查当前文件，换行不会把旧诊断留在上一版本的行号上。

检查内容包括：未声明的变量及作用域、API 名称和参数数量／类型、资源 ID 和 UUID 格式、已知 `nil` 的参数或字段访问、调用非函数、明显错误的算术／连接／长度／比较运算、表的 `nil` 键。重复表键、同名局部变量遮蔽、分支中可能未赋值、除数或循环步长为 0 会给出黄色警告。数字字符串允许参与 Lua 算术；表的元方法、模块返回值和其他运行时动态值不会仅凭猜测判错。

特别注意：`local` 会创建新变量，而不是修改外层同名变量。下面的停止回调读取的仍是外层的 `nil`；IDE 会在声明处提示遮蔽，并标记停止回调的参数错误：

```lua
local entityUuid = nil
local function start()
    local entityUuid = MC.Entity.spawn("minecraft:pig", 0, 64, 0)
    -- 想更新外层变量时，应写 entityUuid = MC.Entity.spawn(...)
end
MC.Event.onScriptStarted(start)
MC.Event.onScriptStopped(function()
    MC.Entity.kill(entityUuid)
end)
```

修改赋值后，清理仍建议加 `if entityUuid then ... end`，避免脚本在生成实体之前就被停止。检查器识别这种保护、`x ~= nil`、`assert(x)` 和提前 `return` 的常见写法。静态检查不执行脚本，不加载 `require` 模块，也不能保证动态资源存在或预测所有事件执行顺序；最终仍以运行结果为准。

### 变量、类型和输出

使用 `local` 创建局部变量；优先使用它，避免不同代码互相覆盖。常用类型有数字、字符串、布尔值、表、函数和 `nil`。`nil` 表示“没有值”，不能把它当作数字直接计算。Lua 的数组索引从 **1** 开始，不是 0。

```lua
local count = 3                 -- 数字
local itemId = "minecraft:apple" -- 字符串
local enabled = true            -- 布尔值
local missing = nil             -- 没有值

print(count, itemId, enabled, missing)
print(type(itemId))             -- string
print(tostring(count) .. " 个苹果") -- .. 用于拼接字符串
```

字符串可用单引号或双引号；`\n` 表示换行。长段原样文本可写成 `[[...]]`。Lua 中只有 `false` 和 `nil` 被当作假；数字 `0` 与空字符串 `""` 都是真。

### 运算、判断和循环

常用比较符号：`==` 相等、`~=` 不等、`<`、`<=`、`>`、`>=`。逻辑组合用 `and`、`or`、`not`。`if`、`for`、`while`、`function` 等块以 `end` 结束。不要用 `=` 比较，它只负责赋值。

```lua
local score = 12
if score >= 10 then
    print("通过")
else
    print("未通过")
end

for i = 1, 3 do
    print("第", i, "次")
end
```

`while` 会一直重复到条件变成假。不要写没有等待、没有退出条件的高频循环；即使它能被停止按钮打断，也会浪费计算资源。需要按游戏刻长期处理时优先使用 `MC.Event.onServerTick`，并设置合理间隔。

### 函数、局部作用域和返回值

函数可接收参数、返回结果；`local function` 限定名称只在当前作用域使用。函数里的局部变量不会自动变成其他函数的变量。一个函数可以返回多个值，接收时按位置排列。

```lua
local function reward(count, multiplier)
    local total = count * multiplier
    return total, total >= 10
end

local amount, enough = reward(4, 3)
print(amount, enough) -- 12  true
```

### 函数注释与代码折叠

在 `function` 的参数括号下面、第一条实际语句之前写普通 Lua 注释，IDE 会将其用于本文件的补全与悬浮提示：

```lua
local function welcome(player, message)
    --#name=欢迎玩家
    --#Introduction=向指定玩家发送欢迎信息
    --@player=目标玩家
    --@message=欢迎内容
    print(player .. ": " .. message)
end

welcome("Alex", "你好")
```

`--#name=` 定义函数作用的译名，`--#Introduction=` 定义介绍，`--@变量名=` 定义参数或函数内变量的说明。支持中文变量名、`--@...=` 可变参数说明和嵌套函数；多条标记可分别写在多行，也可放在同一行普通注释里。函数补全显示“代码名称 · 译名”，也可用译名搜索；插入时仍使用代码名称。悬停函数名称可查看介绍与参数说明，悬停函数内对应变量可查看变量说明。局部函数提示遵循所在块的可见范围。

点击多行函数起始行右侧、代码左侧的小方框可折叠或展开函数；“+”表示已折叠，“−”表示已展开。嵌套函数可以独立折叠，各文件分别保留当前的折叠状态。搜索或调试跳到隐藏代码时自动展开，编辑折叠范围时也会展开。单行函数和没有写完 `end` 的函数不提供折叠。

注释仅在 IDE 中提供提示，在 Lua 中保持普通注释；折叠只改变显示。保存、复制全文与运行始终使用完整源码，隐藏的代码不会被删除或替换。

在 **工具 → 代码折叠** 子菜单中，可以选择 **展开全部代码**、**折叠全部代码**、**折叠函数代码**。全部折叠包含多行函数、if 和数组／表；函数折叠仅折叠函数（包括匿名回调和嵌套函数）。展开全部也会清除被外层遮住的内层折叠。

关闭 IDE 时会按文件记住折叠位置，下次打开自动恢复。不同服务器／世界和玩家分别保存，不相互影响；文件在外部修改后，旧折叠位置不再恢复，避免隐藏错误的代码。

### 表：数组、对象和嵌套配置

Lua 的表既能存列表，也能存按名称取值的对象。`ipairs` 适合按 1、2、3 顺序遍历数组；`pairs` 用于遍历键值表，顺序不保证固定。很多 `MC.*` 方法使用表传复杂选项或返回结果。

```lua
local names = {"Alex", "Steve"}
for index, name in ipairs(names) do
    print(index, name)
end

local player = {uuid = "示例UUID", name = "Alex"}
print(player.name)       -- 与 player["name"] 相同

local components = {
    ["minecraft:unbreakable"] = {},
    ["minecraft:custom_name"] = {text = "示例剑", color = "gold"}
}
print(components["minecraft:custom_name"].text)
```

不要把上面的“示例UUID”直接传给游戏 API；要读取真实在线玩家 UUID，可用 `MC.Player.list()`。表的键若含冒号等特殊字符，必须使用 `["键名"]` 写法。

### 常用标准库与错误处理

`string.format` 格式化文本，`math.floor` 向下取整，`table.insert` 给数组追加元素。`pcall` 可捕获某次操作的运行错误；它不会让无效资源 ID 突然变有效，也不能绕过服务器权限限制。

```lua
local values = {2, 4}
table.insert(values, 6)
print(string.format("共有 %d 项", #values))
print(math.floor(3.8))

local ok, result = pcall(function()
    return MC.Item.name("minecraft:apple")
end)
if ok then print(result) else print("读取失败：", result) end
```

### 黄色运行警告与可恢复错误

`MC.*` 调用遇到目标区块未加载、合法 UUID 对应的玩家已离线、实体已移除或未加载时，会显示黄色 `⚠` 警告，只跳过本次调用，后续语句与事件监听继续运行。失败统一返回 **`nil, 原因字符串`**，不会伪装成成功，也不会强制加载区块。填充／复制会先检查整个区域，遇到未加载区块时不修改任何方块；没有区块数量限制，但仍受脚本运行时限约束。

```lua
local block, reason = MC.Block.get(1000000, 64, 1000000)
if block then
    print(block.id)
else
    print("本次读取跳过：", reason)
end
print("脚本继续执行")
```

读取失败后不能直接使用 `block.id`：对 `nil` 取字段仍是 Lua 运行错误。`pcall` 对这些安全失败返回 `true, nil, 原因`，因为 API 不再抛异常；应检查 API 的第一个返回值。原先已返回 `nil`／`false` 的“是否存在”等查询保持不变。

语法错误、参数类型／范围错误、非法 UUID、未知资源 ID／维度、权限／客户端安装要求、超时与停止脚本仍按错误处理。不会根据错误消息文本把任意异常改成警告，也不会改动原版命令语义。警告包含 API 名称与源代码位置，同一警告每秒最多显示一次，每次运行最多显示 50 条，之后给出一次省略提示，不会因为警告刷屏而终止脚本。IDE 日志、F12 日志和 `/lua` 命令反馈均以黄色显示警告。

### 毫秒等待与游戏 Tick

`MC.sleep(毫秒数)` 仅暂停调用它的主流程或当前事件回调，不会暂停游戏主线程，也不会堵住其他监听：同一个事件再次触发时，也可以开始新一次回调。`MC.sleep(1000)` 约等于等待一秒。单次允许 0–3600000 毫秒，等待也算在脚本最长运行时间里，“停止脚本”会取消全部等待。实际醒来时间受系统调度和其他正在执行的代码影响，不适合要求绝对精确的计时。

```lua
print("开始")
MC.sleep(500) -- 等待约半秒
print("半秒后继续")
```

Minecraft 正常约每秒运行 20 Tick，但卡顿或修改 Tick 速率会改变它与真实时间的关系。与游戏逻辑同步的重复任务用 `MC.Event.onServerTick`；按真实毫秒间隔重复的任务用 `MC.Event.onInterval(intervalMs, callback)`；简单的顺序等待用 `MC.sleep`。不要用空转循环代替等待。

```lua
MC.Event.onItemUsed(function(event)
    local name = event.playerName -- 每次回调的局部变量独立保存
    print(name, "使用物品，开始等待")
    MC.sleep(1000)
    print(name, "一秒后继续")
end)

MC.Event.onBlockPlaced(function(event)
    -- 上面的回调正在等待时，这里仍会立即执行
    print(event.playerName, "放置了", event.blockId)
end)
```

所有流程仍共享脚本的全局变量与外层局部变量；它们只在 `MC.sleep` 等待处交错执行，不会同时操作 Lua 状态。不要假定变量在等待期间保持不变，需保留旧值时先复制到当前回调的局部变量。高频 Tick 回调中的长延时可能积累大量等待流程，数量受服务器“事件队列容量”限制，达到容量后新回调会排队；事件队列也满时沿用丢弃最旧事件的策略。取消监听不打断已经开始的回调，停止整个脚本才会取消全部等待。

### 第一次调用游戏 API

每个 `MC.*` 函数的参数顺序不同，先看悬浮提示或 API 文档。玩家相关操作必须明确传入玩家 UUID；脚本以服务端视角运行，不能假定“当前玩家”就是打开 IDE 的人。下面的示例只读取信息，不修改世界：

```lua
local players = MC.Player.list()
if #players == 0 then
    print("目前没有在线玩家")
    return
end

local player = players[1]
print("玩家：", player.name)
print("UUID：", player.uuid)
print("苹果名称：", MC.Item.name("minecraft:apple"))
```

在正式修改世界前，建议先用 `print` 验证要操作的玩家、维度、坐标和资源 ID。`minecraft:` 是原版命名空间；其他 Mod 的 ID 使用其注册的命名空间。下面的章节介绍 IDE 工具，后半部分逐类解释游戏 API 与复杂配置。

## 脚本目录

Lua、datapack 和 resourcepacks 三个目录窗口将父目录显示在输入框上方，长路径从左侧省略，悬浮可看完整路径。输入框默认只编辑最后一级名称，`Ctrl+A`、Home 和退格不会删掉隐藏的父目录；窄窗口中的长名称会跟随光标横向滚动。点击上方路径行可临时编辑完整路径，Esc 返回名称模式，仍保留原有的创建路径规则。

- 在“文件”窗口输入 `tools/math` 并点击“新建脚本”，会自动创建 `tools` 子目录；也可以先输入 `tools` 点击“新建目录”。
- 左侧目录树可展开/收起；左键点击脚本直接读取并切换标签。右键文件或文件夹打开操作菜单，可重命名或删除；删除前看清目标和确认提示。目录只有在空时才能移除，不会递归删除脚本。
- 路径用 `/` 分隔，最多 6 层；每层可使用 1～48 个英文字母、数字、下划线或连字符，不输入 `.lua` 后缀。
- 文件保存在服务端 `config/mc_lua_ide/scripts`；客户端不保存服务端脚本副本。服务端会逐项校验路径并拒绝符号链接与越界路径。

### 一个 Lua 文件调用另一个 Lua 文件

使用 `MC.Script.require("目录.模块名")` 或 `require("目录/模块名")` 安全加载服务端脚本目录内的 `.lua` 文件。两种写法使用同一份缓存：同一次运行中模块只执行一次，返回模块的 `return` 值；没有返回值时得到 `true`。不能使用 `..`、绝对路径或跨出脚本目录。这个功能不需要开放高危的原生 `package` 权限。

先创建 `demo_modules/util.lua`：

```lua
local M = {}

function M.greet(name)
    return "你好，" .. name .. "！"
end

function M.square(number)
    return number * number
end

return M
```

再创建并运行 `demo_modules/main.lua`：

```lua
local util = MC.Script.require("demo_modules.util")
print(util.greet("Lua IDE"))
print("7 的平方 = " .. util.square(7))
print("模块缓存正常：" .. tostring(util == require("demo_modules/util")))
```

运行日志应输出“你好，Lua IDE！”、“7 的平方 = 49”和“模块缓存正常：true”。也可用 `/lua run demo_modules/main` 运行；原有的引号写法仍可用。修改模块文件后，下一次启动脚本才会读取新内容。

将模块返回值赋给变量后，输入 `util.` 会显示模块导出的函数，支持上下键选择、Tab 或鼠标点击补全；冒号方法可输入 `util:`。列表显示函数参数和中文注释，悬浮可看来源文件与说明。支持 `return M`、直接返回函数表、嵌套表以及模块再导出；模块内部未导出的私有函数不会显示。编辑器通过管理员读取权限获取服务器上的模块代码，只做静态分析，不会执行 `require` 或运行模块；已打开的模块标签优先使用未保存的内容。路径必须是字符串常量，通过运行时计算路径或动态生成的函数无法预先推断。

函数头之后可以添加 `--#name=中文简介`、`--#Introduction=使用说明` 和 `--@param=参数名 参数说明`，它们会出现在模块函数的补全提示中。事件回调 `MC.Event.on…(function(event)` 的函数体自动缩进 **4 个空格**，内部再嵌套 `if` 等代码块时每层增加 4 个空格；粘贴或插入多行代码不会再次叠加当前位置已有的缩进。

## datapack 目录编辑器

- 点击“文件 → datapack 目录”打开独立窗口。输入小写数据包名（例如 `demo`），点击文件夹图标创建模板。模板含 `pack.mcmeta` 和 `data/demo/tags/item/example.json`，保存在当前世界的 `datapacks/mc_lua_ide_edit_demo`。此窗口仅管理自己创建的包，不会列出或删除其他数据包。
- 点击目录展开；点击 JSON、`.mcfunction` 或 `pack.mcmeta` 在代码框中打开。输入完整路径（例如 `demo/data/demo/recipe/my_recipe`）后点击文件图标，可新建 `.json` 文件并自动创建所需子目录。已打开的数据包文件可与 Lua 文件一起在顶部标签栏切换，`Ctrl+S` 保存；JSON 使用独立配色与格式检查，不会按 Lua 运行或自动套用 Lua 粘贴缩进。
- 数据包目录还会列出已有的 `.png`、`.ogg`、`.nbt` 文件，左键可在编辑区打开只读预览：PNG 显示图片尺寸和缩放预览，OGG 可播放/停止；普通 NBT 可展开标签树。若 NBT 符合原版结构模板的 `size`、`palette`、`blocks` 格式，会默认显示 3D 方块视图：按住鼠标左键拖动旋转、滚轮缩放、右键恢复视角，右上角可切回 NBT 标签树。结构视图读取当前客户端加载的方块模型与贴图（包括资源包及其他 Mod），并应用结构文件中的方块状态；极大或无法取得模型的结构会退回简化颜色视图。方块实体的动态内容、场景光照和结构内的实体不在此预览中。预览文件最大 8 MiB，切换标签时声音会停止。它们不会经过文本编辑器保存；放在数据包目录的 PNG/OGG 也不会因此自动成为客户端资源包，请按资源包流程发布材质和声音。
- 右键 `数据包/data` 选择“新建命名空间”。在命名空间目录右键选择“快捷创建类型…”，会列出当前版本常见的 `advancement`、`recipe`、`loot_table`、`function`、`tags`、`worldgen` 等目录及中文作用；在 `tags`、`worldgen` 下继续右键，也可快捷创建对应的二级分类。弹出的列表支持输入文字筛选、鼠标滚轮及上下键切换、点击或回车创建，鼠标悬浮可查看完整作用。
- 目录树中的文件夹会显示“目录名 - 作用”，例如 `recipe - 定义工作台、熔炉等合成配方`；窗口较窄时，悬浮目录名可查看完整说明。自建的未知目录标为“自定义目录”。
- 在已识别的类型目录内右键“新建…”，或在顶部输入完整路径新建文件，会自动填入该类型的示例内容，不再只有 `{}`。配方、进度、战利品表、谓词、物品修饰器和命令函数使用可修改的内置示例；维度示例从当前服务器的主世界注册数据生成；其他复杂类型优先取当前游戏原版数据中的同类型示例，标签保留 `replace` 与 `values` 结构。示例中的物品 ID、文字和规则需要按需求修改；保存并重载后它也会作为真正的数据包内容参与游戏。

- 点击“UI 与窗口 → 视图 → 数据包 JSON 编辑器”打开可拖动、缩放或吸附的编辑窗口。左侧“类型”包含进度、配方、战利品表、标签、维度、世界生成等标准 JSON，以及当前游戏扫描到的模组自定义目录；切到“示例”可读取服务器正在加载的数据包和模组 JSON。右侧以树形图编辑字段，灰色字段从当前类型的已加载示例抽样汇总，点击后才会加入文档；也可以自行添加键、数组条目或直接编辑原始 JSON。字段显示中文说明，原始键名保持不变；可识别的 ID 字段能搜索当前注册表，其他字段显示示例中观察到的可选值。先在 datapack 目录打开某个 `.json` 或 `pack.mcmeta`，按 `Ctrl+I` 会自动选择其类型并导入当前内容。点击“校验并插入”会覆盖同类型的当前文件编辑内容，之后仍需保存并重新加载数据包。维度文件由服务器维度编解码器校验；其他类型目前仅校验 JSON 语法（标签另检查 `values` 数组），不是完整的游戏格式校验。示例字段是提示，不保证涵盖该类型或模组的所有合法字段；现有世界的生成配置可能还需重新进入世界。
- 在 `function` 目录内会创建 `.mcfunction` 文本文件。编辑器会分别高亮命令名、注释、资源 ID、选择器、坐标和宏占位符；输入时从当前连接的游戏命令树读取候选，按上下键切换、`Tab` 或鼠标点击补全（包括服务器提供的命令参数建议）。`Ctrl+I` 会在 `give`、`setblock`、`summon`、`effect give` 等常用命令参数处切换到相应的 ID 插入分类，插入时不添加 Lua 引号；`Ctrl+/` 使用 `#` 注释。点击运行或按 `Ctrl+Enter` 会直接按原版命令函数语法检查并执行当前编辑内容，同时保存文件，不必为了运行当前函数而 `/reload`。宏函数需要参数，仍须使用 `/function`；调用其他尚未加载的函数仍需重载数据包。原版函数执行无法中途停止。`.mcfunction` 暂不实时检查命令语义。`structure` 的 `.nbt` 是二进制文件，当前编辑器只提供结构目录与说明，不生成无效的空结构文件。
- 分类依据 [Minecraft Wiki 的数据包目录结构](https://zh.minecraft.wiki/w/数据包#文件结构) 和本项目适配的 Minecraft 26.1.2 内置数据目录；若其他模组定义了额外目录，可继续使用通用新建操作。
- 右键其他目录仍可选择“新建文件夹”或通用“在此新建 JSON”，以兼容其他模组的数据类型。右键 JSON 文件、函数文件、命名空间、普通文件夹或数据包根目录可“重命名”。在顶部输入框修改名称后按 `Enter` 或点击 ✓ 确认，按 `Esc` 或点击 × 取消。重命名只修改当前目录下的名称，不会把文件移动到别处；`data` 根目录和 `pack.mcmeta` 不可单独重命名。
- 右键文件或目录选择删除；为避免误删，需要再次右键选择“确认删除”。删除数据包根目录会连同其所有文件一起删除；`data` 根目录和 `pack.mcmeta` 不可单独删除。
- 右键数据包根目录、子目录或文件，还可选择“在资源管理器中打开”或“在终端中打开”。单人世界会打开当前世界内由 IDE 管理的数据包实际位置；右键文件时资源管理器会定位到文件，终端会进入其父目录。远程服务器的文件并不在玩家电脑上，因此这两个选项会显示提示，需在服务器主机上操作。菜单不会打开其他数据包或接受越界路径。
- JSON 编辑器目前只保存数据包文件，**不会自动启用新包或热重载**。首次创建后请在服务端用 `/datapack list` 确认包 ID 并手动启用；修改已启用包后使用 `/reload`。维度及部分世界生成内容仍可能需要重新打开世界，JSON 格式通过检查也不代表游戏会接受该类别的全部字段。

## resourcepacks 资源包编辑器

### 快速添加物品材质

在资源包目录右键 `assets/<命名空间>` →“快速添加”→“快速添加物品材质…”，选择本机 PNG，再输入物品模型 ID，例如 `test:shop/gem`（也可只填 `shop/gem`，自动使用当前命名空间）。按 Enter 或“确认导入”后，会同时创建 `textures/item/shop/gem.png`、`models/item/shop/gem.json`、`items/shop/gem.json`；模型使用 `minecraft:item/generated` 平面物品样式，贴图保留原分辨率和透明度。导入后自动展开目录并打开 PNG，可继续用图片工具编辑。按 Esc 或“取消”不会导入。已有同名贴图、模型或物品定义时，整次导入会拒绝覆盖；请换一个 ID。支持最多 16 MiB、边长不超过 2048 且总像素不超过 1048576 的 PNG，不会把其他格式改名当作 PNG。

这些文件只创建资源，不注册新的物品类型。启用资源包并按 F3+T 重载后，可通过 `/give @s minecraft:paper[minecraft:item_model="test:shop/gem"]` 查看材质；Lua 给予物品时也可传入 `{"minecraft:item_model":"test:shop/gem"}` 组件。其他玩家需要同样的资源包才能看到效果，文件仍保存在管理员客户端，不会自动上传。若在 `minecraft` 或已有模组的命名空间使用原物品 ID，则会在启用该资源包后替换对应物品的模型显示。

### OGG 音频预览与 ID 更新

在 resourcepacks 目录左键点击 `.ogg` 文件，即可在主编辑区打开只读音频预览，查看 Vorbis 格式、采样率、声道数和文件大小，点击“播放／停止”试听。不必先启用该资源包；切换标签、关闭 IDE 或重载资源包会停止预览。客户端资源包 OGG 预览上限 64 MiB，服务端数据包只读预览仍为 8 MiB；只支持游戏能解码的 OGG Vorbis，不会转换 Opus 文件。

播放时显示进度条、当前播放时间／总时长（精确到 0.1 秒）和百分比。进度读取游戏音频设备的位置，并累计已经移除的流式缓冲区，暂停时不会按系统时间继续走动；自然播放结束保持 100%，点击停止或切换标签清零，再次播放从头开始。点击进度条或按住左键拖动可跳播：拖动时显示目标时间，松开后从目标位置播放；未播放或已结束时也可拖动选定起点，拖到最右端则显示播放结束。定位在后台执行，停止、切换标签或再次定位会取消过期的定位任务，不会延迟恢复旧位置的音频。总时长通过 Vorbis 流的结束页面采样数计算，缺少结束页面时显示“未知”，不会编造时长，此时不能拖动定位。详情区显示声道、采样率、字节数、含容器开销的平均码率、可用的标称码率、编码器，以及文件内已有的标题、作者、专辑等注释；窗口较小时用鼠标滚轮查看详情。元数据只在打开文件时读取，不会每帧重新扫描或完整解码音频。

数据包目录、资源包目录和插入窗口的刷新按钮会更新编辑器 ID 缓存；成功执行服务端 `/reload` 或客户端资源包重载（例如 `F3+T`、切换资源包）后，插入窗口、组件树中的 ID 搜索和 JSON 编辑器的参考列表也会更新。服务端管理员会收到数据包重载通知，普通玩家不会获得编辑目录或脚本权限。资源文件索引按需读取并缓存，不在每帧扫描目录。

编辑器合并游戏当前加载的 ID 与 IDE 创建目录里的文件定义，包含其他 Mod 的命名空间；嵌套路径如 `data/test/recipe/tools/demo.json` 显示为 `test:tools/demo`，标签显示为 `#test:标签名`。尚未启用或重载的编辑目录 ID 会注明状态，出现在搜索列表并不保证游戏调用已可使用。删除未加载的定义后刷新会移除；已加载的 ID 需成功重载后才从游戏目录消失，世界生成等类型仍可能需要重新打开世界。

资源 ID 按用途区分：`models/item/demo.json` 是模型资源 `test:item/demo`，`items/demo.json` 是物品模型定义 `test:demo`，它们都不注册新的物品或方块。`sounds/music/demo.ogg` 的文件 ID 是 `test:music/demo`；`sounds.json` 中的键 `music.demo` 才是声音插入分类里的音效事件 ID `test:music.demo`。组件树的注册表类型选择器提供模型、纹理、字体、装备、音频文件、粒子贴图定义、方块状态模型和图集等客户端资源类别；资源包 JSON 的模型、纹理和声音文件字段可以搜索这些资源。

主“插入”窗口保留全部游戏和资源包 ID 类型分类，只移除“游戏ID（含音效事件）”与“资源包”两个分组按钮。分类栏可翻页，或用左右方向键切换；每个页面只显示对应类型，并支持命名空间筛选和文字搜索。资源分类包括物品模型、模型、纹理、OGG 音频文件、字体、装备模型、提示框样式、粒子贴图、方块状态和图集。声音事件合并资源包 `sounds.json` 的自定义音效，本地资源包 ID 不依赖服务端查询成功。新建、保存、重命名、删除和快速导入音频会更新索引；外部程序修改文件后点击刷新按钮。未启用的 IDE 编辑目录资源也会列出并标明状态，启用资源包或 `F3+T` 重载后读取已加载资源。只有模型定义而没有注册为物品的 ID 会标为模型资源，不会标成物品。

资源包编辑分为三个可独立移动、调整大小、吸附到 IDE 边缘的窗口：“文件 → resourcepacks 目录”管理文件；“UI与窗口 → 视图 → 资源包 JSON 编辑器”提供 JSON 字段树和游戏资源参考；“UI与窗口 → 视图 → 图片工具”提供像素工具、调色板、分辨率和图层。**实际 JSON 原文始终显示在主代码编辑区**，PNG 画布也在主编辑区；可以同时打开这些工具窗口，贴边后与其他窗口一样使用标签切换。这里编辑的是**当前管理员客户端**的 `resourcepacks/mc_lua_ide_edit_<包名>`，不是服务端数据包，不会自动发布给普通玩家。点击“新建包”会按当前游戏的客户端资源包格式创建 `pack.mcmeta`，以及 `assets/<命名空间>/items/example.json`、`models/item/example.json` 和 `textures/item/example.png` 示例。目录窗口可输入包内完整路径创建目录、JSON 或 PNG，也可选择后重命名、两次确认删除。编辑器只管理自身创建的 `mc_lua_ide_edit_` 资源包，不会覆盖其他现有资源包。

目录树中右键资源包、文件夹或文件，可在当前位置（文件则在同级目录）新建文件夹、JSON 或 PNG；右键 `assets` 可新建命名空间，右键命名空间及 `models`、`textures` 等上级目录可选择“快捷创建资源类型”，直接建好对应目录。右键空白处可新建资源包模板。选择需要输入名称的操作后，父路径在输入框上方显示，输入框选中建议文件名；输入名称按 Enter 或“确认创建”创建，Esc 或“取消”返回，创建的 JSON 会带相应类型示例，PNG 默认 16×16。重命名和删除统一在右键菜单中，不再占用顶部按钮：重命名时修改名称后确认，也可取消；删除需再次右键同一项选择“确认删除”。修改前必须关闭目标及其目录内已打开的文件标签。类型列表可用滚轮浏览，悬浮显示用途说明。

例如要更换原版钻石物品贴图，可在自己创建的包内编辑 `assets/minecraft/textures/item/diamond.png`，使用现有钻石模型；改变模型时再编辑 `assets/minecraft/models/item/diamond.json` 或当前版本的 `assets/minecraft/items/diamond.json`。资源 ID 与路径必须匹配：模型中 `minecraft:item/diamond` 对应 `assets/minecraft/models/item/diamond.json`，纹理中同名 ID 对应 `assets/minecraft/textures/item/diamond.png`。其他 Mod 的内容使用它自己的命名空间。`assets/<命名空间>` 下还可建立 `blockstates`、`models/block`、`textures/block`、`textures/entity`、`textures/gui/sprites`、`atlases`、`font`、`lang`、`sounds` 等目录。资源包 JSON 编辑器与数据包 JSON 编辑器采用相同的左右分栏：左侧“类型／示例”标签可搜索 ID、中文或拼音首字母并滚动浏览，右侧是当前 JSON 的字段树；切换类型不会覆盖当前文件，点击当前客户端已加载的原版、模组或资源包示例才会载入示例。字段树修改会同步到主代码编辑区，底部可写入主编辑器、复制 JSON 或重新读取当前文件；最后按 `Ctrl+S` 保存。具体合法结构仍取决于当前版本的资源类型。

PNG 主画布支持铅笔、画笔、橡皮、整片相邻区域填充和取色。铅笔绘制硬边方形像素笔触，画笔绘制柔边圆形笔触；铅笔、画笔和橡皮都可用图片工具窗口中的“－”“＋”分别调整 1～32 像素大小，切换工具会记住各自的大小。在 Windows 8 及更新版本上，支持通过 Windows Ink 上报压力的数位笔：压力会改变铅笔、画笔、橡皮的笔尖大小，画笔和橡皮还会随压力改变绘制或擦除强度；检测到数位笔后，画布顶部会显示实时压力百分比。普通鼠标及未上报压力的设备保持满压力绘制，其他操作系统当前仅支持普通鼠标行为。鼠标悬浮在图片上时会显示当前笔尖覆盖范围的边框，超出图片的部分会被裁掉。主画布滚轮缩放、中键拖动平移。独立图片工具窗口有 RGB 调色板（左右按钮切换色组）、十六进制颜色输入、宽高分辨率输入与图层添加、删除、显示/隐藏、上下移动；工具窗口内滚轮用于上下滚动面板。输入框中按回车或点击“应用”确认。`Ctrl+Z` / `Ctrl+Y` 撤销重做，`Ctrl+S` 保存。新建 PNG 默认 16×16，之后可在工具窗口调整；最大边长 2048，像素总数不超过 1048576。透明背景棋盘格按图片像素逐格显示，调整分辨率后会同步变化。保存时资源包中的 PNG 会展平为游戏可读取的图片；可再编辑的图层工程单独保存在客户端 `config/mc_lua_ide/resource_layer_projects`，**发布给玩家时只需资源包，不要分发图层工程**。如果外部程序改写了 PNG，旧图层工程不会覆盖它。

右键 `assets/<命名空间>` 目录，选择“快速添加 → 快速添加 OGG 文件”，会打开系统文件选择器。选择后，上方输入框预填音效 ID，可填写 `test:music/demo` 或 `music/demo`（省略命名空间时使用所选目录），按 Enter 或点击“确认导入”；Esc/取消不会写入文件。音频复制到 `assets/test/sounds/music/demo.ogg`，并自动在 `assets/test/sounds.json` 中添加 `music/demo` 音效事件；已有事件与属性保留，重名不会覆盖。只支持 Minecraft 可播放的 Ogg Vorbis，单文件最多 64 MiB，不支持仅改后缀的其他音频或 Ogg Opus。如果 `sounds.json` 在编辑器中打开，请先保存并关闭该标签再导入，防止覆盖未保存内容。导入完成后可用 `/playsound test:music/demo master @s` 播放（需先启用资源包并重新加载资源）。

保存不等于自动应用：先在游戏“资源包”界面启用该包，之后修改文件需重新加载客户端资源（可按 F3+T）；分发给玩家时手动压缩/发布整个资源包。此编辑器暂不提供 Photoshop 的滤镜、矢量图形或颜色管理；OGG 支持导入和预览，但不编辑音频波形。目录说明参考 [Minecraft Wiki 资源包](https://zh.minecraft.wiki/w/资源包) 与 [制作资源包教程](https://zh.minecraft.wiki/w/Tutorial:制作资源包)；实际类型以当前客户端加载的资源为准。

## Git 版本管理（本地 / GitHub）

点击顶部“Git”打开可移动、缩放、吸附的版本管理窗口，顶部可以切换“本地 Git”和“GitHub”。默认使用本地 Git，不需要网络或 GitHub 帐号，但服务器仍需安装 `git`。本地模式的“保存本地版本”只在服务器磁盘保存快照；GitHub 模式的“提交并上传”会保存提交并推送到配置的仓库。两种模式的历史独立保存，切换不会自动发布本地历史。

在“提交”页填写**版本简介**（必填，最多 240 字）和详细说明（可选，最多 2000 字），点击按钮或按 **Ctrl+Enter** 快速提交。GitHub 模式先通过浏览器登录并选择已有仓库或新建仓库，地址与默认分支会自动填写；“设置”页仍允许调整目标分支。仅服务器所有者或 OP 等级 4 能操作。操作范围仅包含服务端**已保存**的 Lua 脚本及本 IDE 管理的数据包，包括 JSON、mcfunction、PNG、OGG、NBT；不包含客户端 resourcepacks、Mod 源码、其他数据包、世界存档或服务器配置。仓库的 `mc_lua_ide` 子目录是该工作区的镜像，工作区中删除的文件也会在下次提交中删除；仓库其他目录不受影响。编辑器存在未保存内容时必须先保存。

“版本历史”按时间倒序显示提交 ID、时间、简介，以及“已上传 / 尚未上传”状态。每页 30 个版本，滚轮浏览列表，使用“更早 / 更新”翻页。选中版本后点击修改文件，可查看绿色新增、红色删除的差异，或切换“查看代码”阅读该版本完整文件的预览；长预览会截断，但恢复使用的是完整文件。预览区滚轮上下滚动，**Shift+滚轮**左右滚动。窄窗口中点击“历史”返回列表；将窗口拉宽可以同时查看历史与代码。鼠标悬浮版本标题可阅读完整简介和详细说明。

“恢复所选版本”需要再次确认，会恢复**整个** Lua / IDE 数据包工作区，包括删除在所选版本中不存在的新文件。请先保存所有编辑内容并停止正在运行的脚本。恢复前自动把当前已保存文件提交为一个**本地备份版本**，然后恢复文件并新增恢复提交，不执行回退历史或强制推送；误操作可以在本地历史中选择“恢复前自动备份”再次恢复。GitHub 模式下恢复后**不会自动上传**，需要再次点击“提交并上传”发布。数据包恢复后可使用“工具 → 重载数据包”，运行中的游戏数据不会自动热重载。恢复时不会触及其他数据包或不支持的文件。

持久版本库存储在当前世界的 `mc_lua_ide_git/local` 或 `mc_lua_ide_git/github-…` 中，可以备份这些目录保留历史；Lua 源文件仍在服务器 `config/mc_lua_ide/scripts` 中。单个版本最多 4096 个文件、每文件 20 MiB、总计 256 MiB；文本仍遵守主编辑器容量。一次详情预览最多列出前 512 个修改文件，恢复仍包含全部文件。旧版已经上传的 `mc_lua_ide` 提交可在配置原仓库、原分支后读取。

GitHub 模式现在提供浏览器登录引导：选择“GitHub”或点击“GitHub 登录 / 账号 / 选择仓库”，然后点击“使用浏览器登录”。游戏显示一次性验证码并打开 `https://github.com/login/device`；在浏览器登录并输入验证码完成授权，游戏自动跳转仓库列表。验证码约 15 分钟有效，服务器按 GitHub 返回的间隔轮询，取消、拒绝授权或过期后可以重新登录。无需在游戏里填写密码、Client Secret 或 Token。

**默认无需配置登录应用**：模组已内置维护者注册的 OAuth App 公开 Client ID `Ov23li9ALF0BE5QLuRIs`。用户直接点击“使用浏览器登录”，各自授权并登录自己的 GitHub 账号；不会共享维护者账号、访问令牌或仓库权限。首次打开账号页面只读取登录状态，不自动发起授权或打开浏览器。

服务器如需使用自己的应用，可点击“配置 Client ID → OAuth App 设置”，进入 GitHub Settings → Developer settings → OAuth Apps，注册应用并勾选 **Enable Device Flow**。这里只填写公开 Client ID，不要填写 Client Secret 或 Token。覆盖配置保存在服务器 `config/mc_lua_ide/github-login.properties`，所有管理员共用；更改会清除已有登录。留空保存可恢复内置默认应用。配置优先级为：服务器启动环境变量 `MC_LUA_IDE_GITHUB_CLIENT_ID` → 配置文件中的非空 Client ID → 内置默认值；环境变量设置后不能在游戏中覆盖。Device Flow 不使用回调地址，因此不需要部署回调服务。流程依据 [GitHub Device Flow 文档](https://docs.github.com/en/apps/oauth-apps/building-oauth-apps/authorizing-oauth-apps#device-flow)。

授权成功后可选择已有仓库：列表按更新顺序显示当前账号有写权限、未归档且未禁用的仓库，包含可访问的组织与协作仓库。每页最多请求 30 个，输入框按名称和简介**筛选当前页**，使用上一页 / 下一页查看更多。单击仓库后点击“使用所选仓库”或回车，服务端再次验证权限并自动保存地址与默认分支，返回提交页。也可点击“新建仓库”，填写名称与简介，选择私有（默认）或公开，再次确认后在当前登录账号下创建并自动选用；不会覆盖已有仓库。此版本新建个人仓库，不代建组织仓库。选定仓库和分支是**服务端共享配置**，其他管理员能看到相同工作区设置；登录账号和凭据则按管理员 UUID 分开。

**安全注意**：浏览器登录请求 `repo` 权限，以读取和上传授权范围内的公有/私有仓库并新建仓库。访问令牌只在**可信服务端的内存**和其 Git 子进程环境中使用，不写入设置、命令参数、仓库或客户端，不与其他管理员共享。关闭 Git 窗口可以保留当前登录；退出登录、断开服务器或停服会清除该会话凭据，下次需重新登录。游戏内退出登录并不撤销 GitHub 网站上的 App 授权，如需撤销，请到 GitHub Settings → Applications → Authorized OAuth Apps。普通玩家无权使用这些接口。公开仓库里的代码可被任何人查看，请检查敏感内容。

旧版服务器 HTTPS 凭据或 `MC_LUA_IDE_GITHUB_TOKEN` 仍保留为后台兼容方式；新的游戏内 GitHub 提交流程要求浏览器登录。推送不会使用 `--force`；失败时本地提交不会丢失，没有远端冲突时直接再次点击“提交并上传”即可重试。如果远端与本地历史发生分叉，模组会拒绝覆盖远端，需管理员在显示的专用版本库目录中手动合并；联网失败但已有缓存时，历史页仍显示缓存并提示错误。新功能要求管理员客户端与服务器使用相同模组版本（协议 36）。

## 多人服务器安装与权限

- 服务端必须安装 MC Lua IDE、Fabric Loader 和匹配版本的 Fabric API；Lua 运行器、脚本文件、事件监听和全部 `MC.*` API 都只在服务端运行。
- 需要使用 IDE 的管理员客户端必须安装同版本 MC Lua IDE。客户端只负责编辑界面、语法提示和发送受限请求。
- 默认情况下普通玩家客户端不需要安装本 Mod，也可以正常连接服务器。
- 管理员可在“Mod Menu → MC Lua IDE → 配置 → 服务器接入”开启“要求玩家安装客户端模组”。开启后，服务器会在玩家进入世界前发起登录握手；未安装 MC Lua IDE 或协议版本不一致的客户端会收到中文原因并被拒绝登录。修改只影响之后的新连接，不会踢出现有在线玩家。
- 只有单人世界所有者或拥有 OP 等级 4（`COMMANDS_OWNER`）的在线玩家可以列出、读取、保存、删除、运行和停止脚本。
- 权限在服务端对每一次请求重新校验。修改客户端、伪造数据包或直接发送网络请求都不能绕过权限检查。
- 强制安装关闭时，客户端与服务端协议版本不一致、服务端没有安装本 Mod 或权限不足会使 U 键无法打开 IDE，并在聊天栏显示具体原因；强制安装开启时，版本检查会提前到登录阶段。
- 独立服务器通常使用 `op <玩家名>` 授权，并保持 `server.properties` 中 `op-permission-level=4`。

连接目标服务器后，从“Mod Menu → MC Lua IDE → 配置”打开设置首页；未进入世界时，服务端配置按钮不可用。“Lua 限制”用于编辑服务端执行策略；“服务器接入”用于决定普通玩家是否必须安装客户端模组。限制按执行资源、事件、MC API、文件沙箱、Lua 语言能力和核心安全边界分页显示；鼠标悬停具体选项可查看说明。这里调整的是一份服务端全局配置，不按管理员账号分别保存：任意管理员保存后，其他管理员重新进入或刷新都会读取相同设置。只有服务器所有者或 OP 等级 4 可以读取和保存，配置位于服务端 `config/mc_lua_ide/lua-limits.properties`。Mod Menu 只是可选的客户端配置入口，并非服务端或普通玩家的必装依赖。

编辑脚本时可以点击顶部最左侧的“文件 → Lua 目录”，在不返回编辑器的情况下打开脚本管理窗口。“文件”二级菜单还包含“保存”和“运行/停止”；顶部功能栏同时提供一个常驻的独立“运行/停止”按钮，方便反复调试。

- 顶部输入名称并点击“新建”，可以创建新的 `.lua` 文件
- 左键点击脚本读取，右键打开重命名、删除等操作；当前编辑中的脚本会以橙色显示
- 支持 `↑`、`↓` 选择，按 `Enter` 读取所选脚本，鼠标滚轮浏览全部文件
- 标题栏可拖动，窗口四条边和四角都可以调整大小
- 移除当前正在编辑的脚本后，如果再次保存，文件会被重新创建

## 窗口吸附与布局

文件、使用手册、插入器、API 文档、物品堆叠组件编辑器和运行日志都可以作为浮动窗口使用，也可以像桌面 IDE 一样停靠到工作区。

- 拖动窗口标题栏到屏幕左侧、右侧或底部边缘；出现蓝色吸附预览后松开鼠标即可停靠
- 停靠面板会占用对应区域，代码编辑器会自动缩小，不会被面板覆盖
- 拖动停靠面板与编辑器之间的蓝色分隔线，可以连续调整左右区域宽度或底部区域高度
- 从停靠面板的标题栏向工作区中间拖动，可以恢复为原来的浮动尺寸和位置
- 同一侧可以停靠多个窗口；它们会组成标签组，并在该区域顶部显示“文件 / 手册 / 插入 / API / 组件 / 文本 / 日志”等标签
- 点击区域顶部的标签即可切换窗口；未选中的窗口会保留在该吸附区域，不会被挤回浮动状态
- 吸附或取消吸附时，窗口的位置、宽高与代码编辑区会连续过渡；调整停靠分隔线时仍保持跟手
- 标签切换带有滑动指示线和方向性内容揭示动画；窗口关闭后会先播放退出动画，再收回对应编辑区域
- 拖动窗口靠近可吸附边缘时会显示呼吸式预览；已有窗口的边缘会提示加入该区域的标签组
- 点击顶部“UI与窗口 → 固定当前布局”可锁定所有已停靠面板和分隔线；未停靠的浮动窗口仍能自由移动
- 如果只想锁定窗口的位置和吸附关系，但仍调整代码区与左／右／下窗口之间的边界，可在“UI与窗口 → 个性化 → 窗口布局”开启“固定布局时可调边框”并保存
- 锁定布局后，浮动窗口不会意外吸附；再次关闭“固定当前布局”即可继续修改停靠结构
- 已停靠的面板位于代码编辑器的上一层，但仍低于浮动窗口、搜索框和菜单；浮动窗口不会再被已固定面板遮挡
- 停靠位置、当前标签、区域尺寸、锁定状态以及每个窗口的显示/隐藏状态都会自动保存，退出并重新启动游戏后也会恢复
- API 文档首次打开时默认全部折叠；关闭后会记住分类展开状态、选中的函数或第三方文档页面、目录和正文滚动位置、搜索条件。重新打开 IDE 或重启游戏会恢复上次浏览位置；Ctrl+点击 / Ctrl+F1 跳转函数时只展开目标路径。搜索时匹配路径自动展开，仍可点击根目录、分类和 API 分组折叠／展开，右侧已选文档不受影响；搜索折叠状态也会随窗口保存，清空搜索不会改变原来的分类折叠状态。修改搜索词或切换拼音搜索开关时会重新展开新的匹配结果。
- 布局保存在客户端配置目录的 `mc_lua_ide/ide-layout.properties`；不影响服务端脚本或其他管理员的客户端布局
- “UI与窗口 → 视图”三级菜单集中提供“使用手册”“插入”“API 文档”“数据组件编辑器”“文本 JSON 编辑器”和“运行日志”；日志按钮即使脚本没有运行也可以打开空日志窗口

## 取色窗口

点击“UI与窗口 → 视图 → 取色”。窗口可以拖动、调整大小、吸附，显示状态和布局随 IDE 保存；也可在个性化的快捷键页面绑定 Ctrl / Shift / Alt + F1～F12 打开。

## ID 插入器

点击“UI与窗口 → 视图 → 插入”，或按 `Ctrl+I`，可以打开可拖动、可缩放的运行时 ID 插入窗口。

“使用手册”和“插入”窗口可以同时打开。两个窗口重叠时，点击可见窗口区域或“UI与窗口 → 视图”中的对应菜单项会把它切换到前面；再次点击已经位于前面的窗口菜单项才会关闭窗口。两个窗口仍可分别拖动和缩放。

以下类型仍分别提供分类页面，游戏类型与资源类型放在同一分类栏，不再有“游戏ID（含音效事件）”和“资源包”分组按钮。窄窗口可点击分类栏两端箭头翻页；鼠标点击类型标签，或用 ← / →、Tab / Shift+Tab 切换。上次分类保存到客户端 `mc_lua_ide/insert-picker.properties`，无参数提示时重新打开仍使用该分类。

- “物品 ID”：读取完整物品注册表
- “方块 ID”：读取完整方块注册表
- “实体 ID”：读取完整实体类型注册表
- “玩家 UUID”：读取当前服务器的在线玩家列表
- “状态效果 ID”“附魔效果 ID”“声音 ID”“粒子效果 ID”：读取当前服务端对应注册表
- 只有“声音 ID”页面支持本地试听：鼠标悬浮或使用 ↑ / ↓、PageUp / PageDown 选中声音条目时播放，切换到另一声音时立即停止上一段；切换分类时停止试听，物品、模型、纹理、OGG 文件等其他页面不会播放声音。静止的鼠标不会抢回键盘选择。移出列表、打开命名空间筛选、失去焦点、插入或关闭窗口会停止试听。试听使用已加载的客户端声音事件，包括其他模组和已启用资源包的声音；客户端缺少对应资源时显示提示，不会请求服务端播放或影响其他玩家。试听不循环、不受坐标距离影响，并遵循客户端主音量；只停止自己的试听音效，不停止游戏或 Lua 脚本的音效。
- “结构模板 ID”：读取当前服务端和数据包中的可放置结构模板（用于 `MC.Structure.place`，不是世界生成结构类型）
- “战利品表 ID”：读取当前服务端和数据包中的战利品表
- 输入文字可按完整 ID、路径、命名空间、本地化名称或中文首拼搜索；例如输入 `mlfk` 可以找到“命令方块”
- 点击“命名空间”打开独立选择器；每项显示命名空间、对应模组名称和当前类型的条目数量
- 命名空间选择器可按 Mod ID、模组显示名、中文或拼音首字母搜索；支持滚轮、`↑`、`↓`、`PageUp`、`PageDown`、`Home`、`End` 和 `Enter`
- 插入器打开时可按 `Ctrl+N` 快速打开或关闭命名空间选择器；按 `Esc` 会先关闭选择器，再关闭插入窗口
- 点击标题栏的 `↻` 重新读取全部类型的 ID
- 每个结果左侧会显示预览：物品模型、方块模型、实体本体、包含帽子/外层皮肤的玩家头像，以及客户端当前资源包里的状态效果图标和粒子贴图。粒子预览读取对应 `particles/<ID>.json` 的第一帧并使用游戏已加载的粒子图集；依赖运行参数的方块／物品粒子、没有贴图定义的粒子和缺失贴图会显示占位图标
- 鼠标滚轮浏览结果，单击条目或用 `↑`、`↓` 选择；按 `Enter` 插入并自动关闭窗口
- ↑ / ↓ 移动列表选择，← / → 切换类型分类；声音 ID 页面中的上下选择才触发试听
- 拖动标题栏移动窗口，拖动边框改变窗口大小

物品、方块和实体数据来自运行时注册表；其他游戏类型由服务器返回当前注册表或资源目录，因此也包含其他 Mod 和数据包的 ID。插入器仍分析光标所在的函数和参数序号，例如 `MC.Effect.give` 切到状态效果页面、`MC.Sound.play` 切到声音页面。在 Lua 物品组件的附魔键中按 `Ctrl+I` 会切到附魔页面；仍可手动切换其他分类。插入器通常自动添加双引号；光标已在字符串内时只插入原始 ID，避免重复引号。

## 数据组件编辑器

点击“UI与窗口 → 视图 → 数据组件编辑器”打开可视化编辑器。它与其他工具窗口一样可以拖动、调整大小、吸附到左侧/右侧/底部，并会保存显示状态和停靠布局。

- 当代码光标位于 `MC.Item.give`、`MC.Item.setSlot`、`MC.Container.setSlot` 等 API 的 `components` 参数时，按 `Ctrl+I` 会优先打开此编辑器，并选中当前完整参数；点击“插入组件”会精确替换该参数。即使打开窗口后移动过代码光标，只要源码未修改，仍会替换最初识别的位置
- 编辑器获得键盘焦点时按 `Ctrl+Enter`，会先保存当前树节点并校验，再执行“插入组件”。如果编辑器由 `Ctrl+I` 打开，成功插入后自动关闭；从菜单打开的窗口会保留
- 顶部可在“物品 / 方块 / 实体”间切换。三页的数据类型不同：物品页是物品堆叠数据组件；方块页从所选方块的实际状态定义读取 `states`（如 `facing`、`half`），有方块实体时还可填写 `blockEntityData`；实体页显示生命值、穿戴装备、发光等实体状态，以及该实体自身支持的数据组件。方块不是方块物品，实体也不是刷怪蛋
- 方块实体数据树会按方块类型显示字段：箱子、熔炉等容器有 `Items`，每项含从 0 开始的 `Slot`、物品 `id`、`count` 和可选物品 `components`；熔炉另有 `cooking_time_spent`、`cooking_total_time`、`lit_time_remaining`、`lit_total_time`；普通和悬挂告示牌有正反两面的 `front_text` / `back_text`，每面 `messages` 必须是四行文本组件，还可设置染料颜色、发光文字和 `is_waxed`。其他 Mod 的方块实体还会读取其默认存储字段，并允许在树中添加自定义字段
- 左侧搜索支持资源 ID、中文名和拼音首字母；右侧组件搜索同样支持中文和首拼
- 物品组件数据由服务端当前注册表读取，包含其他 Mod 注册且拥有持久化 Codec 的组件。方块状态从该方块的状态定义读取，因此其他 Mod 的方块属性也会显示；实体数据组件从实体类型和实体实例读取。装备槽位中的物品仍可单独编辑物品组件
- 三页的“插入配置”分别生成物品组件补丁、方块配置或实体配置，可以作为对应 `MC.Item.*`、`MC.Block.set`、`MC.Entity.spawn` 的参数。方块配置示例：`{states={facing="north"}}`；实体配置示例：`{health=10,equipment={mainhand={id="minecraft:iron_sword",count=1}}}`
- 选中目标后，主区域直接显示完整组件树，不再分成“上方组件列表＋下方编辑区”。点击三角或对象行展开；默认组件、常用组件和高级组件均有标记。“高级”表示已注册，但不保证会对当前目标产生效果
- 灰色组件和字段是可添加的预览，不会仅因展开就写入导出结果。点击右侧“＋”添加组件；已有覆盖点击“✓ 撤销”恢复原始默认行为。撤销覆盖不等于移除物品本来的默认组件
- 展开组件后可直接看到已知的可选字段及中文用途名称。点击字段编辑，类型由模板确定，无需手写 JSON 键；布尔字段单击切换，固定枚举（例如稀有度、装备槽位）提供候选选项，资源 ID 自动提供对应注册表搜索
- 列表展开后有“＋ 添加…”行：新增容器槽位会自动生成槽位和物品堆字段，并分配未使用的槽位；新增药水效果会带上效果 ID、时长等字段；物品内部 `components` 可以继续添加、嵌套编辑组件。`Insert` 新增，`Delete` 删除当前覆盖字段/条目
- “＋字段”打开可搜索的字段选择器，选中后自动使用正确类型和初始结构。`custom_data` 等开放对象还可添加任意自定义键，自行选择字符串、整数、小数、布尔、对象或列表；具有 ID 语义的键仍会自动提供 ID 搜索
- 切换食用/死亡保护效果的 `type` 时，会重建该效果的专属字段（例如“施加效果”需要效果对象，“移除效果”需要效果 ID 列表）。此操作会替换原效果的参数。编辑方块的 `block_state` 时，字段与可选值来自该方块的真实状态定义
- 常用组件使用当前游戏版本的字段模板；其他组件会从实际物品默认值和 Mod 提供的字段提示生成树。没有默认值或字段说明的模组自定义结构无法完整自动推断，可用“自定义字段”继续编辑；最终格式始终由服务端 Codec 校验
- 编辑 `minecraft:enchantments` 或 `minecraft:stored_enchantments` 时，新增子项会打开附魔 ID 搜索，并预填整数等级 `1`；附魔 ID、等级均可修改，也可以填写其他 Mod 注册的附魔 ID。嵌套物品内部的附魔同样支持。最终可用性以当前服务器注册表和组件 Codec 校验结果为准
- 树节点输入框会结合组件类型、键名和完整树路径识别资源 ID。编辑器先枚举当前服务器的全部注册表类型，再按需分页读取所选类型中的全部 ID；例如 `minecraft:timeline` 中的 `minecraft:day` 是时间轴 ID（`minecraft:world_clock` 则是世界时钟定义）、`minecraft:item` 中的 `minecraft:apple` 是物品 ID、`minecraft:mob_effect` 中的 `minecraft:dolphins_grace` 是状态效果 ID。其他 Mod 的注册表和命名空间也会自动出现
- 自动识别不到时点击节点窗口里的“ID类型”，可按完整 ID、注册表名称、命名空间、中文或拼音首字母筛选任意注册表。条目列表同样支持中文和首拼搜索，常用条目会显示用途注释
- 物品堆的两种形式都能识别：例如 `use_remainder = "minecraft:glass_bottle"`，以及 `{id="minecraft:glass_bottle", count=1}`。收纳袋、容器和弩弹药中的简写 ID 也有搜索选项。组件多层嵌套时，按最内层 `components` 的实际组件识别，避免把内部的效果或附魔 ID 误当成外层物品 ID
- 树中的字符串节点单击即可编辑或搜索。弹窗独立于停靠区域的宽度，窄编辑窗口也能显示候选列表；点击“值”输入搜索内容，`Ctrl+A` 清空当前搜索。没有匹配时会显示提示，可换关键词或手动选择 ID 类型
- 目录也包含当前服务端的配方、进度、已加载维度、可重载注册表（例如战利品表）。对于支持标签的字段，输入 `#` 可切换搜索当前类型的全部标签，例如方块条件中的 `#minecraft:logs`；只接受单个物品/实体 ID 的字段不能使用标签，导出仍由服务端校验
- 其他 Mod 可以通过公开的 `McLuaIdeRegistryApi` 添加注册表类型说明、条目名称/用途翻译，以及自己数据组件字段的 ID 类型提示；详见发行包中的 `docs/extensions/third-party-api.zh_cn.md`
- ID 候选支持完整 ID、路径、命名空间、本地化名称、中文和拼音首字母搜索。使用 `↑` / `↓` 循环选择，按 `Tab` 或 `Enter` 填入，也可以直接单击候选；选择后再次按 `Enter` 保存树节点
- 树形编辑器右上角的“源码”仍支持粘贴或修改完整 JSON，确认后会重新生成整棵树，适合复制已有复杂组件或编辑特别大的结构
- “全部组件 / 建议组件”可在完整注册表与当前选项的常用组件间切换
- “插入组件”会把 Lua 组件表插入当前光标；“复制物品堆”复制包含 `id`、`count` 和 `components` 的完整 Lua 表；“复制 JSON”复制精确组件补丁
- 插入或复制之前会把结果发给服务端的 Minecraft 数据组件编解码器校验。字段、类型或资源 ID 无效时不会导出，并显示服务端返回的具体错误

### 掉落物实体 minecraft:item

选择“实体 → minecraft:item”时，编辑的是地上的掉落物，而不是物品或刷怪蛋。编辑器从服务端创建的未入世界实体读取 NBT 默认值，另补充默认未保存的可选归属字段；这不是读取世界中某个已有掉落物的当前状态。

- `Item`（掉落物品堆）：展开后选择物品 ID、数量和嵌套 `components`；物品 ID 支持搜索，物品的附魔、名称等只放在这里。
- `Health`：掉落物生命值，整数 0～32767；区别于生物的 `health`。
- `Age`：存在的游戏刻数，范围 -32768～32767。通常 6000 刻后消失，-32768 为不限寿命。
- `PickupDelay`：拾取延迟游戏刻数，范围 0～32767；0 表示立即拾取，32767 表示永不拾取。
- `Owner`：拾取归属 UUID，遵循原版拾取规则；`Thrower`：投掷来源实体 UUID。二者选填，不添加时沿用默认值。

实体生成的第六参数还支持 Fabric 模组的持久化附加数据（与数据组件不是同一个注册表）：

```lua
local entityUuid = MC.Entity.spawn("touhou_little_maid:maid", -49, 101, -3, "xiaomiaoica:bedwars", {
    ["minecraft:custom_name"] = "商人",
    health = 20, invulnerable = true, noGravity = true,
    equipment = {
        head = {id = "minecraft:cake", count = 1},
        mainhand = {id = "minecraft:firework_rocket", count = 1}
    },
    ["fabric:attachments"] = {
        ["touhou_little_maid:profile"] = {model_id = "geckolib:zhiban_hanfu"}
    }
})
```

需要服务端安装提供相应实体与附件的模组。附件按该模组的持久化 Codec 解析，生成实体加入世界前通过 Fabric API 设置；无需执行 `/data` 命令，也不重新加载整个实体 NBT。仅设置指定附件，不替换坐标、UUID、装备或其他附件；附件值按完整持久化值解析，若要保留该附件自身的其他子字段，请一并传入。未知附件、非持久化附件和错误值都会明确报错，不静默忽略。客户端是否能显示特定模型及是否需要安装对应模组，由模型所属模组决定。本字段不支持任意原始实体 NBT。每次最多 128 个附件，序列化输入最多 262144 字符。

这些字段区分大小写；插入、复制时由服务端校验，生成的配置可直接传给 `MC.Entity.spawn`：

```lua
local dropped = MC.Entity.spawn("minecraft:item", 0, 65, 0, nil, {
    Item = {
        id = "minecraft:diamond",
        count = 3,
        components = { ["minecraft:custom_name"] = { text = "测试钻石" } }
    },
    Health = 5,
    Age = -32768,
    PickupDelay = 0,
    noGravity = true
})
print("掉落物 UUID", dropped)
```

## 文本 JSON 编辑器

点击“UI与窗口 → 视图 → 文本 JSON 编辑器”打开生成器；在聊天、标题、队伍名称等支持 `textOrJson` / `titleOrJson` 等文本组件参数的位置按 `Ctrl+I` 也会直接打开，并在插入时替换该参数。窗口可以移动、缩放、吸附并自动保存布局。左侧分段列表同时显示多个片段；点击可选择，上方可新增或复制，下方可上移、下移、删除，滚轮可浏览更长的列表。底部预览中点击一段也可选中它。

- “内容”支持普通文字、积分榜分数（计分对象和目标）、目标选择器（及分隔文字）、翻译键、按键名称和 **Lua 变量**。Lua 变量可填写 `name`、`event.playerName`、`items[1].count` 等变量或字段表达式；在脚本运行到使用该文本的位置时读取，以 `tostring` 转换为文字，通过 `..` 与其他分段拼接。预览只显示变量名，不读取或执行代码。分数和选择器的实际值由服务器在使用组件时解析，因此编辑器预览会显示占位符
- “样式”支持六位十六进制颜色（`#RRGGBB`）、字体资源 ID、原版 16 色快速色板，以及粗体、斜体、下划线、删除线和乱码效果；每段的样式独立。这里的文字颜色与“颜色”页的第一个颜色 ID 双向同步
- “交互”支持悬浮显示文字、物品、实体，以及点击执行/填入命令、打开网址、复制文字、翻页、打开对话框。悬浮文字还可输入完整的文本组件 JSON。预览只展示交互说明，不会执行点击动作
- “颜色”页可输入逗号分隔的十六进制颜色。关闭逐字渐变时，以第一个颜色 ID 作为整段的颜色；开启后需要 2～32 个颜色，普通文字按可见字符逐字渐变，多色标依次过渡。点击“插入颜色”可打开 RGB 调色板，拖动色相条及颜色区域后插入；关闭渐变时会替换第一个颜色，开启时会新增色标。粗体、字体、悬浮和点击事件会保留到每个渐变字符。动态分数/选择器等内容不能逐字渐变
- “插入 JSON 字符串”会生成已正确转义的 Lua 字符串，可直接放进 `MC.Chat.message`、`MC.Title.show`、`MC.Team.prefix` 等参数
- “复制 JSON”复制原始 Minecraft 文本组件 JSON，便于在命令、配置或其他 Mod 中复用。只要有“Lua 变量”分段，按钮就变为“插入 Lua 拼接”／“复制 Lua 拼接”，生成完整的 Lua 表达式而非原始 JSON；直接放进 Lua 文本参数即可，无需额外加引号。变量中的引号、反斜杠和控制字符会自动进行 JSON 转义，不会破坏其他分段或插入额外 JSON 字段。变量段保留样式、颜色、悬浮和点击功能，但与其他动态内容一样不支持逐字渐变。编辑器只检查表达式语法；变量必须在插入位置的作用域内已定义，未定义字段或运算错误仍会在运行时报告。每个变量表达式在生成文本时求值一次，`nil` 会显示为 `nil`，数字和布尔值也转换成文字；文本生成后不会自动跟随变量后续变化
- 悬浮和点击事件能否触发取决于文本出现的位置；聊天消息等可交互位置支持，标题等非交互界面通常只显示文字。点击“执行命令”由点击该文字的玩家执行，不会自动获得服务器管理员权限

```lua
local styled = "{\"text\":\"任务完成\",\"color\":\"#55FFFF\",\"font\":\"minecraft:default\",\"bold\":true,\"underlined\":true}"
MC.Title.show(uuid, styled)
```

例如，把“积分：”文字片段、一个计分板分数片段和带渐变及点击命令的文字片段接在一起，可以生成一个含 `extra` 的 Minecraft 文本组件；其中点击命令会使用当前版本的 `click_event: {action: "run_command", command: "..."}` 格式。

Lua 变量的例子：在脚本中先定义 `local playerName = "Alex"`、`local coins = 125`，再在编辑器中依次添加“普通文字：玩家：”“Lua 变量：playerName”“普通文字：，金币：”“Lua 变量：coins”，点击“插入 Lua 拼接”放进 `MC.Chat.broadcast(...)` 参数。执行时显示“玩家：Alex，金币：125”，各段仍可以独立设置颜色和交互。一个变量段也可填写 `playerName .. "：" .. coins` 这样的表达式。

## 自动补全

输入关键字或标准函数的开头，光标附近会出现候选框。例如输入 `pri`，然后按 `Tab`，会补全为 `print`。输入 `string.`、`table.`、`math.` 可以补全常用库函数。补全 `MC.*` 函数时会自动生成括号并把光标放入参数位置；括号内会根据当前参数显示 ID、UUID、匹配类型的变量及可选值候选。空参数也可以直接选择；用上下键切换，按 `Tab` 或鼠标点击填入。`Ctrl+I` 仍可打开保留全部分类的插入窗口，并自动选择参数对应类型。

例如 `MC.Item.give(uuid, , )` 的第二参数会列出物品 ID 与字符串变量，第三参数会列出整数变量；`MC.Block.set(0, 64, 0, )` 列出方块 ID；`MC.Player.setGameMode(uuid, )` 可选 `creative` 等模式名称。ID 支持命名空间、中文名称和首拼筛选，也包含服务器/资源包中已经被目录收录的相关 ID。未带引号时补全 ID 会自动添加 Lua 引号，在引号内补全只替换内容；变量只插入变量名。鼠标移到候选上可查看参数与变量类型说明。候选按作用域筛选，局部变量不会泄漏到作用域外；暂时无法静态推断的变量仍保留并标为“类型待确认”，不会为了补全执行脚本。第三方 API 声明的参数类型也适用。

维度参数同样支持动态 ID 补全。例如 `MC.Player.teleport(uuid, 0, 80, 0, )`、`MC.Block.get(0, 64, 0, )` 或 `MC.World.gameTime()` 的维度参数位置，会读取当前服务器的维度目录（包括模组和数据包维度），支持 ID、中文名称和首拼筛选。`↑` / `↓` 选择后按 `Tab` 填入；未加引号时自动添加引号，已有引号时只替换字符串。可选维度参数仍可填 `nil`，其含义以对应函数文档为准。该位置按 `Ctrl+I` 会自动切换到维度 ID 页面。第三方 API 的字符串参数命名为 `dimension` 或 `dimensionId` 时也可使用此补全。

## 实时语法与参数检查

停止输入约 250 毫秒后会自动编译当前文本，但不会执行它。

- `✓ 检查通过`：Lua 语法正确，并且没有发现可静态判断的 MC API 参数错误
- `● 正在检查…`：正在检查 Lua 语法、API 名称、参数数量和参数类型
- `✗ n 个问题`：下方诊断栏会用中文显示第一个问题的行列位置、原因和剩余问题数量

编辑器会检查 `MC.*` 方法是否存在、大小写是否正确、必填参数是否缺失、参数是否过多，并检查可以静态确定的字符串、数字、整数、布尔值和回调函数类型。字符串常量还会检查 UUID、`namespace:path` 资源 ID、游戏模式、天气、难度、事件名称、网络方法和 URL 等格式。错误只标红对应的调用、参数或符号，自动换行和同一行重复字段不会改变错误位置。

变量或函数返回值的实际类型有时只有运行后才能确定。检查器无法确定时不会猜测或阻止运行，服务端 API 仍会在执行时进行最终校验。

## Minecraft API：`MC`

每个脚本都可以直接使用全局表 `MC`。脚本源码通过受限协议提交给当前 Minecraft 服务端，随后由服务端 Lua 沙箱执行；所有方块、世界、玩家、容器和背包操作都在服务端线程读取或修改，不使用客户端缓存数据。单人世界同样走这套协议，只是客户端与内置服务器位于同一进程。

`MC.apiVersion()` 返回 MC Lua IDE 的模组版本字符串，例如 `"1.0.12"`。玩家相关函数不再隐式使用打开 IDE 的玩家，而是显式接收玩家 UUID。命名空间推荐使用首字母大写形式，例如 `MC.Player.health(uuid)`；`MC.player`、`MC.item` 等小写别名也可以使用。资源 ID 省略命名空间时默认使用 `minecraft:`。

输入 `MC.` 或 `MC.Block.` 后，候选项会以 `方法名 - 中文简介` 显示。用 `↑`、`↓` 选择候选，按 `Tab` 会补全可执行的方法名和调用括号，不会把中文说明写进代码。光标进入支持运行时选择的参数后再次按 `Tab`，可直接选择 ID 或 UUID。把鼠标悬浮在候选项或编辑器里的完整 `MC.*` 方法名上，可以按“作用、返回、参数1、参数2……”的固定格式查看详情；无参数方法会显示“参数：无”，受限方法还会显示单人世界限制。`MC.apiVersion()` 返回 MC Lua IDE 的模组版本。

等待可用 `MC.sleep(milliseconds)`，单位是毫秒，例如 `print("开始"); MC.sleep(1000); print("一秒后")`。它只暂停当前主流程或当前事件回调，其他事件及同一监听的后续触发仍能执行；不暂停游戏主线程。单次可等待 0–3600000 毫秒，停止脚本会取消全部等待。等待时间仍计入服务器设置的脚本最长运行时间。

其他 Fabric 模组可以扩展 `MC.*` 或注册自己的顶级大类；管理员进入 IDE 后会自动同步它们的接口和文档。初学者可先从下方的玩家、物品、方块 API 学起；模组作者的 Java 接入方式放在本手册末尾的“第三方模组扩展开发”。

### 获取玩家 UUID

- `MC.Player.list()`：返回全部在线服务端玩家，每项包含 `{uuid, name, dimension, x, y, z}`
- `MC.Player.uuid(name)`：按在线玩家名称查找 UUID；未找到返回 `nil`

```lua
local players = MC.Player.list()
if #players == 0 then
    error("当前没有在线玩家")
end

local uuid = players[1].uuid
print("目标玩家", players[1].name, uuid)
```

### 方块：`MC.Block`

- `MC.Block.get(x, y, z, dimension?)`：读取当前位置真实方块的 `states`、`hasBlockEntity`、`blockEntityData/blockEntityDataJson`，包括箱子内容、熔炉进度、告示牌文字等；没有方块实体时数据为空对象。保留物品形式的 `itemComponents/itemComponentsJson`，两者不是同一种数据
- `MC.Block.id(x, y, z, dimension)`：只返回方块资源 ID
- `MC.Block.isAir(x, y, z, dimension)`：当前位置为空气时返回 `true`
- `MC.Block.set(x, y, z, id, dimension?, components?)`：在服务端放置方块并返回是否变化。第六参数可用方块配置表：`states` 设置所选方块真正支持的状态属性；有方块实体时可用 `blockEntityData` 设置其自定义存储数据；`itemComponents` 可选，用于把方块物品组件传给方块实体。旧式直接传物品组件表仍兼容
- `MC.Block.breakAt(x, y, z, drops, dimension)`：在服务端破坏方块；`drops` 默认为 `true`
- `MC.Block.exists(id)`、`MC.Block.name(id)`：检查注册 ID、读取显示名称
- `MC.Block.fill(...)`：使用一个方块填充长方体区域
- `MC.Block.replace(...)`：替换区域内指定类型的方块
- `MC.Block.clone(...)`：复制方块区域到新位置

所有 `dimension` 参数都可省略，默认是 `minecraft:overworld`。读取未加载区块会返回 `nil, 原因` 并显示黄色警告，脚本继续运行，不会在后台意外加载大量区块。

```lua
local uuid = MC.Player.list()[1].uuid
local pos = MC.Player.position(uuid)
local x = math.floor(pos.x)
local y = math.floor(pos.y) - 1
local z = math.floor(pos.z)

local block = MC.Block.get(x, y, z, pos.dimension)
print("脚下方块", block.id, block.name)

MC.Block.set(x + 2, y, z, "gold_block", pos.dimension)
MC.Block.set(x + 3, y, z, "minecraft:chest", pos.dimension, {
    ["minecraft:custom_name"] = {text = "脚本奖励箱", color = "gold"}
})
MC.Block.set(x + 4, y, z, "minecraft:oak_stairs", pos.dimension, {
    states = {facing = "north", half = "top"}
})
MC.Block.set(x + 5, y, z, "minecraft:chest", pos.dimension, {
    blockEntityData = {Items = {{Slot = 0, id = "minecraft:diamond", count = 2}}}
})
MC.Block.set(x + 6, y, z, "minecraft:oak_sign", pos.dimension, {
    blockEntityData = {front_text = {messages = {
        {text = "第一行"}, {text = "第二行"}, {text = ""}, {text = ""}
    }}}
})
MC.Block.breakAt(x + 2, y, z, true, pos.dimension)
```

物品堆组件只属于“物品形式”。普通方块状态不是物品堆组件。`MC.Block.get` 会返回当前 `states`；`MC.Block.set` 的 `states` 可以用于普通方块，`blockEntityData` / `itemComponents` 仅用于有方块实体的方块。大范围 `fill/replace/clone` 操作的是方块状态，因此不接收物品堆组件；其中容器里的物品请用 `MC.Container.setSlot` 写入。

### 物品：`MC.Item`

- `MC.Item.held(uuid)`：读取指定在线玩家的主手物品；结果包含 `id, name, count, empty, maxStack, damage, maxDamage, components, componentsJson`
- `MC.Item.count(uuid, id, components?)`：统计指定玩家背包中的物品；只检查传入的组件条件，其他组件不影响匹配
- `MC.Item.give(uuid, id, count?, components?)`：由服务端给予指定玩家带数据组件的物品并返回数量；`count` 默认为 1，范围 1–999。背包已满时，剩余物品会掉落在该玩家身边
- `MC.Item.validate(id, count?, components?)`：只校验并规范化物品堆，不修改玩家或世界；成功时返回完整物品堆信息，组件错误时立即报错
- `MC.Item.exists(id)`、`MC.Item.name(id)`、`MC.Item.maxStack(id)`：读取物品注册和基础信息
- `MC.Item.clear(uuid, id?, count?, components?)`：清除指定物品；只检查传入的组件条件，传组件时必须填写 ID；不传组件并省略 ID 时清空背包
- `MC.Item.replaceHeld(uuid, id, count?, components?)`：用带数据组件的物品替换玩家主手物品
- `MC.Item.inventory(uuid)`、`getSlot(uuid, slot)`：读取整个背包或单个槽位
- `MC.Item.setSlot(uuid, slot, itemId?, count?, components?)`、`clearSlot(...)`、`swapSlots(...)`：直接修改背包槽位
- `MC.Item.selectedSlot(uuid)`、`setSelectedSlot(...)`：读取或切换玩家的快捷栏选择
- `MC.Item.equipment(...)`、`setEquipment(uuid, equipmentSlot, itemId?, count?, components?)`：读取或修改主手、副手和装备槽

背包槽位使用从 `0` 开始的索引；快捷栏为 `0–8`。装备槽名称为 `mainhand`、`offhand`、`feet`、`legs`、`chest`、`head`、`body`、`saddle`。`setSlot` 或 `setEquipment` 的 `itemId` 传 `nil` 时会清空对应位置。

所有创建物品堆的方法统一使用 `components` 参数。它可以是 Lua 表，也可以是 JSON 对象字符串；最外层键是完整的数据组件 ID，值采用该组件在 Minecraft 数据编解码器中的结构。服务端会通过当前注册表校验组件，因此也支持其他 Mod 注册的数据组件；未知组件、字段错误或参数类型错误会直接返回中文错误。返回物品堆中的 `components` 是相对于该物品默认值的组件补丁，`componentsJson` 是不会混淆空对象和空数组的精确 JSON 形式，可直接传回任意 `components` 参数。

**筛选与创建的区别：** `MC.Item.count`、`MC.Item.clear` 和 `MC.Item.trade` 的费用 `costs[].components` 只检查你明确提供的组件，省略或 `{}` 都表示不限制组件；并不会要求实际物品只含这些组件。`minecraft:custom_data` 使用原版 NBT 子集匹配，可只写需要的字段，额外字段不影响，嵌套对象也支持；NBT 列表按原版子集语义匹配。其他指定组件按解码后的完整值比较，例如 lore 列表仍需相等，而不是任意包含一行。显式填写默认值（例如 max_stack_size=64）仍会检查该值；`["!minecraft:custom_name"]={}` 表示要求该组件不存在。筛选始终检查物品 ID，不会匹配其他物品。

例如实际知识之书同时带 `custom_data`、`item_model`、`item_name`、`lore` 和 `max_stack_size` 时，只凭自定义类型筛选即可：

```lua
local filter = {
    ["minecraft:custom_data"] = {new_type = "fire_charge"}
}
local count = MC.Item.count(event.playerUuid, "minecraft:knowledge_book", filter)
if count > 0 then
    MC.Item.clear(event.playerUuid, "minecraft:knowledge_book", 1, filter)
end
```

给予、设置槽位、商店奖励仍按填写的组件创建真实物品；物品堆合并和容器取放事件仍比较完整组件，避免把不同自定义物品混为同一堆。

需要移除物品默认自带的某个持久化组件时，可使用带 `!` 的键，例如 `["!minecraft:某组件"] = {}`。临时运行时组件没有可持久化 Codec，读取时不会放进 `components/componentsJson`，也不能跨脚本重新创建。

```lua
local uuid = MC.Player.list()[1].uuid
local held = MC.Item.held(uuid)
if held.empty then
    print("主手为空")
else
    print("主手", held.name, held.id, held.count)
end

local swordComponents = {
    ["minecraft:custom_name"] = {text = "管理员之剑", color = "gold"},
    ["minecraft:unbreakable"] = {}
}

MC.Item.give(uuid, "minecraft:diamond_sword", 1, swordComponents)
print("钻石总数", MC.Item.count(uuid, "diamond"))

MC.Item.setSlot(uuid, 0, "minecraft:diamond_sword", 1, swordComponents)
MC.Item.setSelectedSlot(uuid, 0)
MC.Item.setEquipment(uuid, "head", "minecraft:diamond_helmet", 1, {
    ["minecraft:custom_name"] = {text = "守卫头盔"}
})

-- 读取后无损复制组件到另一个物品堆
local stack = MC.Item.getSlot(uuid, 0)
MC.Item.give(uuid, stack.id, stack.count, stack.componentsJson)
```

#### 玩家背包物品的使用冷却

以下 API 均在服务端执行并通过原版协议同步冷却遮罩，普通玩家不需要安装本 Mod。需要允许服务器的物品／背包 API。

- `MC.Item.isOnCooldown(uuid, id, components?)`：背包中任一匹配物品正在冷却则返回 `true`，没有匹配物品返回 `false`。
- `MC.Item.startCooldown(uuid, id, ticks?, components?)`：立即开始／重新开始冷却。省略 ticks 时读取匹配物品的 `minecraft:use_cooldown.seconds`；没有该组件默认 20 Tick，同组匹配多种时长取最长值。
- `MC.Item.setCooldown(uuid, id, ticks, components?)`：将当前剩余冷却设为 ticks，从调用时重新计时，不是叠加时间；没有冷却时也会立即开始。不修改物品组件和以后使用时的默认冷却时间。
- `MC.Item.clearCooldown(uuid, id, components?)`：让当前冷却立即完成。`setCooldown(..., 0)`／`startCooldown(..., 0)` 效果相同。

时间单位是游戏 Tick，正常 20 Tick = 1 秒，允许整数 `0–1728000`（最多 24 游戏小时）；服务器暂停／降低 Tick 速率时不按现实时间推进。后三个方法返回本次处理的**不同冷却组数量**，没有匹配物品返回 `0`；同组多堆物品不重复计数。不消耗物品，不修改数量或组件。UUID 必须是在线玩家；离线返回 `nil, 原因` 并显示黄色警告；无效 ID、组件或时间参数仍报错。

筛选遍历玩家背包（含快捷栏、装备与副手），不包含打开的外部箱子或鼠标持物。components 支持 Lua 表／JSON 对象字符串，与 `Item.count` 相同：只检查给出的组件，`custom_data` 支持嵌套部分匹配；省略／`{}` 不限制组件。`startCooldown` 需要省略 ticks 又传筛选时，第三参数填写 `nil`。

**共享组限制：** 原版按 `minecraft:use_cooldown.cooldown_group` 记录冷却，没有指定组则使用物品 ID。同组物品会一起冷却／恢复，即使其他物品未被组件筛选命中；筛选不能把原版本就同组的物品拆成独立冷却。需要独立冷却的自定义物品，应在创建时设置不同 `cooldown_group`。这是使用物品冷却，不是近战攻击蓄力，也不是阻止 Lua 事件回调；自定义技能应在回调中先判断冷却再执行。

```lua
local player = MC.Player.list()[1]
if player then
    local uuid = player.uuid
    local filter = {["minecraft:custom_data"] = {new_type = "fire_charge"}}
    -- 背包中已有此类物品时才会操作；100 Tick 正常为 5 秒
    if not MC.Item.isOnCooldown(uuid, "minecraft:knowledge_book", filter) then
        MC.Item.startCooldown(uuid, "minecraft:knowledge_book", 100, filter)
    end
    -- 调整当前冷却为 2 秒，再立即完成（演示用）
    MC.Item.setCooldown(uuid, "minecraft:knowledge_book", 40, filter)
    MC.Item.clearCooldown(uuid, "minecraft:knowledge_book", filter)
end
```

### 玩家：`MC.Player`

- `MC.Player.name(uuid)`：返回指定在线玩家名称
- `MC.Player.position(uuid)`：返回 `{x, y, z, yaw, pitch, dimension}`
- `MC.Player.facing(uuid)`：返回 `{yaw, pitch, direction}`，水平角、垂直角和最接近的方向（north/south/east/west）
- `MC.Player.relativePosition(uuid, direction, plane, distance)`：计算玩家 `front`/`back`/`left`/`right` 方向 `distance` 格处的坐标；`plane` 为 `horizontal`（只按水平朝向）、`vertical`（只按俯仰，front/back 上下移动）或 `both`（完整视线方向）；返回 `{x, y, z, blockX, blockY, blockZ, dimension}`
- `MC.Player.lookDirection(uuid)`：返回长度为 1 的视线方向向量 `{x, y, z}`
- `MC.Player.lookingAt(uuid, infinite?)`：返回准星指向的方块表面的精确坐标 `{x, y, z, blockX, blockY, blockZ, face, blockId, distance, dimension}`，没有命中时为 `nil`；`infinite` 为 `true` 时最远检测 1024 格
- `MC.Player.health(uuid)`：返回 `{current, max}`
- `MC.Player.gameMode(uuid)`：返回 `survival`、`creative`、`adventure` 或 `spectator`
- `MC.Player.teleport(uuid, x, y, z, dimension)`：由服务端传送玩家；省略维度时留在原维度
- `MC.Player.setHealth(uuid, value)`：设置玩家生命值并限制在有效范围
- `MC.Player.setGameMode(uuid, mode)`：设置指定玩家的游戏模式
- `MC.Player.online(uuid)`：检查 UUID 是否在线
- `MC.Player.food(uuid)`、`MC.Player.setFood(...)`：读取或修改饥饿值、饱和度
- `MC.Player.experience(uuid)`、`addExperience(...)`、`setExperience(...)`：控制经验点或经验等级
- `MC.Player.heal(uuid, amount?)`、`damage(...)`、`kill(uuid)`：治疗、伤害或杀死玩家
- `MC.Player.kick(uuid, reason?)`：从服务器断开玩家
- `MC.Player.setSpawn(...)`、`setRotation(...)`：设置个人重生点或视角
- `MC.Player.openBlock(uuid, x, y, z, dimension?)`：打开指定坐标方块的真实原版菜单，例如箱子、熔炉、发射器
- `MC.Player.openCrafting(uuid, title?)`：不依赖方块，直接打开工作台
- `MC.Player.openEnderChest(uuid, title?)`：直接打开该玩家自己的末影箱
- `openAnvil`、`openEnchanting`、`openGrindstone`、`openLoom`、`openCartography`、`openStonecutter`、`openSmithing`：直接打开对应工作站
- `MC.Player.menu(uuid)`、`closeMenu(uuid)`：查询或关闭当前打开的菜单
- `MC.Player.abilities(uuid)`、`setFlying(...)`、`setSpeeds(...)`：读取和修改飞行能力与移动速度
- `MC.Player.absorption(uuid)`、`setAbsorption(...)`：读取和设置金色伤害吸收生命值

```lua
local uuid = MC.Player.list()[1].uuid
local p = MC.Player.position(uuid)
local hp = MC.Player.health(uuid)
print(MC.Player.name(uuid), p.x, p.y, p.z, p.dimension)
print("生命", hp.current, "/", hp.max)

MC.Player.teleport(uuid, p.x, p.y + 5, p.z)
MC.Player.setGameMode(uuid, "creative")

-- 这些菜单由服务端直接打开，不要求附近真的放置对应工作站
MC.Player.openCrafting(uuid, "脚本工作台")
-- MC.Player.openEnderChest(uuid, "个人末影箱")
```

直接工作站函数创建的是临时菜单，关闭后菜单输入槽会按原版规则归还或处理物品。`openBlock` 打开的是真实方块菜单，仍遵守原版有效距离和维度限制，因此目标玩家应位于该方块附近且与方块处于相同维度。

### 通过 ID 获取指定语言名称

```lua
local name, actualLanguage = MC.Item.name("minecraft:diamond", "zh_cn")
print(name, actualLanguage) -- 钻石    zh_cn
print(MC.Block.name("minecraft:stone", "en_us")) -- Stone    en_us
print(MC.Entity.name("minecraft:pig", "zh_cn")) -- 猪    zh_cn
print(MC.Enchantment.name("minecraft:sharpness", "zh_cn")) -- 锋利    zh_cn
```

- `MC.Item.name(itemId, language?)`：物品的默认显示名，支持其他服务端模组物品，不读取某个物品堆的自定义名称。
- `MC.Block.name(blockId, language?)`：方块类型名称，不需要世界坐标。
- `MC.Entity.name(entityType, language?)`：实体**类型 ID** 的名称，如 `minecraft:pig`，不是某个实体 UUID；不会生成实体。
- `MC.Enchantment.name(enchantmentId, language?)`：当前服务器附魔注册表中的描述名称，包含数据包和模组附魔；不附带等级。

语言代码如 `zh_cn`（简体中文）、`zh_tw`（繁体中文）、`en_us`（美式英文）、`en_gb`、`ja_jp`（日文）、`ko_kr`、`de_de`、`fr_fr`；`ZH-CN` 会规范化成 `zh_cn`。语言参数支持 Tab 补全常用值，仍允许输入其他游戏支持的语言。ID 参数支持 Ctrl+I / Tab 自动切换对应的物品／方块／实体／附魔分类。**不填 language 时保持默认名称行为，兼容原有 Item/Block.name(id)。**

明确指定语言时返回两个值：第一个是名称；第二个是实际语言代码。目标词条缺失则尝试 `en_us`，第二值为 `en_us`，不会把英文冒充成中文；若连英文也没有，保留文本组件的 fallback 或翻译键，并返回 `untranslated`。数据包附魔若描述直接写成固定文字，返回原文字和 `literal`，不能凭空翻译没有语言键的文本。附魔描述中的嵌套翻译、参数占位和兄弟文本都会一起处理。

查询在服务端执行，不需要普通玩家安装本 Mod，也不要求开启强制客户端模式。**不会修改全局语言、玩家语言设置或客户端当前资源包。** 默认读取当前版本原版语言与服务端已安装 Mod 的 `assets/*/lang/<language>.json`，不会猜测翻译键（使用物品／方块／实体实际描述键和附魔描述组件）。仅在客户端安装的 Mod、玩家自己使用的资源包翻译，独立服务器无法自动读取。

独立服务器通常只有内置英文。其他原版语言首次查询时，会从 Mojang 官方 `piston-meta.mojang.com` 获取当前版本资源索引，再从 `resources.download.minecraft.net` 下载并校验 SHA-1，缓存在 `config/mc_lua_ide/language-cache/<游戏版本>/`；以后查询复用缓存，最多保留 16 种内存词典。网络等待只发生在 Lua 工作线程，不占用服务器主线程，但首次调用可能较慢。不能联网时，可提前准备对应语言文件。

离线使用或覆盖译名：在**服务端**创建 `config/mc_lua_ide/lang/zh_cn.json`（其他语言同理），格式与 Minecraft 语言 JSON 一致，例如：

```json
{
  "item.minecraft.diamond": "钻石",
  "block.minecraft.stone": "石头",
  "entity.minecraft.pig": "猪",
  "enchantment.minecraft.sharpness": "锋利"
}
```

存在本地指定语言文件时不会下载该语言，它应包含你需要的译名；遗漏词条仍回退英文。此文件优先级高于 Mod 语言，修改后重载数据包或重启服务器即可清除内存缓存。语言文件均限制 8 MiB；只允许固定官方 HTTPS 地址，Lua 不能用 language 参数指定文件路径或任意 URL。加载失败且没有可用语言词条时，返回 `nil, 原因` 并显示黄色警告，脚本继续；无效资源 ID、参数类型或语言代码格式仍报错。网络失败有短暂重试冷却，避免每个物品都重复发起请求。

### 无坐标箱子 UI、鼠标持物与商店

这些 API 全部在服务端执行，普通玩家的原版客户端就能显示菜单，**不要求开启强制客户端模组模式**。

```lua
local player = MC.Player.list()[1]
if player then
    local items = {
        {id = "minecraft:diamond", count = 8,
            components = {["minecraft:custom_name"] = {text = "示例钻石", color = "aqua"}}},
        {id = "minecraft:apple", count = 16}
    }
    local id = MC.Player.openChest(player.uuid, "临时箱子", items, 3, false)
    if id then
        MC.Player.setMenuItem(player.uuid, 2, "minecraft:emerald", 4, nil, id)
        print(MC.Player.menuItem(player.uuid, 0, id).id)
        MC.Player.setCarried(player.uuid, "minecraft:stone", 2, nil, id)
        print(MC.Player.carried(player.uuid, id).count)
        MC.Player.setCarried(player.uuid, nil, nil, nil, id) -- 清空鼠标持物
    end
end
```

`openChest(uuid, title?, items?, rows?, readOnly?)` 返回菜单 ID 或 `nil`；title 支持普通文字、文本 JSON 字符串或文本组件表。箱子为 1～6 行，每行 9 格；省略行数按数组长度向上取整且至少 3 行。物品数组可稀疏填写（空格省略），索引 **1** 对应菜单格子 **0**，每项 `{id,count?,components?}`，也可简写为物品 ID 字符串。组件支持 Lua 表或 JSON 对象字符串，数量不能超过该组件组合的实际堆叠上限。所有物品校验通过后才打开新菜单，无效物品不会顶掉当前窗口。

这是一次性虚拟容器，不属于任何方块或世界位置；关闭会丢弃剩余展示内容，**不是持久仓库，勿把实际贵重物品放入暂存**。脚本停止或结束会关闭它创建的虚拟菜单。`readOnly=false` 时按原版箱子规则正常取放；`true` 时服务端禁止取放、Shift 快移、数字键交换、丢弃、创造复制、拖拽和双击归拢，也不会因关闭菜单把展示品转入背包。只读模式下仍有点击事件，可用于商店。

`menuItem(uuid, slotId, expectedContainerId?)`、`setMenuItem(uuid, slotId, itemId?, count?, components?, expectedContainerId?)` 操作玩家**当前打开的菜单**，支持虚拟箱子、真实箱子和下方背包。槽号是原版菜单编号，从 0 开始，**不等于玩家背包槽号**。`carried`／`setCarried` 操作鼠标上的物品，不是主手物品。设置时 ID 为 `nil`／`air` 或数量为 0 可清空。可传入打开时返回的 `expectedContainerId`，避免玩家关闭／切换窗口后，异步回调误改另一个菜单；ID 已变化时返回 `nil, 原因` 并提示黄色警告。API 主动改物品不伪装成玩家取放事件。

#### 玩家取放与拿到鼠标的监听

- `MC.Event.onContainerItemTaken(callback)`：非玩家背包的容器格子实际减少物品。
- `MC.Event.onContainerItemPlaced(callback)`：容器格子实际增加物品。
- `MC.Event.onContainerItemToCursor(callback)`：从容器格子实际拿到鼠标，包括右键分半、换持、双击从多个格子归拢。
- `MC.Event.onInventoryItemToCursor(callback)`：从玩家自己的背包格子实际拿到鼠标，支持普通背包和打开箱子时的下方背包。
- `MC.Event.onContainerClicked(callback)`：点击尝试，包括只读商店；`changed` 表示本次是否发生实际变化。`slotArea` 为 `container`／`inventory`／`outside`；`clickType` 为 `PICKUP`、`QUICK_MOVE`、`SWAP`、`THROW`、`QUICK_CRAFT`、`CLONE` 或 `PICKUP_ALL`。

```lua
MC.Event.onContainerItemTaken(function(event)
    print(event.playerUuid, event.containerType, event.slotId,
        event.itemId, event.count, event.itemComponents)
    -- 虚拟菜单没有坐标；真实方块容器提供方块坐标。
    print(event.x, event.y, event.z, event.dimension)
end)

MC.Event.onInventoryItemToCursor(function(event)
    print("背包槽位", event.containerSlotId, "菜单槽位", event.slotId,
        "拿到鼠标", event.itemId, event.count, event.cursorAfter.count)
end)
```

事件还包含 `playerName, containerId, virtual, readOnly, containerSlotId, button, item`；取放事件含 `clickedSlotId, before, after, cursorBefore, cursorAfter`。物品表包含 `id,count,empty,components`；`count` 是**本次变化量**，不是最终总量。交换不同物品分别产生取出与放入事件；Shift 快移／数字键直接进入背包而未进入鼠标时，不产生“拿到鼠标”事件。`containerSlotId` 是底层容器／玩家背包的槽号，从 0 开始。`x,y,z,dimension` 属于容器而不是玩家，虚拟箱子、背包、无坐标菜单和无法识别位置的第三方菜单都为 `nil`；玩家位置另在 `playerX,playerY,playerZ,playerDimension`。双箱使用组成容器的锚点坐标；实体容器使用实体当前位置。

这些是**实际玩家菜单点击后的异步通知**，不允许通过回调返回值取消已经完成的取放；不会把鼠标悬浮、无变化点击、API 写入或漏斗自动搬运当成玩家取放。制作不可拿走展示物品的商店，应使用 `readOnly=true` 加 `onContainerClicked`，而不是拿走后再删除鼠标物品。

#### 安全扣费与发货

`MC.Item.trade(uuid, costs, rewards, expectedContainerId?)` 在服务端同一操作中校验并模拟整笔交易，然后一次提交。只使用主背包与快捷栏 0～35，不动装备和副手。`costs/rewards` 是连续数组，每项 `{id,count?,components?}`，最多 54 项。费用不写 components 或写 `{}` 时只按物品 ID；填写组件时只检查指定组件，其中 custom_data 支持 NBT 子集。奖励按完整组件创建，只有 ID 和完整组件相同才合堆，并按真实堆叠上限拆分；余额或背包空间不足返回 `false, 原因`，完全不改背包、不掉落物品，避免只扣费没发货。过期菜单返回 `nil, 原因`；无效资源 ID／组件仍报错。

```lua
local ok, reason = MC.Item.trade(playerUuid,
    {{id = "minecraft:iron_ingot", count = 4}},
    {{id = "minecraft:white_wool", count = 16}}, containerId)
if not ok then MC.Chat.message(playerUuid, tostring(reason)) end
```

完整起床战争分页商店见 `examples/Bed_Wars/Shop/Main.lua`。将它放到服务端 `config/mc_lua_ide/scripts/Bed_Wars/Shop/Main.lua`，在启动脚本中 `local Shop = require("Bed_Wars/Shop/Main")`，然后 `Shop.open(playerUuid, page)` 为指定玩家打开指定页。仅加载模块不会自动打开所有玩家的窗口，也不会自动绑定村民或物品触发。`Open_Shop(playerUuid, page)` 是加载模块后可用的全局别名。

配置格式为 `Config_Shop_Item[页码][商品序号] = {物品ID, 数量, 物品组件, 货币ID, 价格}`，每页支持 1～45 个位置和底行的上一页／下一页／关闭按钮。可在模块顶部修改配置，也可在启动脚本加载模块前定义 `Config_Shop_Item`，或加载后 `Shop.configure(config)`。真正发放的物品使用配置中的组件，展示标题／价格说明不会混进奖励。改配置后重开页面生效，已打开页面按当时展示的价格成交。

```lua
local Shop = require("Bed_Wars/Shop/Main")
-- 可选：队伍名与物品颜色同名时，按玩家所在队伍替换 ID 中的 white。
-- Shop.Color({"red", "green", "blue", "yellow"})
Shop.open("目标玩家UUID", 1)
-- Shop.open("另一个玩家UUID", 2)
-- Shop.close("目标玩家UUID")
```

`Shop.Color(colors)` 为这个商店模块启用队伍配色。例如红队玩家会看到并买到 `minecraft:red_wool`，而不是配置中的 `minecraft:white_wool`。商品及货币 ID 路径中的所有 `white` 均替换为玩家所在队伍的颜色，命名空间、数量、组件、物品介绍和原配置不变；无匹配队伍时保留原 ID。颜色数组支持 16 种物品颜色，数组中的值也必须是实际队伍名。`Shop.Color(nil)` 或 `Shop.Color({})` 关闭。转换后的物品必须已注册；组件内自定义的 `minecraft:item_model` 不会自动改色。换队后点击旧页面会先刷新，再由玩家重新购买。

### 方块容器：`MC.Container`

- `MC.Container.info(x, y, z, dimension?)`：读取真实方块实体的类型、槽位数和是否为空

```lua
end

MC.Container.setSlot(x, y, z, 0, "minecraft:diamond_sword", 1, {
```

### 实体：`MC.Entity`

已有实体用运行中 UUID 定位；实体类型使用注册 ID。玩家也属于实体，但玩家专用操作优先使用 `MC.Player`。

- `get(uuid)`、`exists(uuid)`：读取或检查实体
- `list(dimension?)`、`nearby(x, y, z, radius, dimension?)`：列出维度或半径内实体
- `spawn(entityType, x, y, z, dimension?, components?)`：生成任意已注册实体，包括其他 Mod 实体；成功返回实体 UUID 字符串，可直接用于其他实体 API；加入世界失败返回 `false`，无效参数或无法生成的类型会报错
- `ride(uuid, vehicleUuid, force?)`：第一个 UUID 是乘客（上面的实体），第二个是坐骑（下面的实体）；玩家也可作为乘客。成功或已经骑在目标上返回 `true`，原版/模组拒绝骑乘返回 `false`。默认 `force=true` 跳过普通上车冷却和座位容量检查，传 `false` 保留这些检查；成功换乘会离开旧坐骑
- `dismount(uuid)`：让乘客下坐骑；实际离开返回 `true`，原本没在骑乘或模组拒绝返回 `false`
- `teleport(...)`、`velocity(...)`：传送实体或设置速度
- `kill(uuid)`：调用实体的原版 `kill` 逻辑。有生命实体可走正常死亡流程，非生命实体通常直接移除，并非所有 `kill` 都会触发 `onEntityDied`；`remove(uuid)`：不走死亡流程直接移除非玩家实体
- `setName(...)`、`setGlowing(...)`、`setInvulnerable(...)`、`setGravity(...)`、`fire(...)`：改变实体状态
- `equipment(uuid, equipmentSlot)`：读取已加载有生命实体（`LivingEntity`，包括玩家）的装备，返回值包含 `components/componentsJson`
- `components(uuid)`：读取指定已加载实体的整体快照，返回注册数据组件 `components/componentsJson`、真实实体序列化数据 `entityData/entityDataJson`、`equipment`、`glowing/invulnerable/noGravity`；有生命实体还包括 `health/maxHealth`。组件来自当前实体及其注册类型默认值，不是刷怪蛋。展示实体的显示内容、掉落物的 `Item` 等在 `entityData` 中；NBT 字段保留游戏本身的命名和结构
- `setEquipment(uuid, equipmentSlot, itemId?, count?, components?)`：给已加载有生命实体（`LivingEntity`，包括玩家）设置带数据组件的装备；`itemId` 为 `nil` 时清空
- `tags(uuid)`、`addTag(...)`、`removeTag(...)`：管理命令标签

`get`、`list`、`nearby` 返回项包含 `uuid, type, name, runtimeId, x, y, z, yaw, pitch, dimension, living, glowing, invulnerable, gravity`；有生命实体（`LivingEntity`，包括玩家）还包含 `health, maxHealth`。骑乘信息包括 `vehicleUuid`（当前坐骑 UUID，未骑乘时为 `nil`）和 `passengerUuids`（直接乘客的 UUID 数组，从 1 开始，不含更深层乘客）。

这里“实体”是所有 `Entity` 的统称；“有生命实体”专指 `LivingEntity`，包括玩家，而不是只指怪物或动物。装备、生命值、状态效果和属性 API 要求目标为有生命实体，具体装备槽、效果和属性仍受原版／模组规则约束，不代表掉落物、展示实体等也支持这些功能。

#### 读取物品、实体与方块的组件

以下均从服务端当前对象读取，普通玩家客户端无需安装模组；修改返回的 Lua 表不会直接修改世界。物品堆返回 `components`（组件补丁表）和 `componentsJson`（与 `components` 相同的表，不再是文本），不是该物品所有默认组件的展开。整体实体数据和方块实体数据是另外两种数据，不要与物品堆组件混用。

```lua
local player = MC.Player.list()[1]
if player then
    -- 玩家主手／副手／穿戴槽；背包第一个槽位从 0 开始。
    local offhand = MC.Item.equipment(player.uuid, "offhand")
    local firstSlot = MC.Item.getSlot(player.uuid, 0)
    if offhand then print("副手组件：", offhand.componentsJson) end
    if firstSlot then print("背包槽组件：", firstSlot.componentsJson) end

    -- 也可将运行中的僵尸等实体 UUID 传给 equipment/components。
    local mainhand = MC.Entity.equipment(player.uuid, "mainhand")
    if mainhand then print("实体主手组件：", mainhand.componentsJson) end
    local data, reason = MC.Entity.components(player.uuid)
    if data then
        print("实体组件：", data.componentsJson)
        print("实体 NBT：", data.entityDataJson)
        print("生命值：", data.health)
    else
        print("读取跳过：", reason)
    end

    local pos = MC.Player.position(player.uuid)
    if pos then
        local block = MC.Block.get(math.floor(pos.x), math.floor(pos.y) - 1,
            math.floor(pos.z), pos.dimension)
        if block then print("脚下方块实体数据：", block.blockEntityDataJson) end
    end
end
```

装备槽可用 `mainhand/offhand/head/chest/legs/feet/body/saddle`。空装备和背包槽仍返回物品堆表（`empty=true`、`count=0`、空组件）；只有真正不存在／未加载的实体、离线玩家或未加载区块会返回 `nil, 原因` 并显示黄色警告。无效槽位、格式和权限仍报错。

`MC.Entity.components` 的 `componentErrors` 记录第三方组件 getter／Codec 的读取错误，其他可读取组件仍保留；无 Codec 的临时组件不输出。`entityData` 是游戏实际保存的 NBT 转成的表，不包含无法序列化的纯运行时字段，NBT 数字和数组按 JSON 形式表示；需要保留对象／数组差别时使用对应 `Json` 字段。`equipment` 仅对有生命实体填充，每个槽位的值是完整物品堆表。整体快照不是 `spawn` 的可直接回传配置；不要把整个快照作为物品组件传入。

这些整体读取接口可能返回较多数据，应按需调用，不要每 Tick 反复读取全部实体。单个 `components`／`entityData`／`blockEntityData` 字段超过 262144 字符时报错；大容器优先使用 `MC.Container.getSlot`。`MC.Entity.components` 需要同时开启实体和物品 API 权限。

骑乘操作在服务端执行并使用原版同步，普通玩家无需安装客户端模组。乘客和坐骑必须都已加载且在同一维度；不能骑自己、形成循环，也不能把玩家作为坐骑。这些情况以及无效 UUID、实体不存在都会报错。`force` 不会绕过这些基本限制，也不保证任意模组实体都允许骑乘。骑乘关系属于世界状态，停止脚本不会自动让实体下坐骑。

```lua
-- 让小猪坐在牛上：第一个参数是乘客，第二个参数是坐骑。
local passengerUuid = MC.Entity.spawn("minecraft:pig", 0, 64, 0)
local vehicleUuid = MC.Entity.spawn("minecraft:cow", 0, 64, 0)
if passengerUuid and vehicleUuid then
    print("骑乘成功：", MC.Entity.ride(passengerUuid, vehicleUuid))
    print("当前坐骑：", MC.Entity.get(passengerUuid).vehicleUuid)
    -- 需要下坐骑时：MC.Entity.dismount(passengerUuid)
end
```

```lua
for _, entity in ipairs(MC.Entity.nearby(0, 64, 0, 20)) do
    print(entity.uuid, entity.type, entity.name)
end

local zombieUuid = MC.Entity.spawn("minecraft:zombie", 0, 64, 0, nil, {
  ["minecraft:custom_name"] = {text = "守卫", color = "gold"},
  health = 10,
  equipment = {mainhand = {id = "minecraft:iron_sword", count = 1}}
})

-- 三种展示实体可在「实体组件编辑器」中直接编辑专有字段，或传给 spawn。
MC.Entity.spawn("minecraft:item_display", 0, 65, 0, nil, {
    item = {id = "minecraft:diamond_sword", count = 1,
        components = {["minecraft:enchantment_glint_override"] = true}},
    item_display = "fixed", billboard = "center",
```

### 声音、粒子和屏幕标题

- `MC.Sound.play(soundId, x?, y?, z?, volume?, pitch?, category?, dimension?, playerUuid?, startSeconds?)`
- `MC.Sound.stop(playerUuid, soundId?, category?)`
- `MC.Particle.spawn(particleId, x, y, z, count?, spread?, speed?, force?, dimension?)`
- `MC.Title.show(uuid, textOrJson)`、`subtitle(...)`、`actionbar(...)`
- `MC.Title.times(uuid, fadeIn, stay, fadeOut)`、`clear(uuid)`、`reset(uuid)`

声音、粒子 ID 都来自运行时注册表，支持其他 Mod。`force=true` 会让粒子在更远距离可见，应避免一次生成过多粒子。

声音坐标 `x、y、z` 必须同时填数字，或同时填 `nil`（也可以全部省略）。三个坐标为 `nil` 时不使用固定世界坐标，让指定维度的全部玩家听到；`dimension` 为 `nil` 或省略时向**全服所有维度**广播，不受坐标和距离限制。要保留位置和距离衰减，必须同时提供坐标和明确的维度；声音 API 的 `nil` 维度不再默认为主世界，其他 API 的维度默认值不变。`playerUuid` 为 `nil` 或省略时不限制玩家，填写 UUID 时仍只播放给该在线玩家，并遵守指定维度筛选。

```lua
-- 全服广播：主世界、下界、末地和其他 Mod 维度的玩家都能听到
MC.Sound.play("minecraft:block.note_block.pling", nil, nil, nil)

-- 只广播给主世界的全部玩家，不受玩家所在坐标限制
MC.Sound.play("minecraft:block.note_block.pling", nil, nil, nil,
    1, 1, "master", "minecraft:overworld")

-- 普通位置声音：只让主世界中距离该坐标足够近的玩家听到
MC.Sound.play("minecraft:block.note_block.pling", 0, 64, 0,
    1, 1, "master", "minecraft:overworld")
```

从头广播使用原版的声音协议，普通玩家不需要安装本模组；声音跟随每个听者，玩家移动后不会因远离某个固定原点而变小。广播仍受音量、音调、游戏中的声音分类音量和静音设置影响，音量为 `0` 不会发声。

`startSeconds` 是音频文件的起播位置，单位秒，支持小数，并不是等待时间。省略或填 `0` 沿用原版声音协议，普通玩家无需安装本模组。**非零时间仅在强制客户端模式可用**：在 `Mod Menu → MC Lua IDE → 配置 → 服务器接入` 开启“要求玩家安装客户端模组”，然后重新启动脚本；目标玩家须安装兼容版本。原版声音包没有起播位置字段，不能通过新增纯服务端 API 让无模组客户端跳转。

```lua
local player = MC.Player.list()[1]
if player and MC.Client.available(player.uuid) then
    local p = MC.Player.position(player.uuid)
    -- 从唱片的第 30.5 秒开始，仍支持音量、音调、位置衰减与声音分类。
    MC.Sound.play("minecraft:music_disc.cat", p.x, p.y, p.z,
        1, 1, "record", p.dimension, player.uuid, 30.5)
    -- 需要停止时：MC.Sound.stop(player.uuid, "minecraft:music_disc.cat", "record")
end
```

起播声音使用客户端**当前已加载**的原版、其他 Mod 和资源包 `sounds.json` 声音事件；位置模式只播放给同维度且在声音范围内的玩家，广播模式按维度／UUID 筛选但不检查距离。时间达到或超过选中音频的总时长时不播放，不会退回从头播放。随机声音事件会定位本次选中的音频；音调改变播放速度，但起播秒数始终按音频原始时间计算。定位解码在后台完成，`true` 表示请求已提交，不代表声音资源一定存在或已解码；资源无效时客户端日志有错误说明。单个定位 OGG 限制 32 MiB，总占用限制 128 MiB，最多同时 32 个定位声音。声音仍受游戏设置中的分类音量控制，`MC.Sound.stop`、`/stopsound`、资源重载和断开连接都可停止它。

```lua
local uuid = MC.Player.list()[1].uuid
MC.Sound.play("minecraft:block.note_block.pling", 0, 64, 0)
MC.Particle.spawn("minecraft:flame", 0, 65, 0, 30, 1, 0.02, true)
MC.Title.times(uuid, 10, 60, 20)
MC.Title.show(uuid, {
    text = "任务完成",
    color = "#55FFFF",
    font = "minecraft:default",
    bold = true,
    underlined = true
})
```

### 计分板和队伍：`MC.Score`、`MC.Team`

- `MC.Score.create(objective, criteria?, displayNameOrJson?)`、`remove(objective)`
- `MC.Score.set(holder, objective, value)`、`add(holder, objective, amount)`、`reset(holder, objective?)`
- `MC.Score.display(slot, objective?)`：设置 `sidebar`、`list`、`below_name` 等显示位置
- `MC.Team.create(team, displayName?)`、`remove(team)`
- `MC.Team.join(team, holder)`：将任意实体加入队伍，自动退出原队伍；成功返回 `true`，重复加入同一队伍仍返回 `true`，队伍不存在时报错。
- `MC.Team.leave(holder)`：退出当前队伍；已退出返回 `true`，原本没有队伍返回 `false`。
- `MC.Team.has(team, holder)`：查询实体是否属于指定队伍，返回布尔值；队伍不存在或成员不属于该队伍时返回 `false`。
- `MC.Team.color(team, color)`、`friendlyFire(team, enabled)`、`prefix(team, text)`、`suffix(team, text)`

`holder` 可以是在线玩家 UUID，也可以是由字母、数字、点、下划线、加号、减号组成的虚拟计分名称。

`MC.Team` 的 `holder` 还支持所有非玩家实体的 UUID，包括生物、掉落物、载具、投射物和展示实体，也支持其他模组注册的实体。玩家 UUID 会自动转换成原版计分板使用的玩家名称；离线玩家请使用玩家名。非玩家实体未加载时仍可以使用 UUID 查询、加入或退出，不会强制加载区块。这些方法在服务端执行，普通玩家客户端无需安装模组。队伍颜色、友军伤害、前后缀等设置仍遵循原版规则，不会为原版不支持的实体额外添加效果。

```lua
MC.Team.create("red", "红队")
local pig = MC.Entity.spawn("minecraft:pig", 0, 64, 0)
MC.Team.join("red", pig)
print("猪是否在红队：", MC.Team.has("red", pig)) -- true
MC.Team.leave(pig)
print("退出后：", MC.Team.has("red", pig)) -- false
```

### 进度、配方、战利品和结构

- `MC.Advancement.grant/revoke(uuid, advancementId)`：授予或撤销进度
- `MC.Recipe.give/take(uuid, recipeId)`：解锁或收回配方
- `MC.Recipe.forItem(itemId)`：传入产物 ID，返回所有能合成该物品的工作台配方及各自的 1～9 格数组
- `MC.Recipe.fromGrid(grid)`：传入 1～9 格的物品 ID 数组，返回实际合成产物；`MC.Recipe.usingItem(grid)` 是兼容别名

两个方法都读取服务端当前工作台配方，包含数据包和其他模组的配方。九宫格按从左到右、从上到下编号：第一行是 1～3，第二行是 4～6，第三行是 7～9。

`fromGrid` 的参数是一个物品 ID 字符串数组（最多 9 格），未填写或填 `nil`、`"minecraft:air"` 的位置视为空格。方法调用 Minecraft 的实际配方匹配逻辑，有序配方按格子位置匹配，无序配方忽略排列；匹配成功返回产物物品表，包含 `id`、`count`、`components`、`recipeId`、`ordered`、`unordered`，否则返回 `nil`。

`forItem` 返回配方数组。每个配方的 `grid[1]`～`grid[9]` 是可直接传给 `fromGrid` 的物品 ID 字符串数组（空格为 `""`），遇到可替代原料时选其中一个可用 ID。`ingredients[1]`～`ingredients[9]` 则保留每格**全部**可选物品 ID，空格为 `{}`。有序配方保持原图案（不自动居中），无序配方从第 1 格起列出原料；`ordered`、`unordered` 分别标记是否有序/无序。还提供 `id`、`craftingMode`、`result`、`outputs`、`group`、`special`，有序配方另有 `width` 和 `height`。特殊动态配方若没有静态产物则不会出现在 `forItem` 结果中。

```lua
for _, recipe in ipairs(MC.Recipe.forItem("minecraft:crafting_table")) do
    print(recipe.id, recipe.ordered, MC.Recipe.fromGrid(recipe.grid).id)
end
local grid = {
    "minecraft:oak_planks", "minecraft:oak_planks", nil,
    "minecraft:oak_planks", "minecraft:oak_planks"
}
local result = MC.Recipe.fromGrid(grid)
print(result and result.id, result and result.count)
```

- `MC.Loot.insert(x, y, z, lootTableId, dimension?)`：把结果插入目标容器

### 生成数据包与资源包：`MC.Pack`

`MC.Pack` 仅供有脚本执行权限、且未被服务器关闭“服务端 API”的管理员使用；写入内容会持久保存在当前世界。普通玩家不需要安装本模组。它按原版包目录写入 JSON，不会凭空注册新的 Java 物品、方块或实体类型。`kind` 是命名空间下的目录，例如 `recipe`、`advancement`、`tags/block`、`worldgen/biome`；`id` 是 `命名空间:路径`。JSON 的字段仍须符合当前游戏版本对应类别的格式。

- `MC.Pack.putData(kind, id, json)`：写入当前世界 `datapacks/mc_lua_ide_generated/data/<命名空间>/<kind>/<路径>.json`，随后执行**一次完整的服务端数据包重载**。不能保证无卡顿，也不是只刷新这一条 JSON。维度、维度类型、生物群系及 `worldgen/*` 等世界生成内容即使重载完成，现有世界仍需重启后才能可靠生效。
- `MC.Pack.putDataBatch(entries)`：一次写入最多 256 条 `{kind, id, json}`，合计最多 16 MiB，然后只重载一次；若写入或重载失败，会尽量恢复本批次原文件。适合连续注册多项内容。
- `MC.Pack.putAssetJson(kind, id, json)`：写入客户端资源包 JSON。例如 `items`、`models/item`、`blockstates`。
- `MC.Pack.putAssetPng(kind, id, pngBase64)`：写入 PNG 资源，例如 `textures/item`。参数是 PNG 文件的纯 Base64 内容，不是文件路径或 `data:` URL。
- `MC.Pack.putTexture(id, pngBase64)`：`putAssetPng("textures/item", id, pngBase64)` 的快捷写法。
- `MC.Pack.exportAssets()`：导出当前世界的 `mc_lua_ide_generated_resources.zip`。目前没有自动托管或推送；管理员需要将 ZIP 发布给玩家，由玩家安装资源包。玩家安装后也不需要安装本模组。

返回表含 `status`、`path`、`reloadCompleted`、`requiresRestart`、`applied`、`message`。`server_reload_completed` 表示服务端重载过程结束，**不保证这条 JSON 已通过 Minecraft 对应类别的语义校验**；请检查服务端日志。为避免误报，当前 `applied` 始终保守地返回 `false`。`world_restart_required` 表示生成包已选中并完成重载，但还需重启世界；客户端资源的 `needs_export_and_distribution` 则表示只写入了待导出的文件。

```lua
-- 这会生成 data/example/tags/block/building.json。
local result = MC.Pack.putData("tags/block", "example:building",
    [[{"values":["minecraft:stone","minecraft:oak_planks"]}]])
print(result.status, result.reloadCompleted, result.message)

-- 资源包只改变已有物品的客户端显示，不创建新的物品 ID。
MC.Pack.putAssetJson("items", "minecraft:stick",
    [[{"model":{"type":"minecraft:model","model":"minecraft:item/diamond"}}]])
local exported = MC.Pack.exportAssets()
print("请手动发布资源包：" .. exported.path)
```

一次调用 `putData` 就会触发一次完整重载；批量生成内容请使用 `putDataBatch`，并尽量避开游戏高峰期。资源包生成后，未安装新 ZIP 的玩家仍会看到旧贴图/模型。不同 JSON 类别的热重载能力由 Minecraft 决定，本 API 不会伪装成“所有内容即时且无卡顿生效”。

### 运行时注册表：`MC.Registry`

这一组接口直接读取 Minecraft 启动后形成的注册表，因此会自动包含其他 Mod 的资源，不依赖硬编码列表。

- `MC.Registry.kinds()`：可查询类型列表
- `MC.Registry.list(kind)`：查询任意受支持类型
- `blocks()`、`items()`、`entities()`、`effects()`、`sounds()`、`particles()`、`potions()`、`gameRules()`：常用快捷方法
- `dataComponents()`：列出当前运行时全部物品数据组件类型，包含其他 Mod 注册的组件
- 通用查询还支持 `fluids`、`blockEntities`、`attributes`、`dataComponents`

```lua
for _, kind in ipairs(MC.Registry.kinds()) do
    local ids = MC.Registry.list(kind)
    print(kind, #ids)
end
```

这些高层接口会验证 UUID、资源 ID、数值范围和枚举值。尚未单独封装的原版或 Mod 命令仍可通过 `MC.Command.run(...)` 使用，因此服务端命令系统提供最终的完整控制入口。任意第三方 Mod 的 Java API 没有统一 ABI，只有该 Mod 主动提供兼容入口时才能安全直接绑定；它注册到 Minecraft 注册表和命令树中的内容则可立即使用。

### 原版自定义界面：`MC.UI`

`MC.UI` 使用 Minecraft 26.1+ 的原版 Dialog 协议，由服务端直接向指定玩家打开界面。因此只负责查看和操作界面的普通玩家默认不需要安装本模组；如果服务器管理员打开了“要求玩家安装客户端模组”，则所有新连接都必须安装。可用 `MC.UI.available()` 检查功能是否存在。

IDE 中可从 `UI与窗口 → 视图 → Minecraft UI 编辑器` 打开可视化编辑器。左侧竖排控件栏支持正文、文本输入、布尔开关、数值滑块、单选项和按钮，点击即可添加到中间的 640 × 360 设计画布。点击画布控件后可拖动位置，拖动选中框右下角可调整大小。方向键微调 1 单位，Shift + 方向键移动 10 单位；Delete 删除，Ctrl + D 复制控件（编辑输入框时仍使用文本编辑快捷键）。

右侧是选中控件的独立属性菜单，可以编辑标识、显示文字、默认值、X/Y 坐标及宽高；数值控件还可以设置上下限。向下滚动可找到复制、层级和删除按钮。点击画布空白处或“← 界面属性”可编辑界面标题、ID、类型、ESC 关闭和暂停设置。属性输入支持选中、Ctrl + A、复制粘贴和 Tab 切换。

设计画布中的自由坐标与宽高会完整保存在模板中。**当前 `MC.UI` 输出的是原版对话框，Minecraft 会将正文、输入项和按钮分组自动排版，无法按任意 X/Y 坐标渲染。** 导出时，各组按画布从上到下、从左到右排序；文本框、滑块、选择框及按钮保留宽度，按钮保留提示文字。画布高度和层级仅用于设计模板，不会改变原版控件的高度或覆盖关系。编辑器下方也会显示这一提示。

“插入 UI 内容”会把生成的 `type`、`title`、`inputs`、`buttons` 等字段直接填入光标所在的空 `ui{}` 或 `{}` 内，不重复插入花括号。在其他位置插入时生成可作为变量值或函数参数使用的 `{ ... }` 表；“复制 UI 内容”复制不带外层花括号的字段。需要注册界面时，可将这个表传给 `MC.UI.register(uiId, ui)`；界面 ID 由调用方提供。模板名称可使用中英文、数字、下划线和连字符，保存/读取的模板位于客户端 `config/mc_lua_ide/ui_templates`；旧模板读取时会自动分配初始位置。

- `MC.UI.register(uiId, definition)`：为当前脚本注册可重复使用的界面定义
- `MC.UI.open(playerUuid, uiId)`：向指定在线玩家打开已注册界面
- `MC.UI.show(playerUuid, uiId, definition)`：不注册，直接打开一次界面
- `MC.UI.close(playerUuid)`：关闭指定玩家当前的原版 Dialog
- `MC.UI.list()`：列出当前脚本注册的全部界面 ID
- `MC.UI.unregister(uiId)`：移除一个定义
- `MC.UI.clearRegistered()`：移除全部定义并返回移除数量
- `MC.Event.onUiAction(callback)`：监听按钮提交；事件含 `playerUuid, playerName, uiId, actionId, inputs`

界面 `type` 可选 `form`、`notice`、`confirmation`。通用字段如下：

- `title`：标题；`body`：正文字符串或字符串数组
- `canCloseWithEscape`：是否允许 Esc 关闭，默认 `true`
- `pause`：单人游戏中是否暂停，默认 `false`
- `afterAction`：按钮后的行为，可选 `close`、`none`、`wait_for_response`
- `columns`：`form` 的按钮列数，范围 1–8
- `buttons`：普通按钮数组；每项支持 `id, label, tooltip, width`
- `exit`：`form` 的可选退出按钮，结构与普通按钮相同

`inputs` 中每项都需要唯一的 `key`，支持四种类型：

- `text`：文本框；支持 `label, initial, maxLength, width, labelVisible, multiline, maxLines, height`
- `boolean`：勾选框；支持 `label, initial, onTrue, onFalse`
- `number`：数字滑块；支持 `label, min, max, initial, step, width, labelFormat`
- `select`：单选列表；`options` 每项支持 `id, text, initial`

完整示例：

```lua
local players = MC.Player.list()
if #players == 0 then error("当前没有在线玩家") end

MC.UI.register("server_menu", {
    type = "form",
    title = "服务器菜单",
    body = {"请输入留言并选择操作："},
    canCloseWithEscape = true,
    afterAction = "close",
    columns = 2,
    inputs = {
        {key = "message", type = "text", label = "留言", maxLength = 128},
        {key = "public", type = "boolean", label = "公开显示", initial = false},
        {key = "amount", type = "number", label = "数量", min = 1, max = 64, initial = 1, step = 1},
        {key = "mode", type = "select", label = "模式", options = {
            {id = "info", text = "查询", initial = true},
            {id = "execute", text = "执行"}
        }}
    },
    buttons = {
        {id = "submit", label = "提交", tooltip = "发送给服务端 Lua 脚本"},
        {id = "cancel", label = "取消"}
    }
})

MC.Event.onUiAction(function(event)
    if event.uiId ~= "server_menu" then return end
    print("玩家", event.playerName, "点击", event.actionId)
    if event.actionId == "submit" then
        print(event.inputs.message, event.inputs.public,
            event.inputs.amount, event.inputs.mode)
    end
end)

MC.UI.open(players[1].uuid, "server_menu")
```

每次打开都会生成一次性随机令牌。服务端只接受对应玩家、当前运行脚本、已声明按钮和已声明输入键的回传；客户端附加或伪造的其他字段会被忽略。玩家提交一次后令牌立即失效，脚本若要显示下一步界面，应在 `onUiAction` 中再次调用 `MC.UI.open`。停止脚本会注销界面监听并关闭尚未提交的界面。

### 强制客户端 API：`MC.Client`

API 文档中所有 `MC.Client.*` 条目都会集中显示在独立的“客户端 Mod 专用 API”大类，并显示醒目的“仅强制客户端模式”标记。这些控制函数必须同时满足以下条件，否则服务端会返回中文错误：

1. 在“Mod Menu → MC Lua IDE → 配置 → 服务器接入”开启“要求玩家安装客户端模组”。
2. 开启后重新启动 Lua 脚本，使脚本获得新的限制快照。
3. 目标玩家在线，并安装了协议兼容的 MC Lua IDE 客户端。
4. “聊天、显示与界面 API”没有被服务器限制关闭。

状态查询：

- `MC.Client.available(playerUuid)`：目标玩家满足客户端 API 条件时返回 `true`
- `MC.Client.info(playerUuid)`：返回 `{playerUuid, online, required, available, protocol}`
- `MC.Client.list()`：列出已安装兼容客户端的在线玩家，包含 `uuid, name, protocol`

客户端操作：

- `MC.Client.message(playerUuid, textOrJson)`：只在目标客户端的聊天栏显示本地系统消息
- `MC.Client.toast(playerUuid, titleOrJson, messageOrJson)`：显示右上角系统 Toast
- `MC.Client.notice(playerUuid, titleOrJson, bodyOrJson)`：打开客户端通知页，玩家可点击返回
- `MC.Client.closeNotice(playerUuid)`：只关闭由 `MC.Client.notice` 打开的页面，不会关闭箱子等其他界面
- `MC.Client.openUrlPrompt(playerUuid, url)`：显示原版安全链接确认框；必须由玩家手动确认，脚本不能静默打开网页
- `MC.Client.openIde(playerUuid)`：请求打开 IDE；目标玩家仍必须通过服务器所有者或 OP 4 权限校验
- `MC.Client.hasResourcePack(playerUuid, packName)`：查询该玩家本地是否启用了指定名称或资源包 ID
- `MC.Client.enableResourcePack(playerUuid, packName)`：选择该玩家本地已有的指定材质包并等待资源重载；找不到时会返回中文错误

材质包列表属于玩家客户端本地状态，服务端本身无法可靠读取，因此这两个函数属于客户端 Mod 专用 API。名称会依次匹配资源包 ID、显示名称以及去掉 `file/`、`.zip` 后的文件名；模糊结果不唯一时不会擅自选择。

```lua
local player = MC.Player.list()[1]
if not player then error("没有在线玩家") end

local client = MC.Client.info(player.uuid)
if not client.required then
    error("请先开启强制客户端模式，并重新启动脚本")
end
if not client.available then
    error("目标客户端不兼容")
end

MC.Client.message(player.uuid, {text = "这条消息只在你的客户端显示", color = "#55FFFF"})
MC.Client.toast(player.uuid, {text = "任务完成", color = "gold", bold = true}, "服务端脚本已经执行完成")
MC.Client.notice(player.uuid, {text = "服务器公告", color = "#FFAA00"}, "点击下方按钮返回之前的页面。")

-- 只弹确认框，不会直接打开浏览器
MC.Client.openUrlPrompt(player.uuid, "https://example.com/help")
```

客户端 API 不提供截图、读取按键内容、静默修改剪贴板或绕过确认直接打开外部链接等隐私能力。强制安装握手与专用数据包仅用于兼容性和功能协商，并不把客户端变成可信执行环境。

### 服务端事件：`MC.Event`

当前提供 33 种常用服务端事件，覆盖方块、物品、实体、玩家、状态效果、睡眠、区块、维度、Tick、聊天、命令、自定义界面操作和毫秒定时任务。游戏事件来自服务端世界；涉及玩家的事件始终提供 `playerUuid`，不要用客户端玩家对象代替 UUID。

事件回调不会在主代码执行完后消失。只要至少注册了一个事件，脚本就保持“运行中”，可用编辑器“停止”按钮或 `/lua stop` 停止并自动注销全部回调。回调在脚本线程中按顺序处理，不直接阻塞服务端线程，因此它们是观察型事件，不能取消原本的放置、攻击或交互。队列最多保留 1024 项，持续来不及处理时会丢弃最旧事件。

#### 注册与管理

- `MC.Event.on(eventName, callback, intervalTicks?)`：按名称注册；返回整数注册 ID。对于 `"interval"` 事件，第三个参数是整数毫秒，省略时为 `1000`
- `MC.Event.onInterval(intervalMs, callback)`：按真实毫秒间隔重复执行；与游戏 Tick 无关
- `MC.Event.names()`：返回当前支持的全部事件名称，可用于遍历或动态注册
- `MC.Event.off(registrationId)`：只注销指定回调；找到时返回 `true`
- `MC.Event.clear()`：注销当前脚本的全部回调；返回注销数量
- 游戏事件的 `onXxx(callback)` 都是通用 `on` 的易读快捷写法；定时任务用 `onInterval(intervalMs, callback)`
- `onServerTick`、`onLevelTick` 可把间隔作为第二个参数传入；例如 `20` 约为一秒一次

每个回调收到一个 `event` 表，`event.type` 是事件名称。资源 ID 都是完整的 `namespace:path`，所以也支持其他 Mod 注册的方块、物品、实体、效果和维度。

```lua
for _, eventName in ipairs(MC.Event.names()) do
    print("支持事件", eventName)
end

local id = MC.Event.on("blockBroken", function(event)
    print(event.playerUuid, event.blockId, event.x, event.y, event.z)
end)
print("注册 ID", id)
```

#### 脚本启动与停止

`MC.Event.onScriptStarted(callback)` 监听当前脚本启动，在注册后的下一次调度（主代码返回或使用 `MC.sleep` 让出执行权）执行一次。`MC.Event.onScriptStopped(callback)` 监听脚本结束，手动停止、正常结束、运行错误或超时都会触发。也可用 `MC.Event.on("scriptStarted", callback)` / `MC.Event.on("scriptStopped", callback)` 注册，用 `off` / `clear` 注销。它们只属于本次脚本运行，不监听其他脚本；这两个监听本身不会让脚本保持运行。

```lua
local count = 0
MC.Event.onScriptStarted(function(event)
    print("已启动：", event.scriptName)
end)
MC.Event.onScriptStopped(function(event)
    print("已结束：", event.reason, "累计：", count, "次")
    if event.error then print(event.error) end
end)
MC.Event.onInterval(1000, function(event)
    count = event.count
    print("运行中：", count)
end)
```

运行后按停止或执行 `/lua stop` 测试，完整示例见 `examples/script_lifecycle.lua`。若需要在其他主代码执行之前初始化，请直接写在文件开头，不要等待启动回调。

两种回调共有 `type`、`registrationId`、`scriptName`、`ownerUuid`、`startedAt`（Unix 毫秒时间戳）、`elapsedMs`（实际运行毫秒）。停止回调还包含 `reason`（`completed` 正常结束、`stopped` 主动停止、`error` 错误/超时）、`stopped`、`success` 和 `error`（无错误时为 `nil`）。脚本原有局部变量、闭包在停止回调中仍可使用。

停止回调等原来的 Lua 执行流程退出后，按注册顺序执行，可输出日志和调用已授权的游戏 API 清理资源。不能使用 `MC.sleep` / `MC.wait`、注册新事件，也不会停在断点；每个回调最多 1 秒，全部回调共用最多 2 秒。回调报错会写入日志并尝试下一个，不改变原始结束原因；总预算用完后跳过剩余回调。服务器已经完全关闭、进程崩溃或强制终止时无法保证清理完成。事件权限及监听数量限制仍然适用，普通玩家无需安装客户端模组。

#### 毫秒定时任务

`MC.Event.onInterval(intervalMs, callback)` 按服务端真实时间重复执行，`intervalMs` 必须是 `1–3600000` 的整数毫秒。首次执行等待一个完整间隔。它不是游戏 Tick，不需要玩家安装客户端模组；服务端的事件权限、监听数量、执行队列和脚本运行时间限制仍然适用。

```lua
local id = MC.Event.onInterval(1000, function(event)
    print("第", event.count, "次，已运行", event.elapsedMs, "ms")
    if event.count >= 5 then
        MC.Event.off(event.registrationId)
    end
end)
print("定时监听 ID：", id)
-- 同样可以写成 MC.Event.on("interval", function(event) ... end, 1000)
```

回调参数：`type="interval"`、`registrationId`（用于注销）、`intervalMs`（配置的间隔）、`count`（实际执行次数，从 1 开始）。`elapsedMs` 现改为计划经过时间，严格等于 `scheduledCount × intervalMs`；`deltaMs` 是距离上次回调计划时间的差值，不累计调度误差。`scheduledCount` 是从注册起的计划周期序号，跳过周期时会跳号。`actualElapsedMs` 和 `actualDeltaMs` 保留实际经过时间、实际执行间隔；`lateMs` 是实际开始相对本次计划时间的延迟。`skippedCount` 是两次执行间跳过的周期数，`totalSkippedCount` 为累计跳过次数。需要真实耗时的旧脚本，请把 `elapsedMs` / `deltaMs` 改为 `actualElapsedMs` / `actualDeltaMs`；其他事件的同名字段不变。

例如 1000ms 的定时器，某次实际在 3007ms 执行时，`elapsedMs=3000`、`actualElapsedMs=3007`、`lateMs=7`。循环应直接使用 `event.elapsedMs` 驱动逻辑时间，不要自行累加实际延迟。如果中间跳过了周期，计划时间仍沿注册时的基准前进，而不是从回调完成时重新计时。

同一监听不会重叠执行。回调尚未结束（包括回调内 `MC.sleep`）时会跳过该监听错过的时间点，不会在恢复后堆积补发；睡眠会让出 Lua 执行权，其他监听仍可运行。系统调度、长代码、服务端 API 和断点暂停可能使执行延后，不保证硬实时。`MC.Event.off(id)` 和 `clear()` 会移除监听并取消尚未开始的回调，但不会中断已经开始的回调；停止脚本会中断所有回调并注销监听。只注册定时监听也会使脚本保持运行，直到注销完毕或停止。

#### 方块与物品

- `blockPlaced` / `onBlockPlaced`：成功放置方块；`playerUuid, playerName, blockId, x, y, z, dimension, hand, itemId, itemCount, itemComponents`
- `blockBroken` / `onBlockBroken`：玩家成功破坏方块；上列玩家、方块、坐标字段，加 `hadBlockEntity`。包括创造模式挖床头或床尾等联动拆除情况，每次操作按玩家实际挖掘的那一格触发一次，坐标和方块 ID 是破坏前的目标；另一半自动消失不会额外触发。兼容 Axiom 的特殊挖掘数据包（包括不更新邻居等模式），不要求安装 Axiom；Axiom 的非挖掘编辑、脚本/命令删方块不视为玩家挖掘。被取消、权限拒绝或挖空气不触发，不会改变原版或 Axiom 的掉落、权限和拆除行为。
- `blockAttacked` / `onBlockAttacked`：左键攻击方块；玩家、方块、坐标字段，加 `hand, face`
- `blockUsed` / `onBlockUsed`：右键使用方块；玩家、方块、坐标字段，加 `itemId, itemCount, itemComponents, hand, face`
- `itemUsed` / `onItemUsed`：尝试使用手中物品；`playerUuid, playerName, itemId, itemCount, itemComponents, count, hand, x, y, z, dimension`

```lua
MC.Event.onBlockPlaced(function(event)
    print("放置", event.playerName, event.blockId, event.x, event.y, event.z)
    if event.blockId == "minecraft:diamond_block" then
        MC.Chat.message(event.playerUuid, "你放置了钻石块！")
    end
end)

MC.Event.onBlockBroken(function(event)
    print("破坏", event.blockId, "含方块实体", event.hadBlockEntity)
end)
```

#### 实体与战斗

实体字段按角色使用统一前缀。例如 `entityUuid, entityType, entityName, entityRuntimeId, entityX, entityY, entityZ`；目标实体使用 `target*`，击杀者和被击杀者使用 `killer*`、`killed*`，伤害来源使用可选的 `attacker*`、`direct*`。

- `entityAttacked` / `onEntityAttacked`：玩家攻击目标；玩家字段、`hand` 和 `target*`
- `entityUsed` / `onEntityUsed`：玩家右键实体；玩家字段、`hand, itemId, itemCount, itemComponents` 和 `target*`
- `entityLoaded` / `onEntityLoaded`：实体加载；`entity*` 和 `dimension`
- `entityUnloaded` / `onEntityUnloaded`：实体卸载；`entity*` 和 `dimension`
- `entityChangedDimension` / `onEntityChangedDimension`：非玩家实体切换维度；`entity*, originalUuid, fromDimension, toDimension`
- `entityDamaged` / `onEntityDamaged`：有生命实体（`LivingEntity`，包括玩家）结算伤害后；`entity*, damageType, baseDamage, damageTaken, blocked, remainingHealth`，以及可选伤害来源字段。致死伤害使用死亡监听
- `entityDied` / `onEntityDied`：实体死亡（仅 `LivingEntity` 死亡流程，包括玩家）；`entity*, dimension, damageType`，以及可选伤害来源字段。**不是全部实体的删除监听**：掉落物、展示实体等被移除、调用 `MC.Entity.remove` 或区块卸载不会触发此事件；不死图腾等阻止死亡时也不会触发。只需玩家死亡请使用 `onPlayerDied`
- `entityKilledOther` / `onEntityKilledOther`：实体击杀另一个有生命实体（`LivingEntity`，包括玩家）；`killer*, killed*, damageType, dimension`，以及可选伤害来源字段
- `projectileHitBlock` / `onProjectileHitBlock`：任意弹射物（箭、三叉戟、雪球、火球、风弹及模组弹射物）击中方块，在弹射物作出反应之前触发。字段：`projectile*`（UUID／类型／名称／位置）、`hasOwner` 及 `owner*`、射击者是玩家时的 `playerUuid`／`playerName`、精确命中点 `hitX`／`hitY`／`hitZ`、被击中方块 `blockId`／`x`／`y`／`z`、被击中的面 `face`、`inside`、`dimension`
- `projectileHitEntity` / `onProjectileHitEntity`：任意弹射物击中实体。字段：`projectile*`、`hasOwner` 及 `owner*`、`playerUuid`／`playerName`、`hitX`／`hitY`／`hitZ`、被击中实体 `target*`、`targetIsPlayer`（为 true 时有 `targetPlayerName`）、`dimension`
- `equipmentChanged` / `onEquipmentChanged`：有生命实体（`LivingEntity`，包括玩家）装备槽变化；`entity*, slot, oldItemId, oldItemCount, oldItemComponents, oldCount, newItemId, newItemCount, newItemComponents, newCount, dimension`

```lua
MC.Event.onEntityDamaged(function(event)
    print(event.entityName, "受到", event.damageTaken, "点伤害")
    print("剩余生命", event.remainingHealth, "伤害类型", event.damageType)
    if event.attackerUuid then
        print("攻击者", event.attackerName, event.attackerUuid)
    end
end)

MC.Event.onEntityDied(function(event)
    print("死亡", event.entityType, event.entityUuid, event.dimension)
end)
```

#### 玩家、效果与睡眠

- `playerJoined` / `onPlayerJoined`：玩家加入；`playerUuid, playerName, x, y, z, dimension`
- `playerLeft` / `onPlayerLeft`：玩家离开；字段同加入事件
- `playerDied` / `onPlayerDied`：玩家确认死亡；`playerUuid, playerName, x, y, z, dimension, damageType, deathMessage`，以及可选 `attacker*` 和 `direct*`。非玩家死亡不会触发，不死图腾等成功阻止死亡也不会触发；此监听不能取消死亡。环境伤害没有攻击者时，对应字段为 `nil`。`damageType` 是原版伤害消息类型（例如 `fall`、`genericKill`），不是注册表 ID；`deathMessage` 是原版死亡消息的纯文本。数据是死亡发生时的快照，Lua 回调异步执行。服务端监听，普通玩家无需安装模组；停止脚本自动注销。通用写法是 `MC.Event.on("playerDied", callback)`
- `playerRespawned` / `onPlayerRespawned`：玩家复活／重生完成；`playerUuid, playerName, x, y, z, dimension` 是重生后的玩家位置快照。`alive` 表示**重生前是否存活**，不是复活后是否活着：`false` 表示死亡后复活，`true` 表示存活时重建（例如从末地返回）。只监听死亡后的复活时使用 `if not event.alive then ... end`。服务端监听，普通玩家无需安装模组；停止脚本自动注销，回调异步执行且不能取消重生。通用注册为 `MC.Event.on("playerRespawned", callback)`
- `playerChangedDimension` / `onPlayerChangedDimension`：玩家切换维度；玩家字段、`fromDimension, toDimension`
- `effectAdded` / `onEffectAdded`：有生命实体（`LivingEntity`，包括玩家）获得状态效果；`entity*, effectId, duration, amplifier, ambient, visible, fromCommand, dimension`
- `effectRemoved` / `onEffectRemoved`：有生命实体（`LivingEntity`，包括玩家）移除状态效果；字段同添加事件
- `sleepStarted` / `onSleepStarted`：支持睡眠的有生命实体（`LivingEntity`，包括玩家）开始睡眠；`entity*, bedX, bedY, bedZ, dimension`
- `sleepStopped` / `onSleepStopped`：支持睡眠的有生命实体（`LivingEntity`，包括玩家）停止睡眠；字段同开始事件

```lua
MC.Event.onPlayerJoined(function(event)
    MC.Chat.message(event.playerUuid, "欢迎，" .. event.playerName)
end)

MC.Event.onPlayerDied(function(event)
    print("玩家死亡", event.playerName, event.playerUuid)
    print("位置", event.dimension, event.x, event.y, event.z)
    print("原因", event.damageType, event.deathMessage)
    if event.attackerUuid then
        print("攻击者", event.attackerName, event.attackerType, event.attackerUuid)
    end
end)

MC.Event.onPlayerChangedDimension(function(event)
    print(event.playerName, event.fromDimension, "->", event.toDimension)
end)

MC.Event.onPlayerRespawned(function(event)
    if not event.alive then
        print("玩家已复活", event.playerName, event.playerUuid)
        print("重生位置", event.dimension, event.x, event.y, event.z)
    end
end)
```

#### 区块、维度与 Tick

- `chunkLoaded` / `onChunkLoaded`：区块加载；`chunkX, chunkZ, minBlockX, minBlockZ, dimension, newChunk`
- `chunkGenerated` / `onChunkGenerated`：新区块生成完成；区块坐标和维度字段
- `chunkUnloaded` / `onChunkUnloaded`：区块卸载；区块坐标和维度字段
- `levelLoaded` / `onLevelLoaded`：维度加载；`dimension, gameTime, dayTime`
- `levelUnloaded` / `onLevelUnloaded`：维度卸载；字段同加载事件
- `serverTick` / `onServerTick`：服务器 Tick；`tick, playerCount`
- `levelTick` / `onLevelTick`：每个已加载维度的 Tick；`tick, dimension, gameTime, dayTime`

Tick 默认每 Tick 触发。建议传入间隔以降低脚本开销：20 Tick 约一秒，1200 Tick 约一分钟。

```lua
MC.Event.onServerTick(function(event)
    print("服务器 Tick", event.tick, "在线", event.playerCount)
end, 20)

MC.Event.onLevelTick(function(event)
    if event.dimension == "minecraft:overworld" then
        print("主世界时间", event.dayTime)
    end
end, 200)
```

#### 聊天与命令

- `chat` / `onChat`：玩家发送聊天；`playerUuid, playerName, message, decoratedMessage, x, y, z, dimension`
- `command` / `onCommand`：命令提交给服务端；`command, sourceName, x, y, z, dimension`；若来源是实体则有 `source*`，若来源是玩家则另有 `playerUuid, playerName`

`command` 不含开头的 `/`。在命令回调里再次执行同类命令时要自行设置条件，避免产生递归监听。

```lua
MC.Event.onChat(function(event)
    print("<" .. event.playerName .. "> " .. event.message)
end)

MC.Event.onCommand(function(event)
    print("命令来源", event.sourceName, "内容", event.command)
end)
```

#### 自定义界面操作

- `uiAction` / `onUiAction`：玩家点击脚本界面按钮；`playerUuid, playerName, uiId, actionId, inputs`
- `inputs` 是 Lua 表，键和值来自界面定义；文本和选择返回字符串，勾选框返回布尔值，数字滑块返回数字
- 玩家按 Esc 直接关闭时不会触发按钮事件

#### 注销示例

```lua
local joinId = MC.Event.onPlayerJoined(function(event)
    print(event.playerName)
end)

MC.Event.off(joinId)
-- MC.Event.clear() 可以一次清除当前脚本的全部监听
```

多人模式下，脚本始终保存在并运行于远端服务端。执行输出通过专用通道实时返回给发起运行的管理员；管理员断开连接时，由该管理员启动的活动脚本会自动停止，防止无人管理的脚本继续运行。

## 从基础到进阶的完整案例

前面的 API 章节按功能查阅；以下案例展示怎样把 Lua 的变量、判断、表和函数与服务端 API 组合起来。先保存代码，再运行。涉及广播、奖励或修改世界的示例应先在测试世界验证。

### 案例一：倒计时公告（顺序执行）

这个脚本会实时输出并向全服广播四条消息，然后自然结束。`MC.sleep` 暂停的只是当前执行流程，服务器和其他事件监听仍正常运行；脚本运行期间可随时按“停止”。

```lua
MC.Chat.broadcast("活动将在 3 秒后开始")
for seconds = 3, 1, -1 do
    print("剩余", seconds, "秒")
    MC.sleep(1000)
end
MC.Chat.broadcast("活动开始！")
```

### 案例二：放置方块时发奖（持续事件）

脚本注册事件后会保持运行。只有玩家放置钻石块才发一颗绿宝石；同一玩家在 100 Tick 内再次触发会被忽略。`event.playerUuid` 来自触发事件的玩家，不是启动 IDE 的管理员。

```lua
local lastRewardTick = {}

local registrationId = MC.Event.onBlockPlaced(function(event)
    if event.blockId ~= "minecraft:diamond_block" then return end

    local now = MC.Server.tickCount()
    local previous = lastRewardTick[event.playerUuid] or -100000
    if now - previous < 100 then return end

    lastRewardTick[event.playerUuid] = now
    MC.Item.give(event.playerUuid, "minecraft:emerald", 1)
    MC.Chat.message(event.playerUuid, "放置钻石块奖励：1 颗绿宝石")
    print("已奖励玩家", event.playerName)
end)

print("监听已注册，ID：", registrationId)
-- 需要结束时点击 IDE 的“停止”，或在脚本内调用 MC.Event.off(registrationId)
```

事件回调共享此脚本的局部表 `lastRewardTick`，因此冷却记录会保持到停止脚本。重新运行会重置记录；若需要跨重启保存，须在服务器允许隔离文件写入后使用 `MC.File`。高频事件不要在回调内长时间等待，以免积压事件队列。

### 案例三：先预览、再小范围填充方块

`MC.Block.fill` 会直接修改服务端世界，不受原版 `/fill` 数量上限约束，更要自己控制范围。下面默认只打印计划；确认坐标、维度和方块 ID 后，才把 `dryRun` 改为 `false`。初次测试建议用测试世界和已加载区块。

```lua
local dryRun = true
local x1, y1, z1 = 0, 64, 0
local x2, y2, z2 = 2, 64, 2
local blockId = "minecraft:glass"
local dimension = "minecraft:overworld"

local volume = (x2 - x1 + 1) * (y2 - y1 + 1) * (z2 - z1 + 1)
print("计划在", dimension, "填充", volume, "个", blockId)

if not dryRun then
    local changed = MC.Block.fill(x1, y1, z1, x2, y2, z2, blockId, dimension)
    print("区域发生变化：", changed)
end
```

更多复杂功能——数据组件、实体装备、配方、原版 UI、网络与数据包——可按前面的分类跳转思路在“API 文档”中搜索具体方法，再复制其模板。脚本运行产生的 `print` 会实时显示在日志窗口；脚本结束后日志不会自动消失。

## 管理员客户端命令

- `/lua`：通过权限检查后直接打开 IDE
- `/lua list`：列出服务端保存的所有脚本
- `/lua run <名称>`：普通运行指定脚本，不启用变量采样；`print` 输出实时发送到管理员聊天栏
- `/lua testrun <名称>`：以调试模式运行指定脚本，启用已设置的断点，可配合 `F12` 变量与断点监视；`print` 同样发送到聊天栏
- `/lua stop`：停止服务端当前正在运行的脚本

输入 `/lua run ` 或 `/lua testrun ` 后，Tab 补全会从服务端读取全部 Lua 脚本（包括多层子目录），按完整相对路径显示，例如 `tools/math`、`demo_modules/main`。路径使用 `/` 分隔，无需引号；也可输入 `.lua` 后缀，运行时自动去除。输入 `tools/` 筛选该目录及其子目录，或直接输入文件名前缀查找其他目录中的同名脚本；候选提示显示完整 `.lua` 文件名。新增、删除脚本后再次触发补全会重新读取列表，不会沿用其他服务器的目录。未获得服务器所有者／OP 等级 4 权限时不提供脚本名称。

## 个性化、字号和界面缩放

编辑器顶部菜单为“UI与窗口”。其中“UI与窗口 → 个性化”打开外观设置页，只在当前管理员客户端保存配置；点击“保存并应用”生效，“放弃更改”不保存。

“文本”中的“代码滚轮灵敏度”支持直接输入 0.1～20 的倍率，或用两侧加减按钮以 0.1 调整。默认 1 倍；例如 0.5 更慢、2 更快。点击“保存并应用”后立即生效，重开 IDE 和重启游戏仍保留。只影响 Lua、JSON、函数等文本代码区（含行号栏）的滚轮滚动，不改变目录、手册、日志的滚动速度或图片画布缩放；拖动滚动条、键盘移动和自动定位光标的速度不受影响。

“文本 → 过长代码自动换行”默认开启：超出代码区宽度的行只在屏幕上折行，不修改文件内容。关闭并保存后，每个实际代码行保持一行；在代码区或行号栏按住 `Shift` 使用滚轮可左右滚动（滚轮向下往右、向上往左），横向滚轮也可使用。横向滚动同样遵循代码滚轮灵敏度，输入和方向键移动会自动让光标保持可见。搜索高亮、错误标记、鼠标选中和 API 悬浮提示随横向滚动对齐。

Lua 的多行函数、`{ … }` 数组／表和 `if … elseif … else … end` 左侧都有折叠按钮。`if` 会折叠到与它配对的 `end`，包含全部分支，嵌套结构可独立折叠；注释和字符串中的括号、关键字不会被当成代码结构。折叠仅隐藏显示行，复制、保存、运行仍包含完整代码；跳转到隐藏内容或编辑折叠区域会自动展开。未写完整或只有一行的结构不显示折叠按钮。

- 文本：选择深色、浅色、高对比度配色；切换 Minecraft 默认或等宽字体；分别调整 10%–300% 字号、行高和字符宽度。编辑器换行、行号与光标定位会同步调整。“自定义语法配色”可逐项选择普通文本、关键字、字符串、数字、函数与 API、注释、常量、运算符、成员、参数、语法错误的颜色。在底部输入 `#RRGGBB` 或六位十六进制值，按回车或“应用”暂存，再点击“保存并应用”。“重置”使当前项目重新跟随主题默认颜色。
- 光标：选择竖线、下划线或方块形状，设置宽度、颜色和是否闪烁。
- 背景图：点击“打开图片目录”，把 PNG 图片放进客户端的 `config/mc_lua_ide/backgrounds`，然后在“背景图片”中选择。可调整可见度、原始大小/完整显示/裁剪铺满/拉伸填充模式，以及九宫格对齐位置。背景仅显示在代码编辑区；“裁剪铺满”时，对齐位置也决定图片裁剪方向。

旧的“UI与窗口 → 字号”和“UI与窗口 → 配色”快捷入口仍可使用，设置会与个性化页同步。

“UI与窗口 → 界面缩放”同样支持 10%–300% 的预设值和自定义百分比，会缩放整个 IDE，包括菜单、编辑区、吸附区域、浮动窗口和文字。鼠标命中、拖动、悬浮与边框缩放会同步换算，不需要改变 Minecraft 的全局 GUI 缩放。

## 安全限制

Java/luajava、操作系统库、原生文件 IO、原生 package 加载器和 Lua debug 库默认全部禁用，但服务器所有者可以在“核心安全边界”页分别开启。安全的 `require` / `MC.Script.require` 只加载 `scripts` 下的 Lua 文件，不属于高危原生包加载。所有高风险开关旁都会显示红色“⚠ 高危”提示：

- `Java / luajava`：脚本可能获得 JVM、服务端内部对象、文件和网络访问能力
- `操作系统库 os`：脚本可能执行系统命令或读取进程环境
- `原生 io 与任意路径`：启用 `io`、`dofile`、`loadfile`，不再受每脚本数据目录限制
- `package / require`：开放原生包路径和加载器；全局 `require` 仍由本 Mod 的脚本目录安全加载器接管
- `Lua debug 库`：脚本可以移除停止和超时钩子，可能导致脚本无法正常终止
- `HTTP/HTTPS 网络 API`：提供 `MC.Network`，可访问公网、服务器内网或本机 HTTP 服务，存在 SSRF 风险

限制页面会按影响分级并常驻显示具体理由：红色“高危”表示能力可能越过 Lua 沙箱、访问主机或以控制台权限操作服务器；黄色“警告”表示能力仍受游戏 API 或脚本目录边界限制，但可能修改世界、玩家、物品或造成性能与数据风险。关闭时按钮显示绿色“安全：禁止”，开启时按钮使用对应的红色或黄色。

这些开关直接降低服务端安全性，只应在完全信任全部服务端 Lua 脚本时开启。网络页还可以限制连接/请求超时和最大请求响应字节数，并且不会自动跟随重定向；这些限制不能消除访问内网服务的风险。启用 Java 互操作后也可能绕过 `MC.Network` 的限制直接进行网络访问。

“Lua 限制”页面还可以分别控制：

- 脚本长度、最长运行时间、输出行数、单行长度和中断检查频率
- 事件监听数量、事件队列容量和 Tick 事件最低间隔
- 命令、世界、玩家、实体、物品容器、聊天显示与自定义界面、服务端管理和注册表等 `MC.*` API 分类
- `load/loadstring`、协程、元表/raw 操作以及垃圾回收控制
- 隔离文件的读取、写入和删除权限、单文件大小和文件数量

“服务器接入”页面单独提供“要求玩家安装客户端模组”开关。它属于黄色警告项：开启不会扩大 Lua 权限，但会阻止原版客户端和旧协议客户端登录。服务端只接受与当前 `MC Lua IDE` 协议版本一致的握手；这个检查用于版本兼容和安装要求，不是反作弊认证，能够自行实现协议的自定义客户端仍可完成握手。

隔离文件权限默认全部关闭。只启用 `MC.File` 读取、写入或删除时，不会恢复 Lua 原生 `io`，脚本只能访问自己的 `config/mc_lua_ide/data/<脚本名>/` 目录；相对路径、符号链接、文件数量和大小都会由服务端验证。如果另外打开红色高危的“原生 io 与任意路径”，此隔离边界将不再成立：

```lua
MC.File.write("state.txt", "ready")
MC.File.append("events.log", "started\n")
print(MC.File.read("state.txt"))

for _, path in ipairs(MC.File.list()) do
    print(path)
end
```

脚本可通过 `MC.Limits.current()` 读取本次启动使用的限制快照。`MC.Command.run` 拥有服务端控制台能力，因此整个 IDE 和设置协议只向服务器所有者权限开放。

启用红色高危的网络开关后，可以使用：

```lua
local response = MC.Network.get("https://example.com")
print(response.status, response.body)

local posted = MC.Network.post(
    "https://example.com/api",
    "{\"message\":\"hello\"}",
    "application/json"
)
print(posted.status)
```

## 第三方模组扩展开发（进阶）

服务端上的其他 Fabric 模组既可以注册 `MC.<模组命名空间>.*`，也可以创建 `TestMod.*` 这样的独立顶级 API 大类，并为每个方法提供参数类型、用法模板和多语言说明。管理员打开 IDE 时会从服务端同步这些元数据；扩展函数会自动加入 Tab 补全、语法配色、悬浮提示、实时参数检查和“API 文档”，详情中会标出来源模组。扩展模组还可声明函数需要客户端 Mod，使其自动进入“客户端 Mod 专用 API”大类。普通玩家不能读取扩展 API 文档。完整接入说明见项目中的 `docs/extensions/third-party-api.zh_cn.md`。

### 创建独立 API 大类

模组初始化时使用公开 Java 方法 `McLuaIdeApi.rootFunction(ownerModId, rootName, method, function)`。例如下面的注册会创建 `TestMod.playerCount()`，翻译对象中的作用、返回值、详细说明和用法模板会自动写入游戏内 API 文档：

```java
McLuaIdeApi.register(
    McLuaIdeApi.rootFunction("test_mod", "TestMod", "playerCount", (context, args) ->
        context.onServer(server -> LuaValue.valueOf(server.getPlayerCount())))
    .translation("zh_cn", McLuaIdeApi.translation("TestMod API", "获取服务器在线玩家数量")
        .returns("整数；当前在线玩家数量")
        .details("由 test_mod 在服务端读取")
        .usage("print(TestMod.playerCount())")
        .build())
    .build()
);
```

```lua
print("当前在线玩家：", TestMod.playerCount())
```

同一模组可使用相同 `rootName` 继续注册更多方法。每个顶级大类只能属于一个模组，并且不能使用 `MC`、`print`、`math` 等保留名称。需要目标客户端安装 Mod 的方法还应调用 `.requiresClientMod()`；这类方法仍会统一放到“客户端 Mod 专用 API”大类。

### 添加 API 文档标题与页面

模组还可使用 `McLuaIdeDocsApi.page(ownerModId, categoryId, pageId)` 在 API 文档左侧创建自己的分类标题和页面。页面支持标题、正文、提示框和带“插入/复制”按钮的 Lua 代码块，并支持多语言及中文首拼搜索。它由服务端同步给管理员客户端，不要求普通玩家安装扩展模组。例如：

```java
McLuaIdeDocsApi.page("test_mod", "guide", "start")
    .translation("zh_cn", McLuaIdeDocsApi.translation("TestMod 指南", "快速开始")
        .heading("运行示例")
        .text("下面的代码可直接插入 Lua 编辑器。")
        .code("print(TestMod.playerCount())")
        .build())
    .register();
```

这是 API 文档中的声明式页面 UI，不会执行第三方客户端代码；玩家游戏内交互界面仍使用 `MC.UI`。

### 添加独立 IDE 工具窗口

其他 Mod 现在可以通过客户端接口 `wiki.ica.xiaomiao.mcluaide.api.client.McLuaIdeWindowApi` 创建自己的独立窗口。注册后的窗口在“UI与窗口 → Mod 窗口”菜单打开，支持移动、缩放、左/右/下吸附、同侧标签切换、开关动画和布局保存；固定布局及允许调整吸附边框的设置也适用。

此功能需要管理员客户端同时安装提供窗口的扩展 Mod；它不会通过服务端下载执行任意客户端代码，也不改变服务端管理员权限。普通玩家无需安装仅供管理员 IDE 使用的扩展。服务端同步的 API 文档页面与这种客户端独立窗口是两种不同能力。

在扩展 Mod 的 `ClientModInitializer#onInitializeClient` 中、打开 IDE 前注册：

```java
McLuaIdeWindowApi.window("test_mod", "script_tools")
    .title(Component.literal("TestMod 脚本工具"))
    .size(360, 240)
    .minimumSize(160, 100)
    .content(context -> new MyWindowContent(context))
    .register();
```

`MyWindowContent` 实现 `McLuaIdeWindowApi.Content`。IDE 管理外框与焦点；内容绘制、输入框和按钮使用内容区局部坐标，并可通过 `context.insertText(...)` 插入主代码框、`context.copyText(...)` 复制。完整接口、生命周期、客户端入口配置和可编译示例见项目的 `docs/extensions/third-party-api.zh_cn.md` 与 `examples/third_party_windows/TestModClient.java`。

## 编辑器工具、高级调试与终端

编辑器：Ctrl+F / Ctrl+H 查找与替换（区分大小写、全词、正则），括号匹配与自动补全括号，小地图，缩进参考线，Ctrl+G 转到行，Ctrl+B 转到定义，Ctrl+Shift+B 查找引用，F2 重命名（仅当前文件），大纲，Ctrl+D / Alt+点击多光标，代码片段（输入 `fn`、`for`、`if` 等后按 Tab），文件对比，Ctrl+Shift+F 在文件中查找，Ctrl+P 快速打开，Ctrl+Shift+P 命令面板。

断点：右键行号栏可设置条件、命中次数或日志消息（日志点）。暂停后，点击调用栈中的帧查看该帧，把表达式加入「监视」，鼠标悬停变量查看值，或在编辑器右键菜单中选择「运行到光标」。

终端：通过「视图 → 终端」或 Ctrl+` 打开。「+」可启动本机 shell 或服务器终端。服务器终端是服务端机器上的 shell，默认关闭，需要服务器管理员在 `config/mc_lua_ide/terminal.properties` 中设置 `enabled=true`，且只有 OP 等级 4 可以使用。

扩展：无需 Java，通过 `config/mc_lua_ide/extensions` 中的 JSON 文件即可添加代码片段和简单命令；修改后在命令面板执行「重新加载扩展清单」。清单格式和编辑器 API 见项目中的 docs/extensions。

标题栏：「个性化 → 窗口 → 标题栏与菜单合并」会把菜单和最小化/最大化/关闭按钮放进窗口的标题栏一行。Windows 默认开启（保留系统边框、吸附和阴影）；macOS 与 Linux（X11）默认关闭，且未在真实机器上测试；Wayland 保留系统标题栏。

更多工具：调试器中的异常断点和协程列表（条件与监视不会再卡住脚本）；全局变量和 require 模块的跨文件转到定义、查找引用与重命名；拆分编辑器；「备份与恢复」面板（服务器脚本快照、设置导出/导入）；「审计日志」面板；多名管理员同时编辑时的提示与带冲突检查的保存。所有功能都可在命令面板（Ctrl+Shift+P）中找到。

## 常见问题

### 为什么脚本能通过语法检查，运行时仍然报错？

编辑器可以提前发现 Lua 结构错误以及可静态确定的 `MC.*` API 名称、参数数量、参数类型和常见格式问题。变量的运行时内容、玩家是否在线、资源是否真实存在、区块是否加载等动态状态，仍需运行到对应代码时才能最终确认。

服务器配置也可以从 IDE 顶部“工具 → 服务器配置…”打开，与 Mod Menu 配置入口使用同一页面，可调整“Lua 限制”和“服务器接入”。返回时回到原 IDE；读取及保存服务器配置仍要求服务器所有者或 OP 等级 4 权限。

### 为什么 OUTPUT 面板消失了？

游戏中按 F12，开启“显示 Lua 日志”后，右下方会实时显示当前客户端运行的脚本日志，包括 `print` 输出、错误、完成及停止状态。普通运行和调试运行均支持；退出 IDE 后仍可查看，脚本结束后日志保留。再次关闭开关即可隐藏，不影响移动和鼠标操作。显示区自动跟随最新日志，最多保留 200 行；断开服务器会清空日志，避免不同服务器的内容混在一起。

OUTPUT 会在开始运行时自动展开，脚本结束或停止后保留日志。点击输出区域右上角的关闭按钮即可收起。

日志文字可以按住鼠标左键拖动选择，再按 Ctrl+C 复制；点击日志后按 Ctrl+A 可全选全部日志（包括滚动区域之外的内容）。标题栏“复”按钮可以直接复制全部日志。复制保留原始换行，不会把窗口宽度导致的自动折行写入剪贴板。

### 如何编辑脚本文件？

既可以使用管理员客户端的游戏内编辑器，也可以由服务器管理者直接修改服务端 `config/mc_lua_ide/scripts` 中的 `.lua` 文件，然后在 IDE 中重新读取。
