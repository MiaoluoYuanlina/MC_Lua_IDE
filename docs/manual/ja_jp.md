# MC Lua IDE ユーザーガイド

## 導入と権限

サーバーと、IDE を使用する管理者のクライアントに Mod を導入してください。必須クライアントモードを有効にしない限り、一般プレイヤーはバニラクライアントで参加できます。スクリプトの保存と実行はサーバーが行います。クライアントへの導入だけでは管理者権限は得られません。

言語は Minecraft の設定に従います。日本語ではこのガイドと日本語 UI、中国語では中国語 UI、それ以外は英語を使用します。コード、入力内容、ファイル名、リソース ID は翻訳しません。第三者 Mod の API はその Mod が用意した翻訳を使用します。詳細説明やサーバーからのメッセージの一部は原文を残します。

## 最初のスクリプト

**U** キーで IDE を開き、**ファイル → Lua ファイル**で作成または読み込んでください。サブフォルダーは `/` で区切ります。ファイルをクリックするとメインエディターのタブで開きます。右クリックから作成、名前の変更、削除などを選べます。

```lua
print("Hello, Minecraft!")
for _, player in ipairs(MC.Player.list()) do
    print(player.name, player.uuid)
end
```

**Ctrl+S** で保存し、上部の実行ボタンまたは **Ctrl+Enter** で実行します。停止するとイベントの登録と待機処理を解除します。スクリプトはサーバー視点で実行され、プレイヤーを操作する場合は通常、オンラインのプレイヤー UUID が必要です。

`/lua run <script>` は通常実行、`/lua testrun <script>` はデバッグ実行です。`/lua stop` で停止できます。コマンドの候補にはサブフォルダーのスクリプトも含まれます。

## 日本語・ローマ字検索

日本語では ID 選択、名前空間、API リファレンス、コンポーネント、JSON の種類の検索に日本語読み検索を使用できます。中国語のピンインとは別の機能です。

- `komando` または `koma` → `コマンド`。ローマ字の全体・前方部分で検索できます。
- `こまんど` → `コマンド`。ひらがなとカタカナを区別しません。
- `ｺﾏﾝﾄﾞ` → `コマンド`。半角カナや濁点の分離も検索時に正規化します。
- `shou` と `syou`、`shi` と `si` など、主なローマ字表記の違いに対応します。
- `コーヒー` は `koohii`、`kohi` などの表記で検索できます。
- `鉄の剣` は `tetsunoken`、`保存` は `hozon`、`変数` は `hensuu` のように、収録済みのゲーム名・UI 用語の読みで検索できます。

漢字の読みは同じ字でも文脈で異なるため、全単語を自動推測する機能ではありません。組み込みの読み辞書にない漢字や Mod 独自の固有名詞は、元の表記かリソース ID で検索してください。カナで書かれた Mod 名・アイテム名は通常のローマ字変換を使用できます。中国語ピンインで代用することはありません。

API リファレンスには **ローマ字** スイッチがあります。オフでも通常の名前・ID 検索とカナの表記揺れ検索は利用できます。ローマ字と中国語のピンインの設定は別々に保存します。中国語に戻しても日本語側の設定を上書きしません。英語などでは両方のスイッチを非表示にします。

検索に使う正規化と読みは表示・入力内容を書き換えません。挿入するのは常に元の正しい ID です。API リファレンスではローマ字で一致した元の文字もハイライトします。

## 編集と補完

- **Tab** で候補を確定し、上下キーで候補を選択します。ローカル変数、API、引数の種類に合う ID も補完します。
- **Ctrl+I** はカーソル位置を判定して ID 選択・データコンポーネント・テキスト JSON を開きます。
- **Ctrl+F** はコード検索です。選択したテキストを検索語に使用できます。
- **Ctrl+A/C/X/V** はフォーカスのあるエディターや入力欄を操作します。
- **Ctrl+Z** で元に戻し、**Ctrl+Shift+Z** でやり直します。
- **Ctrl+F1/F2/F3/F4** は API リファレンス・ID 選択・実行ログ・データコンポーネントです。個人設定で変更できます。
- **Ctrl+ホイール** はコードの文字サイズ、折り返しがオフのときは **Shift+ホイール** で横スクロールします。
- 関数にマウスを重ねると説明を表示し、**Ctrl+クリック** または **Ctrl+F1** で関連 API を開きます。

ツールのコード整形は空白 4 文字のインデントに整えます。折りたたみは関数・if・テーブルの表示のみを変更します。静的チェックではすべての実行時データを判定できないため、サーバーでの検証も必要です。

## ウィンドウと外観

**UI とウィンドウ → 表示**から各ツールを開きます。タイトルをドラッグして移動し、強調された端をドラッグしてサイズ変更できます。左右または下にドラッグするとドッキングし、同じ領域のウィンドウはタブで切り替えます。タブの順番もドラッグで変更できます。

レイアウト固定中はドッキング位置を変えられません。個人設定で固定中の区切り線の変更を許可できます。フロートウィンドウは移動できます。右上のボタンで閉じてください。配置、表示状態、開いているファイルは次回に復元します。

個人設定で文字サイズ、行間、文字幅、スクロール感度、折り返し、カーソル、背景画像、構文色、ショートカットを調整できます。「保存して適用」で確定し、「変更を破棄」でキャンセルします。

## Lua の基本

```lua
local level = 5
local enabled = true
local items = {"first", "second"}
local settings = {count = 3}

local function describe(value)
    if value > 3 then
        return "large"
    else
        return "small"
    end
end

for index, value in ipairs(items) do
    print(index, value, describe(level))
end
```

通常は `local` を使用してください。Lua の配列は 1 始まりです。イベントのコールバックはローカル変数やテーブルを共有します。`MC.Item.give(...)` はドット呼び出しです。コロン `:` を使うと受信者が追加の引数になり、引数がずれます。

別の Lua ファイルは `require` で読み込めます。公開する関数をテーブルに入れ、そのテーブルを `return` してください。解決可能なモジュールの公開関数も補完候補に表示します。

## アイテム・プレイヤー・ブロック

```lua
local player = MC.Player.list()[1]
if player then
    MC.Item.give(player.uuid, "minecraft:diamond", 3)
    local position = MC.Player.position(player.uuid)
    if position then
        print(position.x, position.y, position.z, position.dimension)
    end
end
```

アイテム ID は `minecraft:diamond` のような文字列です。インベントリのスロット番号ではありません。インベントリとメニューのスロット番号は別物で、どちらも 0 始まりです。メインハンドとマウスに持っているアイテムも区別します。

```lua
local player = MC.Player.list()[1]
if player then
    MC.Item.give(player.uuid, "minecraft:knowledge_book", 1, {
        ["minecraft:custom_data"] = {new_type = "fire_charge"},
        ["minecraft:item_name"] = "Fire Charge",
        ["minecraft:item_model"] = "minecraft:fire_charge",
        ["minecraft:lore"] = {"Right-click to activate"}
    })
end
```

作成 API ではコンポーネントパッチを指定します。`count`、`clear`、取引の費用、クールダウンのフィルターは指定したコンポーネントのみ検査します。`custom_data` は入れ子の NBT の部分一致です。それ以外の指定値は全体が一致する必要があります。報酬の合流・スタック結合は引き続きコンポーネント全体を比較します。

ブロックの状態・ブロックエンティティ、エンティティの装備や体力、アイテムスタックのコンポーネントは異なる形式です。データ編集ウィンドウで対象を選択すると適切な形式で編集できます。

チャンク未読込、オフライン、対象不在などの回復可能な失敗では `nil, 理由` と黄色い警告を返すことがあります。値があるか確認してから参照してください。無効な引数・権限・不明な ID などは通常のエラーです。

## 使用クールダウン

```lua
local player = MC.Player.list()[1]
if player then
    local uuid = player.uuid
    print(MC.Item.isOnCooldown(uuid, "minecraft:ender_pearl"))
    MC.Item.startCooldown(uuid, "minecraft:ender_pearl", 100)
    MC.Item.setCooldown(uuid, "minecraft:ender_pearl", 40)
    MC.Item.clearCooldown(uuid, "minecraft:ender_pearl")
end
```

時間は整数のゲーム Tick で、通常は 20 Tick＝1 秒です。0～1728000 に対応し、0 で即時終了します。省略時の startCooldown はアイテムの use_cooldown、未設定なら 20 Tick を使用します。setCooldown は呼び出し時からの残り時間を置き換えます。

バニラはスロットではなくグループ単位でクールダウンを管理します。同じグループのアイテムは一緒に停止・再開します。これらの API はスロット単位の独立タイマーや、近接攻撃のチャージ、Lua イベントの抑制ではありません。

## イベントと待機

```lua
MC.Event.onBlockBroken(function(event)
    print(event.playerName, event.blockId, event.x, event.y, event.z)
end)

MC.Event.onInterval(1000, function(event)
    print(event.count, event.elapsedMs)
end)

MC.Event.onScriptStopped(function(event)
    print("Stopped")
end)
```

監視を登録するとスクリプトは実行状態を維持します。停止すると登録を解除します。`MC.sleep(milliseconds)` は現在の処理だけを待機させ、他のイベントやサーバーを止めません。コールバックは共有状態を変更できるため、待機前後の状態に注意してください。

プレイヤーの死亡と復活は別イベントです。エンティティの死亡通知は、すべての削除・アンロードを知らせる通知ではありません。正確な受信フィールドと制約は API リファレンスの原文も確認してください。

## テキストと仮想メニュー

```lua
MC.Chat.broadcast({text = "Hello!", color = "#55AAFF", bold = true})
local player = MC.Player.list()[1]
if player then
    MC.Player.openChest(player.uuid, "Example Shop", {
        {id = "minecraft:diamond", count = 1},
        {id = "minecraft:apple", count = 8}
    }, 3, true)
end
```

テキスト JSON では区間、色、グラデーション、書式、スコア、セレクター、ホバー／クリックイベントなどを編集できます。プレビューではサーバー上の値をすべて解決できるとは限りません。

仮想チェストはワールド内の保管庫ではありません。永続的な倉庫として貴重品を預けないでください。読み取り専用はサーバーで移動を拒否します。店では onContainerClicked と、支払い・報酬を原子的に処理する Item.trade を使用してください。座標のないコンテナーの座標は nil です。

## デバッグ・ログ・復旧

testrun で変数とブレークポイントを有効にします。F12 は HUD とデバッグ設定です。デバッガーには現在の文、スタック、ブレークポイント、再開・ステップ・停止を表示します。ワールド停止設定はサーバー全体に影響する場合があります。

変数ウィンドウはドラッグ選択、行のダブルクリック、Ctrl+A/C、コピーに対応します。選択中は表示スナップショットを固定し、Esc で解除します。実行ログも選択してコピーできます。

異常終了時の下書きは、次回の復旧確認または「ツール → ファイルの復旧」から開けます。元のファイルをすぐ上書きすることはありません。確認して保存してください。

## エディター機能・詳細デバッグ・ターミナル

エディター：Ctrl+F / Ctrl+H で検索・置換（大文字小文字、単語単位、正規表現）、括弧の対応表示と自動補完、ミニマップ、インデントガイド、Ctrl+G で行へ移動、Ctrl+B で定義へ移動、Ctrl+Shift+B で参照検索、F2 で名前変更（現在のファイルのみ）、アウトライン、Ctrl+D / Alt+クリックで複数カーソル、スニペット（`fn`・`for`・`if` などを入力して Tab）、ファイル比較、Ctrl+Shift+F でファイル内検索、Ctrl+P でクイックオープン、Ctrl+Shift+P でコマンドパレット。

ブレークポイント：行番号欄を右クリックして条件、ヒット回数、ログメッセージ（ログポイント）を設定できます。停止中はコールスタックのフレームをクリックして確認し、式をウォッチに追加し、変数にマウスを重ねて値を見られます。エディターのメニューから「カーソルまで実行」も使えます。

ターミナル：「表示 → ターミナル」または Ctrl+` で開きます。＋ボタンで自分のコンピューターのシェル、またはサーバーターミナルを起動します。サーバーターミナルはサーバー機上のシェルで、既定では無効です。サーバー管理者が `config/mc_lua_ide/terminal.properties` で `enabled=true` を設定し、OP レベル 4 のみ使用できます。

拡張：Java なしで、`config/mc_lua_ide/extensions` の JSON ファイルからスニペットと簡単なコマンドを追加できます。編集後はコマンドパレットの「拡張マニフェストを再読み込み」を実行してください（日本語表示では英語表記の場合があります）。形式とエディター API はプロジェクトの docs/extensions を参照してください。

タイトルバー：「個人設定 → ウィンドウ → メニューをタイトルバーに統合」を有効にすると、メニューと最小化・最大化・閉じるボタンがウィンドウのタイトルバーの行に入ります。Windows では既定で有効（システムの枠・スナップ・影は維持）。macOS と Linux（X11）では既定で無効で、実機では未テストです。Wayland では通常のタイトルバーのままです。

## データパック・リソースパック

各ディレクトリはファイルメニューにあります。JSON 本文はメインエディターで編集し、JSON ツールウィンドウでテンプレートや現在のゲームのサンプルを読み込みます。保存後にツールから再読み込みします。ディメンションなど一部の変更はワールドの開き直しが必要です。

PNG には鉛筆・ブラシ・消しゴム・塗りつぶし・レイヤー・パレットなどを使えます。OGG は情報とシークバーで試聴できます。構造物 NBT は実際のブロックテクスチャを使った回転・拡大可能なプレビューです。

画像やモデルを追加しても、新しい登録済みアイテムの種類を作るわけではありません。既存アイテムに item_model を設定できます。管理者が編集したローカルのリソースパックは自動で全プレイヤーに配布されないため、別途公開またはサーバーリソースパックの設定が必要です。

AI 解析と MCP は既定で無効です。AI 解析を有効にすると関連コードを外部サービスに送信し、料金が発生する場合があります。MCP はトークンと権限を確認してください。API 文書は「ツール → API リファレンスを書き出す」から Markdown に保存できます。
